# 网关供给与编排消费边界

## 目的

明确源码侧推送与服务端消费的职责分界，避免轮询、指纹、自适应间隔等概念在两侧重复实现或互相覆盖。

## 角色划分

- 推送侧（`cce-gateway`）：运行在源码所在机器，只负责本地枚举、内容指纹、压缩打包、推送清单与内容、轮询增量。不感知向量、嵌入、解析与编排，不做索引写入。
- 消费侧（`cce-orchestrator` 的供给入口与索引流水线）：负责接收推送队列、消费清单与事件、执行解析分组切块与向量写入、维护关系图与检查点。不主动连接源码机器做拉取。

## 归属规则

- 文件枚举与变化指纹归推送侧：以本地扫描快照为准，缓存只是跨重启加速重哈希的纯读优化，不参与变化判定。
- 索引状态、世代管理、失败重试与死信归消费侧：推送成功只代表送达，不代表已索引。
- 轮询间隔与自适应策略归推送侧：按基线文件规模放宽轮询，服务端不调整推送节奏。
- 心跳文件归推送侧：供进程监管与探活使用，与索引健康端点无关。
- 业务参数默认值归 `SyncParams`：命令行分支与常驻守护进程只翻译显式参数，环境变量次之，缺省一律沿用共享默认值，不得各自重写覆盖语义。

## 数据流

源码扫描 → 指纹比对 → 清单与内容推送 → 服务端供给队列 → 索引流水线 → 向量与关系落盘 → 检查点推进。失败发生在队列之前由推送侧重试，发生在队列之后由消费侧按检查点恢复。

## 维护约定

- 新增推送参数时先加到共享参数结构，再由各入口翻译，禁止在入口内复制覆盖逻辑。
- 调整消费语义时只改编排侧，推送载荷格式变化需同步更新供给队列的版本校验。
