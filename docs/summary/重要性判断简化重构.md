# 重要性判断简化重构

## 背景

原有的 `determine_importance` 机制存在以下问题:

1. **过度复杂**: 依赖未实现的 `utility_functions` 统计,导致判断逻辑失效
2. **可靠性差**: 多层嵌套的条件判断,难以维护和测试
3. **双路径冗余**: `determine_importance` 和 `determine_importance_simple` 逻辑重复

## 重构方案

### 核心原则

1. **统一入口**: 删除 `determine_importance_simple`,统一使用 `determine_importance`
2. **基于设计模式**: 利用已识别的设计模式判断重要性
3. **简化逻辑**: 减少嵌套层级,提高可读性

### 新的判断策略

#### 1. 文件类别优先

```rust
match FileCategory::determine(parsed_file) {
    FileCategory::Test | FileCategory::Config | FileCategory::Generated | FileCategory::Minimal => {
        return ImportanceLevel::Low;
    }
    FileCategory::Documentation | FileCategory::Schema => {
        return ImportanceLevel::Medium;
    }
    FileCategory::Normal => {
        // 继续详细分析
    }
}
```

#### 2. 核心模块识别

```rust
if FileCategory::is_core_module(&parsed_file.path) {
    return ImportanceLevel::High;
}
```

核心模块包括: main, lib, mod, index

#### 3. 设计模式分析

**样板代码模式识别**:

- Getter/Setter: 数据访问样板代码
- Builder: 构建器模式样板代码
- Singleton: 单例模式样板代码
- 简单独立函数: 无成员、短跨度 (<200字符)

**判断逻辑**:

```rust
let pattern_analysis = Self::analyze_design_patterns(processing_result);

// 如果超过 70% 是样板代码,降低重要性
if pattern_analysis.boilerplate_ratio > 0.7 {
    return ImportanceLevel::Low;
}
```

#### 4. 实体复杂度

```rust
// 高实体数量
if entity_count >= 15 {
    return ImportanceLevel::High;
}

// 复杂结构 (多个类/trait)
let complex_type_count = processing_result
    .groups
    .iter()
    .filter(|g| matches!(g.group_type, GroupType::ClassWithMethods | GroupType::TraitWithImpls))
    .count();

if complex_type_count >= 2 {
    return ImportanceLevel::High;
}

// 公开 API
if !parsed_file.exports.is_empty() {
    return ImportanceLevel::High;
}

// 简单文件
if entity_count < 5 {
    return ImportanceLevel::Low;
}
```

### 生成策略判断

简化后的生成策略判断:

```rust
pub fn determine_generation_strategy(
    parsed_file: &ParsedFile,
    processing_result: &ProcessingResult,
    config: &SummaryConfig,
) -> GenerationStrategy {
    match config.strategy {
        SummaryStrategy::RuleBased => GenerationStrategy::RuleOnly,
        SummaryStrategy::ModelEnhanced => {
            // 1. 特殊文件类别 - 规则生成
            if category.should_skip_model() {
                return GenerationStrategy::RuleOnly;
            }
            
            // 2. 高文档覆盖率 - 规则生成
            if doc_coverage >= 0.5 {
                return GenerationStrategy::RuleOnly;
            }
            
            // 3. 高样板代码比例 - 规则生成
            if pattern_analysis.boilerplate_ratio > 0.6 {
                return GenerationStrategy::RuleOnly;
            }
            
            // 4. 核心模块 - 模型增强
            if FileCategory::is_core_module(&parsed_file.path) {
                return GenerationStrategy::ModelEnhanced;
            }
            
            // 5. 复杂文件 - 模型增强
            if entity_count >= 10 || processing_result.groups.len() >= 7 {
                return GenerationStrategy::ModelEnhanced;
            }
            
            // 6. 默认 - 规则生成
            GenerationStrategy::RuleOnly
        }
    }
}
```

## 实现细节

### PatternAnalysis 结构

```rust
#[derive(Debug, Clone, Default)]
struct PatternAnalysis {
    /// 样板代码模式组数量
    boilerplate_count: usize,
    /// 总组数
    total_groups: usize,
    /// 样板代码比例
    boilerplate_ratio: f32,
}
```

### 样板代码识别

```rust
fn analyze_design_patterns(processing_result: &ProcessingResult) -> PatternAnalysis {
    let mut boilerplate_count = 0;
    
    for group in &processing_result.groups {
        // 检查设计模式
        if let Some(ref pattern_info) = group.pattern_info {
            if pattern_info.is_getter_setter() 
                || pattern_info.is_builder() 
                || pattern_info.is_singleton() {
                boilerplate_count += 1;
            }
        }
        
        // 检查简单独立函数
        if group.group_type == GroupType::Standalone {
            if group.members.is_empty() && group.span.len() < 200 {
                boilerplate_count += 1;
            }
        }
    }
    
    let boilerplate_ratio = boilerplate_count as f32 / total_groups as f32;
    
    PatternAnalysis {
        boilerplate_count,
        total_groups,
        boilerplate_ratio,
    }
}
```

## 优势

### 1. 简化性

- **单一入口**: 统一使用 `determine_importance(parsed_file, processing_result)`
- **清晰流程**: 文件类别 → 核心模块 → 设计模式 → 实体复杂度
- **减少依赖**: 不依赖未实现的统计字段

### 2. 可靠性

- **基于已实现功能**: 利用现有的设计模式识别
- **明确阈值**: 所有判断条件都有明确的阈值
- **易于测试**: 每个判断步骤都可独立测试

### 3. 可维护性

- **减少代码量**: 删除约 200 行冗余代码
- **清晰文档**: 每个判断步骤都有注释说明
- **易于扩展**: 新增判断条件只需添加相应步骤
