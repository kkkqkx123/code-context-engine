# 工具函数识别策略

## 概述

本文档分析如何基于实体组的AST结构识别工具函数(utility functions),用于文件重要性判断和摘要生成策略选择。

## 工具函数定义

工具函数是指具有以下特征的函数:

### 核心特征

1. **简单性**: 代码行数少,逻辑简单
2. **辅助性**: 为其他函数提供服务,非核心业务逻辑
3. **通用性**: 可在多处复用,无特定上下文依赖
4. **纯函数性**: 无副作用,输出仅依赖输入

### 典型示例

```rust
// 工具函数示例
fn trim_string(s: &str) -> String {
    s.trim().to_string()
}

fn format_date(timestamp: i64) -> String {
    // 简单的日期格式化
}

fn is_valid_email(email: &str) -> bool {
    email.contains('@') && email.contains('.')
}
```

## 识别策略设计

### 策略一: 基于AST结构特征

#### 1.1 代码复杂度分析

利用 `Entity` 的以下字段:

```rust
pub struct Entity {
    pub span: Span,           // 代码跨度
    pub depth: usize,         // 嵌套深度
    pub children: Vec<EntityId>,  // 子实体数量
    pub parameters: Vec<(String, Option<String>)>,  // 参数列表
    // ...
}
```

**判断规则**:

- **行数阈值**: `span.len() < 150` 字符 (约 5-10 行)
- **嵌套深度**: `depth <= 1` (无深层嵌套)
- **子实体数量**: `children.len() <= 3` (无复杂内部结构)
- **参数数量**: `parameters.len() <= 3` (简单参数列表)

#### 1.2 控制流复杂度

通过分析 `combined_source` 中的控制流关键字:

```rust
// 简单函数: 无或少量控制流
// 复杂函数: 包含多个 if/match/loop 等
```

**实现方式**:

```rust
fn has_simple_control_flow(source: &str) -> bool {
    let control_keywords = ["if", "match", "loop", "while", "for"];
    let mut count = 0;
    for keyword in &control_keywords {
        count += source.matches(keyword).count();
    }
    count <= 2  // 最多 2 个控制流语句
}
```

### 策略二: 基于调用模式

#### 2.1 调用频率分析

利用 `EntityMeta` 的调用信息:

```rust
pub struct EntityMeta {
    pub call_count: usize,      // 被调用次数
    pub callers: Vec<EntityId>, // 调用者列表
    pub callees: Vec<EntityId>, // 被调用者列表
    // ...
}
```

**判断规则**:

- **高复用性**: `call_count >= 3` (被多处调用)
- **低依赖性**: `callees.len() <= 2` (不依赖其他复杂函数)
- **广泛调用者**: `callers.len() >= 2` (被多个不同函数调用)

#### 2.2 调用链深度

工具函数通常位于调用链末端:

```rust
// 工具函数: 不调用其他函数或仅调用标准库
// 非工具函数: 调用多个业务函数
```

### 策略三: 基于命名模式

#### 3.1 命名特征

工具函数通常具有特定命名模式:

```rust
fn is_utility_name(name: &str) -> bool {
    let utility_prefixes = [
        "is_", "has_", "can_", "should_",  // 判断函数
        "get_", "set_", "to_", "from_",    // 访问/转换函数
        "format_", "parse_", "validate_",  // 格式化/解析函数
        "trim_", "clean_", "normalize_",   // 清理函数
    ];
    
    utility_prefixes.iter().any(|prefix| name.starts_with(prefix))
}
```

#### 3.2 语义特征

通过函数签名分析:

```rust
// 纯函数特征: 返回值类型明确,无 &mut 参数
fn is_pure_function(entity: &Entity) -> bool {
    // 检查返回类型
    if entity.return_type.is_none() {
        return false;
    }
    
    // 检查参数是否包含可变引用
    for (_, type_opt) in &entity.parameters {
        if let Some(t) = type_opt {
            if t.contains("&mut") {
                return false;
            }
        }
    }
    
    true
}
```

### 策略四: 基于分组类型

#### 4.1 分组特征

利用 `EntityGroup` 的分组信息:

```rust
pub struct EntityGroup {
    pub group_type: GroupType,
    pub members: Vec<GroupedEntity>,
    pub pattern_info: Option<PatternInfo>,
    // ...
}
```

**判断规则**:

- **独立函数**: `group_type == Standalone` 且无复杂模式
- **辅助方法**: 在 `ClassWithMethods` 中但非核心方法
- **Getter/Setter**: 通过 `pattern_info` 识别

#### 4.2 模式识别

利用已有的模式识别结果:

```rust
// Getter/Setter 通常是工具函数
if let Some(pattern) = &group.pattern_info {
    if pattern.is_getter_setter() {
        return true;
    }
}
```

## 综合评分策略

### 评分维度

| 维度 | 权重 | 评分范围 |
|------|------|----------|
| 代码复杂度 | 0.3 | 0-1 |
| 调用模式 | 0.3 | 0-1 |
| 命名特征 | 0.2 | 0-1 |
| 分组特征 | 0.2 | 0-1 |

### 评分计算

```rust
fn calculate_utility_score(entity: &Entity, meta: &EntityMeta, group: &EntityGroup) -> f32 {
    let complexity_score = calculate_complexity_score(entity);
    let call_pattern_score = calculate_call_pattern_score(meta);
    let naming_score = calculate_naming_score(&entity.name);
    let group_score = calculate_group_score(group);
    
    complexity_score * 0.3
        + call_pattern_score * 0.3
        + naming_score * 0.2
        + group_score * 0.2
}

fn is_utility_function(score: f32) -> bool {
    score >= 0.6  // 阈值可配置
}
```

## 实现方案

### 阶段一: 基础实现

在 `PreprocessingPipeline` 中添加工具函数识别:

```rust
// src/grouper/pipeline.rs
impl PreprocessingPipeline {
    pub fn process(&self, parsed_file: &ParsedFile) -> ProcessingResult {
        // ... 现有处理逻辑 ...
        
        // 新增: 识别工具函数
        let (groups, entity_meta, stats) = self.identify_utility_functions(
            groups,
            entity_meta,
            &mut stats
        );
        
        ProcessingResult {
            groups,
            entity_meta,
            stats,
        }
    }
    
    fn identify_utility_functions(
        &self,
        groups: Vec<EntityGroup>,
        mut entity_meta: HashMap<String, EntityMeta>,
        stats: &mut ProcessingStats,
    ) -> (Vec<EntityGroup>, HashMap<String, EntityMeta>, ProcessingStats) {
        let mut utility_count = 0;
        
        for group in &groups {
            if let Some(header) = &group.header {
                let score = self.calculate_utility_score(header, &group);
                if score >= 0.6 {
                    if let Some(meta) = entity_meta.get_mut(&header.name) {
                        meta.is_utility = true;
                        utility_count += 1;
                    }
                }
            }
        }
        
        stats.utility_functions = utility_count;
        (groups, entity_meta, stats.clone())
    }
}
```

```rust
pub struct UtilityDetector {

impl UtilityDetector {
    pub fn detect(&self, entity: &Entity, context: &DetectionContext) -> UtilityScore {
        let mut scores = Vec::new();
        
        // 1. 复杂度评分
        scores.push(self.score_complexity(entity));
        
        // 2. 调用模式评分
        scores.push(self.score_call_pattern(entity, context));
        
        // 3. 命名评分
        scores.push(self.score_naming(entity));
        
        // 4. 语义评分
        scores.push(self.score_semantics(entity));
        
        UtilityScore::combine(scores)
    }
}
```

## 性能考虑

### 1. 计算复杂度

- 简单特征检查: O(1)
- 调用图分析: O(V + E) (V=顶点数, E=边数)
- 综合评分: O(n) (n=实体数量)

### 2. 缓存策略

```rust
pub struct UtilityScoreCache {
    cache: LruCache<EntityId, f32>,
}

impl UtilityScoreCache {
    pub fn get_or_compute(&mut self, id: EntityId, compute: impl FnOnce() -> f32) -> f32 {
        *self.cache.entry(id).or_insert_with(compute)
    }
}
```

### 3. 增量更新

仅对新文件或修改的文件重新计算:

```rust
pub fn update_utility_scores(&mut self, changed_files: &[FileId]) {
    for file_id in changed_files {
        self.recalculate_for_file(file_id);
    }
```

## 总结

通过综合运用AST结构特征、调用模式、命名模式和分组类型,可以有效识别工具函数。实现后,将显著提升文件重要性判断的准确性,并为摘要生成提供更丰富的上下文信息。

关键要点:

1. **多维度综合**: 不依赖单一特征,综合多个维度评分
2. **可配置性**: 提供灵活的配置选项适应不同项目
3. **性能优化**: 使用缓存和增量更新保证性能
4. **渐进实现**: 分阶段实现,从简单到复杂
