# 文件摘要索引与查询集成设计

## 一、当前设计分析

### 1.1 现有架构

当前项目已经具备以下基础组件：

```

├── summary/                    # 摘要生成模块
│   ├── generator.rs           # RuleBasedGenerator - 基于规则的摘要生成
│   ├── model_generator.rs     # ModelEnhancedGenerator - 模型增强摘要

├── orchestrator/
```

### 1.2 已有类型定义

**FileSummary** (`src/types/entity.rs` 和 `src/summary/types.rs`)：

```rust

    pub file_path: String,
    pub language: String,
    pub summary_text: String,        // 摘要文本
    pub main_entities: Vec<String>,  // 主要实体名称
    pub imports: Vec<String>,        // 导入的模块
```

**RuleBasedGenerator** (`src/summary/generator.rs`)：

已经实现了基于规则的摘要生成，可以从 `ParsedFile` 提取：
- 文件元信息（路径、语言、行数）
- 主要实体（类、函数等）
- 导入依赖
- 导出符号
- 标签（web、database、async等）

### 1.3 当前缺失

1. **索引流程未集成摘要生成**：`IndexOrchestrator` 没有调用 summary 生成和存储
2. **摘要向量存储缺失**：没有将摘要 embedding 存储到独立的 Qdrant collection
3. **查询流程不完整**：`HierarchicalStrategy` 中的 `search_summaries` 和 `search_details` 是 placeholder 实现

## 二、用户思路评估

### 2.1 用户思路

> 直接在 post-processor 阶段把处理后的文本段（包括自然语言化、分段）拼接，再由 summary 模块总结文件内容

### 2.2 问题分析

这个思路存在以下问题：

| 问题 | 说明 |
|------|------|
| **时间顺序错误** | Post-processor 处理的是单个代码实体的转换结果，以批次处理多个文件，无法在一个文件的实体全部处理完之前生成摘要 |
| **信息丢失** | Post-processor 的输入已经是转换后的自然语言描述，拼接后再处理相当于对二手信息做摘要，丢失了原始代码结构信息 |
| **复杂度增加** | 在 post-processor 阶段引入摘要生成功能，会耦合两个不同关注点的逻辑 |
| **重复处理** | `ParsedFile` 已经包含了生成摘要所需的所有信息，无需再经过 post-processor 转换 |

### 2.3 正确思路

**直接在 `ParsedFile` 上生成摘要，绕过 post-processor 阶段**：

```
FileEntry → FileProcessor.process_code_file() → ParsedFile
                                                    ↓
                                          RuleBasedGenerator
                                                    ↓
                                              FileSummary
                                                    ↓
                                    Embedding → Qdrant (summary collection)
```

理由：
1. `ParsedFile` 包含完整的文件级信息（entities、imports、exports）
2. 摘要生成只需要元信息（实体名、导入导出），不需要完整的代码内容
3. 基于规则的摘要生成轻量快速，无需模型参与
4. 摘要本身不用于最终召回，只需要能表示文件主题即可

## 三、正确的设计方案

### 3.1 核心原则

根据用户要求明确：

1. **文件摘要不参与最终召回** - 仅作为第一轮查询，提高相应文件里代码段的匹配分数
2. **轻量设计** - 不要复杂的权重调整机制
3. **基于规则** - 使用 RuleBasedGenerator，无需模型参与
4. **独立存储** - 摘要使用独立的 Qdrant collection

#### 3.2.2 修改 StorageCoordinator

新增存储摘要到独立 collection 的方法：

```rust
// src/orchestrator/index/storage_coordinator.rs

pub async fn store_summaries(
    &self,
    summaries: &[FileSummary],
) -> Result<usize, OrchestratorError> {
    let qdrant = match &self.qdrant {
        Some(q) => q,
        None => return Ok(0),
    };

    let embedder = match &self.embedder {
        Some(e) => e,
        None => return Ok(0),
    };

    if summaries.is_empty() {
        return Ok(0);
    }

    // 准备摘要文本用于 embedding
    let texts: Vec<String> = summaries
        .iter()
        .map(|s| s.to_embedding_text())
        .collect();

    // 生成 embedding
    let embeddings = embedder.embed(&texts).await?;

    // 构建 vector points
    let points: Vec<VectorPoint> = summaries
        .iter()
        .zip(embeddings.embeddings.iter())
        .map(|(summary, vector)| {
            let payload = SummaryPayload {
                file_path: summary.file_path.clone(),
                summary: summary.summary_text.clone(),
                main_entities: summary.main_entities.clone(),
                imports: summary.imports.clone(),
                exports: summary.exports.clone(),
                entity_count: summary.entity_count,
                line_count: summary.line_count,
                language: summary.language.clone(),
                tags: summary.tags.clone(),
            };

            VectorPoint::new(
                format!("summary:{}", summary.file_path),
                vector.clone(),
                Payload::from_summary(payload),
            )
        })
        .collect();

    // 存储到独立的 summary collection
    if !points.is_empty() {
        qdrant.upsert_summary_points(&points).await?;
    }

    Ok(points.len())
}
```

#### 3.2.3 修改 QdrantClient

新增对 summary collection 的操作：

```rust
// src/storage/qdrant/client.rs

pub struct QdrantClient {
    client: Arc<Qdrant>,
    collection_name: String,
    summary_collection_name: String,  // 新增：摘要 collection 名称
    config: QdrantConfig,
}

impl QdrantClient {
    /// 存储摘要向量到独立的 collection
    pub async fn upsert_summary_points(
        &self,
        points: &[VectorPoint],
    ) -> Result<(), StorageError> {
        // 确保 summary collection 存在
        self.ensure_summary_collection().await?;

        let point_structs: Vec<PointStruct> = points
            .iter()
            .map(|p| p.to_point_struct())
            .collect();

        self.client
            .upsert_points(
                &self.summary_collection_name,
                None,
                &point_structs,
                None,
            )
            .await
            .map_err(|e| StorageError::qdrant(e))?;

        Ok(())
    }

    /// 搜索摘要索引
    pub async fn search_summaries(
        &self,
        query_vector: Vec<f32>,
        top_k: usize,
        min_score: f32,
    ) -> Result<Vec<SummarySearchResult>, StorageError> {
        let search_result = self.client
            .search_points(&SearchPoints {
                collection_name: self.summary_collection_name.clone(),
                vector: query_vector,
                limit: top_k as u64,
                score_threshold: Some(min_score),
                with_payload: Some(WithPayloadSelector::from(true)),
                ..Default::default()
            })
            .await
            .map_err(|e| StorageError::qdrant(e))?;

        // 转换为 SummarySearchResult
        Ok(search_result.result.into_iter().map(|r| {
            SummarySearchResult {
                file_path: r.payload.get("file_path").map(|v| v.to_string()).unwrap_or_default(),
                score: r.score,
                summary: r.payload.get("summary").map(|v| v.to_string()).unwrap_or_default(),
            }
        }).collect())
    }
}
```

### 3.3 查询流程集成

#### 3.3.1 完成 HierarchicalStrategy 实现

```rust
// src/orchestrator/query/strategies/hierarchical.rs

pub struct HierarchicalStrategy {
    config: HierarchicalConfig,
    qdrant: Option<Arc<QdrantClient>>,      // 新增
    embedder: Option<Arc<Embedder>>,        // 新增
}

impl HierarchicalStrategy {
    pub fn with_clients(
        config: HierarchicalConfig,
        qdrant: Arc<QdrantClient>,
        embedder: Arc<Embedder>,
    ) -> Self {
        Self {
            config,
            qdrant: Some(qdrant),
            embedder: Some(embedder),
        }
    }

    /// 搜索摘要索引（实现）
    async fn search_summaries(&self, query: &str) -> anyhow::Result<Vec<SummaryResult>> {
        let qdrant = self.qdrant.as_ref()
            .ok_or_else(|| anyhow::anyhow!("Qdrant client not configured"))?;
        let embedder = self.embedder.as_ref()
            .ok_or_else(|| anyhow::anyhow!("Embedder not configured"))?;

        // 生成 query embedding
        let query_embedding = embedder.embed(&[query]).await?
            .embeddings.into_iter().next()
            .ok_or_else(|| anyhow::anyhow!("Failed to generate query embedding"))?;

        // 搜索摘要索引
        let results = qdrant.search_summaries(
            query_embedding,
            self.config.summary_top_k,
            self.config.min_summary_score,
        ).await?;

        Ok(results.into_iter().map(|r| SummaryResult {
            file_path: r.file_path,
            score: r.score,
            summary_text: r.summary,
        }).collect())
    }

    /// 搜索细节索引（实现）
    async fn search_details(&self, query: &str) -> anyhow::Result<Vec<DetailResult>> {
        let qdrant = self.qdrant.as_ref()
            .ok_or_else(|| anyhow::anyhow!("Qdrant client not configured"))?;
        let embedder = self.embedder.as_ref()
            .ok_or_else(|| anyhow::anyhow!("Embedder not configured"))?;

        // 生成 query embedding
        let query_embedding = embedder.embed(&[query]).await?
            .embeddings.into_iter().next()
            .ok_or_else(|| anyhow::anyhow!("Failed to generate query embedding"))?;

        // 搜索主索引（代码片段）
        let results = qdrant.search(
            query_embedding,
            self.config.detail_top_k,
            0.0,
            None,
        ).await?;

        Ok(results.into_iter().map(|r| DetailResult {
            id: r.id,
            kind: r.payload.entity_type.unwrap_or_default(),
            name: r.payload.extra.get("entity_names")
                .and_then(|v| v.as_str())
                .unwrap_or_default()
                .to_string(),
            file_path: r.payload.file_path,
            score: r.score,
            content: r.payload.code_chunk,
            start_line: r.payload.start_line,
            end_line: r.payload.end_line,
            metadata: r.payload.extra.iter()
                .map(|(k, v)| (k.clone(), v.to_string()))
                .collect(),
        }).collect())
    }
}
```

#### 3.3.2 简化的分数提升机制

根据用户要求，不要复杂的权重调整，使用简单的 boost factor：

```rust
fn apply_boosting(
    &self,
    details: Vec<DetailResult>,
    file_boost_map: &HashMap<String, f32>,
) -> Vec<SearchResult> {
    details
        .into_iter()
        .map(|detail| {
            let is_boosted = file_boost_map.contains_key(&detail.file_path);
            let boosted_score = if is_boosted {
                detail.score * self.config.boost_factor
            } else {
                detail.score
            };

            SearchResult {
                id: detail.id,
                kind: detail.kind,
                name: detail.name,
                file_path: detail.file_path,
                score: boosted_score,
                original_score: detail.score,
                sources: vec!["hierarchical".to_string()],
                snippet: Some(detail.content.clone()),
                content: detail.content,
                start_line: detail.start_line,
                end_line: detail.end_line,
                is_boosted,
                boost_reason: if is_boosted {
                    Some("file_summary_match".to_string())
                } else {
                    None
                },
                relations: None,
                call_chain: None,
                metadata: detail.metadata,
            }
        })
        .collect()
}
```

## 七、关键设计决策

### 7.1 为什么不基于 post-processor 输出生成摘要？

- `ParsedFile` 已经包含完整的文件级元信息
- Post-processor 输出是细粒度的代码段，丢失了文件整体结构
- 基于规则生成摘要只需要实体名称和导入导出信息，不需要完整代码内容

### 7.2 为什么使用独立 collection？

- 摘要和细节的向量类型不同（文件级 vs 代码段级）
- 独立的 collection 可以配置不同的 HNSW 参数
- 便于单独清空或重建摘要索引

### 7.3 为什么 boost factor 设计为固定值？

根据用户要求：
> "文件本身不要设计复杂的权重调整机制"

- 固定 boost factor（如 1.2）实现简单
- 避免过度调参
- 效果可以通过实际查询验证后调整

## 八、总结

本设计遵循以下核心原则：

1. **轻量级**：基于规则的摘要生成，无需模型参与
2. **简单直接**：固定 boost factor，无复杂权重调整
3. **并行处理**：摘要索引和细节索引独立存储和检索
4. **不干扰主流程**：文件摘要不参与最终召回，仅用于提升相关文件代码段的分数

实施建议：
- **Phase 1** 可以快速验证效果（1-2天）
- **Phase 2** 完成完整的查询流程（2-3天）
- 通过 A/B 测试验证提升效果后再决定是否继续 Phase 3
