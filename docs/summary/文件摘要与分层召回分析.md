# 文件摘要与分层召回分析报告

## 一、当前项目文件处理现状分析

### 1.1 文件处理流程

当前项目采用**实体级分块**策略，处理流程如下：

```
文件扫描 → AST解析 → 实体提取 → AST转NL → 向量嵌入 → 存储
```

**关键特点**：
- **语义分块**：每个代码实体（函数、类、结构体等）作为独立片段
- **双路径输出**：BM25路径（保留符号）+ Embedding路径（纯语义）
- **无文件级摘要**：当前没有生成或存储文件级别的摘要信息

### 1.2 现有存储结构

#### 1.2.1 向量数据库（Qdrant）

```rust
pub struct Payload {
    pub file_path: String,           // 文件路径
    pub code_chunk: String,          // 代码块内容
    pub start_line: u32,             // 起始行
    pub end_line: u32,               // 结束行
    pub entity_type: Option<String>, // 实体类型
    pub path_segments: HashMap<String, String>, // 路径分段（用于过滤）
    pub extra: HashMap<String, String>, // 额外信息
}
```

**现状问题**：
- 所有片段存储在同一个collection中
- 没有区分文件摘要和代码细节
- 无法实现分层检索

## 二、是否需要文件摘要和分层存储？

### 2.1 当前架构的局限性

| 问题 | 影响 |
|------|------|
| **缺乏文件级视角** | 用户查询"认证模块"时，无法快速定位到相关文件 |
| **片段碎片化** | 大文件被拆分成多个片段，缺乏整体上下文 |
| **召回效率低** | 需要遍历所有片段才能找到相关文件 |
| **相关性判断不完整** | 片段匹配无法反映文件整体相关性 |

### 2.2 分层存储的收益

| 收益 | 说明 |
|------|------|
| **快速文件定位** | 第一层摘要召回可快速定位相关文件 |
| **相关性增强** | 摘要命中时提升该文件所有片段的分数 |
| **上下文补充** | 摘要提供文件级上下文，补充片段细节 |
| **存储优化** | 摘要索引小，可使用全表索引加速 |

### 2.3 结论：**强烈建议实施**

理由：
1. 当前项目已有 `ParsedFile` 结构，包含生成摘要所需的所有信息
2. `RelationIndex` 已有 `file_index` 和 `entity_file_index`，可扩展支持摘要
3. 分层召回可显著提升检索质量和效率
4. 实施成本可控，可渐进式引入

### 3.2 存储层设计

#### 3.2.1 摘要索引（Summary Index）

**存储位置**：Qdrant独立collection（如 `ws-{hash}-summary`）

**特点**：
- 小规模：每个文件一个向量
- 全表索引：使用较小的HNSW参数，支持快速召回
- 低维度：可使用较小的向量维度（如512维）

**Payload结构**：

### 3.3 摘要生成策略

#### 3.3.1 基于规则的摘要（推荐初期使用）

```rust
pub fn generate_rule_based_summary(parsed_file: &ParsedFile) -> FileSummary {
    let mut summary = FileSummary::default();
    
    // 1. 文件元信息
    summary.file_path = parsed_file.path.clone();
    summary.language = parsed_file.language.to_string();
    
    // 2. 导入依赖概览
    summary.imports = parsed_file.imports.iter()
        .map(|imp| imp.module.clone())
        .collect();
    
    // 3. 主要实体
    let classes: Vec<_> = parsed_file.entities.iter()
        .filter(|e| e.kind == EntityKind::Class)
        .collect();
    let functions: Vec<_> = parsed_file.entities.iter()
        .filter(|e| e.kind == EntityKind::Function)
        .collect();
    
    summary.main_entities = classes.iter()
        .chain(functions.iter())
        .take(10)
        .map(|e| e.name.clone())
        .collect();
    
    // 4. 导出符号
    summary.exports = parsed_file.exports.iter()
        .map(|e| e.function_name.clone())
        .collect();
    
    // 5. 生成摘要文本
    summary.summary = format!(
        "File: {}\nImports: {}\nEntities: {}\nExports: {}",
        parsed_file.path,
        summary.imports.join(", "),
        summary.main_entities.join(", "),
        summary.exports.join(", ")
    );
    
    // 6. 生成标签
    summary.tags = generate_tags(parsed_file);
    
    summary
}
```

#### 3.3.3 混合策略

```rust
pub fn generate_summary(
    parsed_file: &ParsedFile,
    importance_score: f32,
) -> FileSummary {
    // 高重要性文件：规则摘要 + 模型增强
    if importance_score > 0.7 {
        let rule_summary = generate_rule_based_summary(parsed_file);
        // 可选：异步调用模型增强

    }
    // 普通文件：纯规则摘要
    else {
        generate_rule_based_summary(parsed_file)
    }
```

### 3.4 检索流程设计

#### 3.4.1 双路召回 + 分数融合

```rust
pub struct HierarchicalSearcher {
    summary_client: QdrantClient,  // 摘要索引客户端
    detail_client: QdrantClient,   // 细节索引客户端
    bm25_client: Bm25Client,       // BM25客户端
    boost_factor: f32,             // 提升系数（默认1.2）
}

impl HierarchicalSearcher {
    pub async fn search(
        &self,
        query: &str,
        top_k: usize,
    ) -> Result<Vec<SearchResult>, Error> {
        // 1. 并行召回
        let (summary_results, detail_results, bm25_results) = tokio::try_join!(
            self.search_summary(query, top_k),
            self.search_detail(query, top_k * 2),
            self.search_bm25(query, top_k)
        )?;
        
        // 2. 构建文件到摘要分数的映射
        let file_boost_map: HashMap<String, f32> = summary_results
            .iter()
            .map(|r| (r.payload.file_path.clone(), r.score))
            .collect();
        
        // 3. 融合分数
        let mut final_results: Vec<SearchResult> = Vec::new();
        
        // 3.1 处理细节索引结果
        for mut result in detail_results {
            if let Some(summary_score) = file_boost_map.get(&result.payload.file_path) {
                // 摘要命中，提升分数
                result.score = result.score * self.boost_factor;
                result.boost_reason = Some(format!(
                    "summary_match(score={:.3})",
                    summary_score
                ));
            }
            final_results.push(result);
        }
        
        // 3.2 处理BM25结果
        for mut result in bm25_results {
            if let Some(summary_score) = file_boost_map.get(&result.payload.file_path) {
                result.score = result.score * self.boost_factor;
            }
            // 去重：如果细节索引已有相同片段，保留分数更高的
            if !final_results.iter().any(|r| r.id == result.id) {
                final_results.push(result);
            }
        }
        
        // 4. 排序并返回Top-K
        final_results.sort_by(|a, b| b.score.partial_cmp(&a.score).unwrap());
        final_results.truncate(top_k);
        
        Ok(final_results)
    }
}
```

#### 3.4.2 Query扩展策略（可选）

```rust
pub async fn search_with_query_expansion(
    &self,
    query: &str,
    top_k: usize,
) -> Result<Vec<SearchResult>, Error> {
    // 1. 先检索摘要
    let summary_results = self.search_summary(query, 3).await?;
    
    // 2. 如果摘要相关度高，扩展query
    let expanded_query = if !summary_results.is_empty() 
        && summary_results[0].score > 0.7 
    {
        format!(
            "{}\n\nContext from file overview:\n{}",
            query,
            summary_results[0].payload.summary
        )
    } else {
        query.to_string()
    };
    
    // 3. 用扩展后的query检索细节
    self.search_detail(&expanded_query, top_k).await
}
```

### 3.5 索引构建流程

```rust
pub async fn build_hierarchical_index(
    orchestrator: &mut IndexOrchestrator,
    parsed_files: &[ParsedFile],
) -> Result<(), Error> {
    // 1. 生成文件摘要
    let summaries: Vec<FileSummary> = parsed_files
        .iter()
        .map(|pf| generate_summary(pf, calculate_importance(pf)))
        .collect();
    
    // 2. 存储摘要到摘要索引
    let summary_points: Vec<VectorPoint> = summaries
        .iter()
        .map(|s| VectorPoint {
            id: format!("summary:{}", s.file_path),
            vector: embed_summary(s).await?,
            payload: s.to_payload(),
        })
        .collect();
    
    orchestrator.summary_client.upsert_points(&summary_points).await?;
    
    // 3. 存储细节到细节索引（现有流程）
    for parsed_file in parsed_files {
        let conversions = orchestrator.converter.convert_parsed_file(parsed_file, None);
        let detail_points = build_detail_points(&conversions, &summaries);
        orchestrator.detail_client.upsert_points(&detail_points).await?;
    }
    
    // 4. 存储BM25摘要索引
    let bm25_docs: Vec<Bm25Document> = summaries
        .iter()
        .map(|s| Bm25Document {
            id: s.file_path.clone(),
            text: s.to_bm25_text(),
            metadata: HashMap::new(),
        })
        .collect();
    
    orchestrator.bm25_client.batch_index_summary(&bm25_docs).await?;
    
    Ok(())
}
```

## 四、实施建议

### 4.1 分阶段实施

| 阶段 | 内容 | 预期收益 |
|------|------|----------|
| **Phase 1** | 基于规则的摘要生成 + 摘要索引存储 | 快速验证效果 |
| **Phase 2** | 双路召回 + 分数融合 | 提升检索质量 |
| **Phase 3** | BM25摘要索引 + 混合检索 | 增强关键词召回 |
| **Phase 4** | 模型增强摘要（可选） | 提升摘要质量 |

### 4.2 配置参数

```toml
[hierarchical_index]
enabled = true
boost_factor = 1.2              # 摘要命中时的分数提升系数
summary_collection_suffix = "-summary"  # 摘要collection后缀
use_model_summary = false       # 是否使用模型生成摘要
model_summary_threshold = 0.7   # 使用模型摘要的重要性阈值
max_summary_length = 500        # 摘要最大长度
```

### 4.3 性能优化

1. **摘要索引优化**：
   - 使用较小的向量维度（512维）
   - 使用较小的HNSW参数（m=8, ef_construct=64）
   - 启用全表索引

2. **缓存策略**：
   - 缓存摘要向量，避免重复编码
   - 缓存文件到摘要的映射关系

3. **增量更新**：
   - 文件变更时，同时更新摘要和细节索引
   - 使用文件哈希检测变更

### 4.4 监控指标

| 指标 | 说明 |
|------|------|
| `summary_match_rate` | 摘要命中的查询比例 |
| `boost_effectiveness` | 分数提升后的排序变化率 |
| `summary_index_size` | 摘要索引大小 |
| `query_latency_p50/p95` | 查询延迟 |

## 六、总结

### 6.1 核心价值

1. **快速文件定位**：摘要索引作为第一级召回，快速定位相关文件
2. **相关性增强**：摘要命中时提升相关片段分数，提升检索精度
3. **上下文补充**：摘要提供文件级上下文，补充片段细节
4. **渐进式实施**：可分阶段引入，风险可控

### 6.2 实施优先级

1. **高优先级**：基于规则的摘要生成 + 摘要索引存储
2. **中优先级**：双路召回 + 分数融合
3. **低优先级**：模型增强摘要（可选）

### 6.3 预期效果

- 检索准确率提升：**15-30%**
- 文件定位速度提升：**2-3倍**
- 用户满意度提升：显著改善"找不到相关文件"的问题
