# 各语言不需要的内容说明

本文逐语言记录有意不实现的分发分支，用于后续排查时快速区分设计如此与真正缺口。判定口径以当前代码实际分支为准。所有条目均有文档注释与期望表测试锁定，不允许静默落入通用分支后又被当作缺口补齐。

使用方式：新增语言时对照此表确认哪些层可以直接复用保守回落，改动已有语言时先查此表，避免把有意简化改成误报更多的专用分支。查询矩阵说明每种查询有无原因，覆盖清单说明每个语言总体状态，本文只说明为何不需要。

## 通用原则

无类型系统的语言不做类型识别，无可见性体系的语言不做可见性区分，无包管理器的语言不设包供给方，模板与样式语言走嵌入块二次解析，数据格式与未知语言走文档通道，插件语言取决于插件供给。以上回落均为保守否定或通用复用，已在对应模块以注释加测试锁定。

## Rust、Python、JavaScript、TypeScript、Go

核心解析、符号提取、修饰符、行为控制流、标准库调用与分类、包供给方、导入分类、相对导入、测试注解与命名均有专用分支，不需要额外补充。

已经完成的内容：

* 可变参数判定已按语言逐个落地：重载候选携带提取期元数快照（总数、必需数、可变标记），各语言的剩余形收集器按声明文本识别，默认值计入必需数，无提取记录时保持中性。限定解析的精确预过滤为有意保留，重载打分路径走元数区间判定。逐语言用例与同步守卫已锁定。

不需要的内容：

* 去噪三批均已落地，不再列为缺口。C、C++、Python、JS 家族、Go、Bash、Java、C#、PHP、Ruby、Lua 均有专用去噪分支，Kotlin 取 JVM 互操作注解行、Scala 取编译器提示注解行、Dart 取重写标记与 lint 忽略注释，期望表测试锁定。模板与样式语言走嵌入块二次解析，数据格式与未知语言走文档通道，均按去噪设计有意关闭，不要补齐。
* 特质识别仅 Rust 有专用分支，其余语言统一否定。原因是特质为 Rust 语言概念，其他语言无对应语义。位置在标准库识别的类型特质分发，复用插件语言走有效语言继承，锁定测试覆盖可解析语言哨兵。
* 常量表按语言特性取舍，详见后文常量表一节，不要为补齐而补齐。

## Java、Kotlin、Scala、C#、Dart、JSX、TSX

解析、查询、提取、修饰符、标准库调用与分类、测试识别均完整，可见性均有专用分支，类型成员中 C#、C++、Dart 复用同族后端，JSX、TSX 与 JS 家族对等。

不需要的内容：

* 相对导入解析统一为空。原因是 Java、Kotlin、Scala、C# 导入恒为绝对包或命名空间路径，无相对语法，Dart 的相对部分已由文件拼接覆盖，包协议与 SDK 协议恒为空。位置在抽取上下文的相对解析分发，锁定测试断言四语言为空。不要为绝对路径加相对解析。
* 命名空间策略中除 Java 系与 C# 外的分支为空是有意的，JS 家族遗漏之外的空分支不要补。
* 导出标记仅 JS 家族与 C++ 访问段特殊处理，其余语言依赖可见性推导，不要为显式导出语言加重复标记。

## C、C++

查询与提取、修饰符与访问段、标准库调用与分类完整，相对导入与内部判断中引用型已覆盖，可见性与类型成员已有专用后端。

不需要的内容：

* 包供给方统一为空。原因是 C、C++ 走头文件路径分支而非包供给，头文件处理器解析包含路径即可。位置在供给方注册表，锁定测试断言两语言无供给方。不要新增包供给方。
* 测试实体识别仅路径规则。原因是常用框架的测试宏解析为调用表达式而非实体，实体层强行识别只增误报，且信号本身受路径约束。位置在测试套件语言分发，降级理由已在模块注释写明。不要为调用形宏加实体分支。
* 可见性命名分支为空。原因是 C 无命名约定可见性，存储类信号已够用。不要加命名启发式。

## PHP

提取与修饰符、标准库完整，可见性与类型成员已有专用后端，命名空间包声明已提取，文件包含相对解析已覆盖。

不需要的内容：

* 可见性命名分支为空。原因是 PHP 可见性完全由修饰符决定，无命名约定。不要加下划线之类的启发式。
* 包供给方已有，无需为文件包含另设供给方，文件包含走相对解析即可。

## Ruby

提取与标准库调用完整，修饰符有意为空，可见性与类型成员已有专用后端。

不需要的内容：

* 修饰符提取统一为空。原因是 Ruby 可见性通过方法调用而非声明修饰符表达，无修饰符概念。位置在修饰符提取分发的有意为空分支，锁定测试断言空且不泄漏。不要把调用名当修饰符抽取。
* 类型识别中通用回落部分是有意的，动态类型不做静态推断，不要强行加类型分支。
* 测试实体识别中注解与命名统一为空，仅保留路径规则。原因是测试框架的描述块解析为调用而非实体，实体层识别无增益。降级理由已在语言分发注释写明。不要加调用名匹配。

## Lua、Bash

提取与标准库调用完整，其余多为保守回落，均属设计如此。

不需要的内容：

* 修饰符提取统一为空。原因是两语言无修饰符概念。锁定测试同上。
* 类型识别统一否定。原因是无静态类型系统。位置在标准库类型的语言分发，保守否定并有同步测试。不要加类型表。
* 可见性统一文件域。原因是无可见性体系，符号默认文件可见即可。位置在策略默认分支，Bash 的局部变量信号除外。不要加公开默认。
* 类型成员统一通用回落。原因是无类型定义体系，父子索引已够用。位置在类型成员分发的通用分支，锁定测试覆盖两语言。不要加专用后端。
* 包供给方统一为空。原因是无中心包管理语义，相对引用走文件拼接即可。锁定测试断言两语言无供给方。不要新增供给方。
* 测试实体识别仅路径规则，Lua 的命名规则需先满足路径规则才触发。原因是测试框架的描述块同样为调用形。不要放宽路径约束。
* 常量表统一否定。原因是误报率高，待调用链精度提升后再议。不要加命名约定常量表。

## Html、Css、Vue、Svelte、Ejs、Scss、Less

模板与样式语言整体走嵌入与文档通道，缺失的调用与行为能力属于设计，不列为缺口。

不需要的内容：

* Scss、Less 无独立语法解析，统一走文档通道。原因是项目内无对应语法解析器，样式语义无需 AST。位置在语言检测的文本类型分支。不要加 AST 分支。
* Html、Css、Vue、Svelte、Ejs 无直接符号提取器，统一为空。原因是依赖嵌入块二次解析，嵌入内容以宿主语言重新进入各层。位置在符号提取器工厂，统一返回空。不要加直接提取器。
* 调用、行为、控制流查询缺失由嵌入回路补回，其中行为与控制流在模板语言间不对称，原因已在查询矩阵写明。不要为模板语言补直接查询。
* 标准库识别统一保守否定。原因是模板自身无标准库调用，嵌入块以宿主语言判定。锁定测试断言模板语言恒假，复用插件继承宿主。不要加模板标准库表。
* 可见性与供给方统一保守，无包供给方。原因同上。不要新增。

## Json、Yaml、Toml、Xml、Unknown 与扩展名未知文本

统一走文档通道，不参与 AST 评定。原因是数据格式无实体关系语义，未知语言无语法保证。位置在文件类型路由与解析门禁。不要加 AST 分支，不要加标准库、可见性、供给方分支。

## Custom 插件语言

取决于插件供给。无插件时各层保守回落，有复用声明时经有效语言解析继承宿主的调用识别、裁剪、去噪与分组行为，类型与常量层统一走有效语言解析。原生插件语言可通过启发式钩子声明调用级行为（标准库调用分类、裸方法表），未声明时维持保守。

已经完成的内容：

* 调用级插件扩展点已落地：新增标准库调用分类与裸方法表两个可选钩子，复用既有启发式能力名，保持旧插件兼容。宿主解析器按优先级取首个答案，异常与超时记告警并回落内置。接入点为调用抽取分类与嵌入文本裁剪，均仅对自定义语言生效，内置语言行为不变。实体级已有钩子覆盖，无需重复。去噪画像暂不开放插件自定义。

不需要的内容：

* 未声明新钩子的原生插件语言在各层维持保守否定，不要为其加宿主表继承。
* 复用插件语言不需要逐层加分支，入口解析有效语言后自动继承，冒烟测试锁定继承与回落即可。新增分发时必须先解析有效语言再匹配，否则复用继承会断裂。
* 配套能力默认可选组合，严格项目可用 `plugins.missing_heuristics_policy = "deny"` 拒绝无配套语言的注册，默认 `warn` 只告警不断流。拒绝与放行均有期望测试锁定。
