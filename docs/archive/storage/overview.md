# 存储模块跨域架构对比（归档）

> 范围：向量、全文、关系三类存储的合约位置、装配方式、隔离模型、接线状态。
> 结论性质：本目录只归档经评估为合理的差异；设计问题另见计划目录中的问题清单。

## 合约位置

- 向量合约与关系合约集中存放在中立的 `cce-storage-common` 中，实现 crate 只保留转接逻辑。
- 全文合约存放在实现 crate `cce-storage-bm25` 内部的合约模块中，与本地分支实现同 crate。
- 该布局差异本身是历史成因，不影响语义，但给复用带来不对称，是否保留见问题清单。

## 装配层形态

- 三类存储都在编排层使用后端枚举做分支选择，不使用特征对象，符合项目约定的无动态分发原则。
- 向量枚举完整实现了向量合约，读写两侧的本地与远端分支都可用。
- 全文枚举与关系枚举是纯粹的持有型枚举，未实现各自的存储合约；写入侧、读取侧与热更新侧目前只接受本地分支，远端分支构造成功但在各消费点直接返回配置错误。
- 向量属于真实双后端可用，全文与关系属于合约与配置先行、运行时只接本地，这是三者最大的接线状态差异。

## 隔离与命名模型

- 向量：双后端共享同一个集合名，按字符串分组标识做逻辑隔离。
- 全文：共享索引内的工程字段做隔离，索引名作为调用参数传入。
- 关系：本地按工程拆分为独立数据库文件并通过工程句柄进入，远端在共享库内按工程字段过滤，进入操作只是克隆。
- 三种隔离形态分别贴合各自引擎的物理形态，属于合理差异。

## 读写可变性

- 向量与关系合约全部使用共享引用，后端在内部自行处理并发。
- 全文合约的批量写入使用独占引用，上层因此用互斥锁持有本地客户端。
- 该差异源于全文写入器的历史形态，归档为已知差异，是否收敛见问题清单。

## 世代可见性语义

- 三类存储都理解世代概念：向量用世代列表加排除文件列表，全文用工程加世代加排除文件，关系用工程加世代的内容行与快照链。
- 单世代忽略排除文件、多世代只隐藏父世代被覆盖文件的规则在三路保持一致。
- 后端切换一律要求全量重建，不做跨后端数据迁移，三类配置注释与文档口径一致。

## 可观测性与韧性

- 远端分支普遍自带断路器、重试与指标，本地分支依赖进程内调用，不设网络类韧性措施。
- 向量枚举在装配层提供统一的健康诊断快照，全文与关系枚举缺少对等物，调用方需要自行分支。
- 前者是合理的物理差异，后者是待补齐的对称性缺口，见问题清单。
