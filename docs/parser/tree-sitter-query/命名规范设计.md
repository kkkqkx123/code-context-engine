# 查询捕获命名规范设计

## 概述

本文档定义了 Tree-sitter 查询捕获的统一命名规范，确保跨语言的一致性和 parser 逻辑的简洁性。

## 设计原则

1. **层次对称性**：所有捕获名称使用相同的层次结构
2. **可解析性**：parser 可以通过简单的字符串分割提取语义信息
3. **跨语言一致性**：相同概念在不同语言中使用相同的命名
4. **可扩展性**：支持未来添加新的语言和实体类型
5. **简洁性**：在保证信息完整的前提下尽量简短

## 命名格式

### 基本格式

```
@[domain].[category].[subtype].[role].[attribute]
```

### 层次说明

| 层次 | 位置 | 说明 | 可选性 |
|------|------|------|--------|
| domain | 1 | 顶级域（entity/call/dependency/comment） | 必填 |
| category | 2 | 大类分类（type/function/variable等） | 必填 |
| subtype | 3 | 具体子类型（class/struct/definition等） | 必填 |
| role | 4 | 捕获角色（name/body/params等） | 必填 |
| attribute | 5 | 可选属性（qualified/nested/template等） | 可选 |

## Parser 解析逻辑

### 数据结构

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub enum Domain {
    Entity,
    Call,
    Dependency,
    Comment,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub enum EntityCategory {
    Type,
    Function,
    Method,
    Variable,
    Component,
    Namespace,
    Template,
    Preprocessor,
    Attribute,
    Delegate,
    Event,
    Property,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub enum CallCategory {
    Direct,
    Method,
    Constructor,
    Template,
    Delegate,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub enum DependencyCategory {
    Include,
    Using,
    Import,
    Macro,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub enum CommentCategory {
    Line,
    Block,
}

#[derive(Debug, Clone)]
pub struct CaptureName {
    pub domain: Domain,
    pub category: Option<String>,
    pub subtype: Option<String>,
    pub role: Option<String>,
    pub attribute: Option<String>,
}
```

### 解析函数

```rust
impl CaptureName {
    pub fn parse(capture: &str) -> Result<Self, ParseError> {
        // 移除 @ 前缀
        let capture = capture.strip_prefix('@').unwrap_or(capture);

        // 分割各部分
        let parts: Vec<&str> = capture.split('.').collect();

        if parts.len() < 2 {
            return Err(ParseError::InvalidFormat);
        }

        // 解析 domain
        let domain = match parts[0] {
            "entity" => Domain::Entity,
            "call" => Call::Call,
            "dependency" => Domain::Dependency,
            "comment" => Domain::Comment,
            _ => return Err(ParseError::UnknownDomain(parts[0].to_string())),
        };

        // 解析其他部分
        Ok(CaptureName {
            domain,
            category: if parts.len() > 1 { Some(parts[1].to_string()) } else { None },
            subtype: if parts.len() > 2 { Some(parts[2].to_string()) } else { None },
            role: if parts.len() > 3 { Some(parts[3].to_string()) } else { None },
            attribute: if parts.len() > 4 { Some(parts[4].to_string()) } else { None },
        })
    }
}
```

## 命名示例

### C 语言示例

```scheme
; 结构体定义
(struct_specifier
  name: (type_identifier) @entity.type.struct.name
  body: (field_declaration_list) @entity.type.struct.body
) @entity.type.struct

; 函数定义
(function_definition
  type: (_) @entity.function.definition.return_type
  declarator: (function_declarator
    declarator: (identifier) @entity.function.definition.name
    parameters: (parameter_list) @entity.function.definition.params
  )
  body: (compound_statement) @entity.function.definition.body
) @entity.function.definition

; 直接函数调用
(call_expression
  function: (identifier) @call.direct.function.name
  arguments: (argument_list) @call.direct.function.arguments
) @call.direct

; 宏依赖
(preproc_def
  name: (identifier) @entity.preprocessor.macro.name
) @entity.preprocessor.macro
```

## 迁移指南

### 从旧命名迁移到新命名

| 旧命名 | 新命名 | 说明 |
|--------|--------|------|
| @entity.type.class.name | @entity.type.class.name | 无变化 |
| @entity.method.definition.name | @entity.method.definition.name | 无变化 |
| @entity.function.definition.name | @entity.function.definition.name | 无变化 |
| @entity.variable.normal.name | @entity.variable.declaration.name | subtype 更改为 declaration |
| @entity.variable.local.name | @entity.variable.local.name | 无变化 |
| @entity.field.name | @entity.variable.field.name | category 更改为 variable |
| @entity.parameter.name | @entity.variable.parameter.name | category 更改为 variable |
| @call.direct.function.name | @call.direct.function.name | 无变化 |
| @call.method.object.name | @call.method.instance.object | subtype 更改为 instance |
| @call.method.function.name | @call.method.instance.function | subtype 更改为 instance |
| @call.static.class.name | @call.method.static.class | category 更改为 method |
| @call.static.method.name | @call.method.static.function | role 更改为 function |
| @dependency.using.namespace.name | @dependency.using.namespace.name | 无变化 |

## 最佳实践

1. **保持一致性**：同一类别下使用相同的命名模式
2. **避免冗余**：不要在命名中重复信息（如 @entity.type.class.type_name）
3. **使用描述性名称**：role 应清晰描述捕获的内容（name, body, params）
4. **可选属性**：只在必要时使用 attribute 层
5. **文档化**：为自定义的捕获名称添加注释说明

## 扩展指南

当需要添加新的捕获类型时：

1. 确定所属 domain（entity/call/dependency/comment）
2. 确定所属 category（如果有）
3. 选择合适的 subtype（如果需要更细粒度）
4. 定义 role（name, body, params 等）
5. 如有特殊属性，添加 attribute 层
6. 更新本文档

示例：
```
@entity.<category>.<subtype>.<role>.<attribute>
      ↓          ↓         ↓      ↓         ↓
    domain    category  subtype  role   attribute
```
