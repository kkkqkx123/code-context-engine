# Relation 模块总览

## 模块简介

`src/relation` 目录是代码关系提取引擎的核心模块，主要负责从源代码中提取函数调用关系、构建索引并提供查询能力。该模块支持多语言，并采用分层架构设计。

## 核心功能

1. **关系索引构建** - 从 ParsedFile 构建函数调用关系索引
2. **调用链查询** - 基于 EntityId 进行正向/反向调用链查询
3. **文件状态管理** - 支持增量解析和依赖跟踪
4. **跨文件符号解析** - 多语言符号解析和依赖关系管理
5. **文件级依赖跟踪** - 基于文件级的依赖图管理，支持热更新与增量解析

## 索引结构

Relation 模块包含以下核心索引：

### 基础索引（5 个）

1. **Function Index** - EntityId -> Entity（函数实体索引）
2. **Call Index** - caller ID -> 调用关系（调用关系索引）
3. **Import Index** - file ID -> ImportTable（导入表索引）
4. **File Index** - file ID -> FileInfo（文件信息索引）
5. **Export Index** - file ID -> 导出列表（导出索引）

### 新增索引（新架构）

6. **Resolved Relation Index** - caller EntityId -> 已解析的关系
7. **Callee Index** - callee EntityId -> caller 列表（反向索引，性能优化）

## 模块组织结构

```
src/relation/
├── mod.rs                    # 模块入口和重新导出
├── types.rs                  # 通用类型定义
├── error.rs                  # 错误类型定义
├── context.rs                # 错误上下文处理
├── query.rs                  # 调用链查询 API
├── dependency_graph.rs       # 文件级依赖图（热更新）
├── config_parser/            # 构建配置解析器
├── symbol/                   # 符号抽象层
├── symbol_table/             # 四层符号表架构
└── index/                    # 关系索引和解析
```

> 注：符号提取层位于 `src/parser/extractor/`（语言无关的导入/导出提取）。

## 核心架构层次（自底向上）

### 1. Symbol 层（symbol/）

符号抽象层，提供基础类型：

- `SymbolId` - 符号标识符
- `Visibility` - 可见性模型（支持多语言）
- `ScopeContext` - 作用域上下文
- `SymbolMetadata` - 符号元数据

> 继承图功能（`InheritanceGraph`）已移至 `relation::oop` 子模块，
> 供 OOP 语言的 protected 成员可见性检查使用，当前默认不启用。

### 2. Symbol Table 层（symbol_table/）

四层符号表层次结构：

- `LocalSymbolTable` - 文件级符号管理
- `ModuleSymbolTable` - 模块级导入/导出
- `PackageSymbolTable` - 包级导出
- `ProjectSymbolTable` - 项目级符号管理

### 3. Index 层（index/）

关系索引和解析：

- `RelationIndex` - 核心索引结构
- `IndexBuilder` - 索引构建器
- `RelationResolver` - 跨文件关系解析
- `LocalCallResolver` - 单文件调用解析（预处理）
- `DependencyIndex` - 依赖查找索引

## 支持模块

### Extraction 层（src/parser/extractor/）

语言无关的导入/导出提取：

- `traits.rs` - 核心提取器 trait
- `common/standardized.rs` - 标准化类型
- 语言特定提取器：C, C++, C#, JavaScript, TypeScript, Rust, Go, Python, PHP, Ruby, Dart, Scala

### Config Parser 层（config_parser/）

构建系统配置解析：

- 支持 Cargo.toml (Rust)
- package.json (JavaScript/TypeScript)
- requirements.txt / pyproject.toml (Python)
- go.mod (Go)
- pom.xml / build.gradle (Java)
- CMakeLists.txt (C/C++)
- 等等...

### Dependency Graph（dependency_graph.rs）

文件级依赖跟踪（用于热更新）：

- 前向依赖（文件依赖谁）
- 反向依赖（谁依赖文件）
- 拓扑排序
- 循环依赖检测

### Query 层（query.rs）

高级调用链查询 API：

- `CallChainQuery` - 调用链查询
- `CallChainTraverser` - 图遍历算法
- `TraversalConfig` - 遍历配置

## 解析流水线

关系解析遵循两阶段流水线：

```
1. LocalCallResolver（单文件）
   └─> 解析文件内部调用
   └─> 计算调用顺序
   └─> 生成 LocalCall

2. RelationResolver（跨文件）
   └─> 解析跨文件调用
   └─> 分类外部调用（stdlib/external/unknown）
   └─> 构建完整索引
```

## 多语言支持

### 可见性模型

支持多种语言的可见性规则：

- **Rust**: pub / pub(crate) / pub(super) / pub(in path) / private
- **Java**: public / protected / package / private
- **Go**: 导出（大写）/ 未导出（小写）
- **Python**: public / \_private / **dunder**
- **C#**: public / internal / protected / private / protected internal
- **C++**: public / protected / private / friend

### 导入分类

支持将导入分类为：

- StandardLibrary - 标准库
- ExternalPackage - 外部包
- InternalModule - 内部模块

- Unknown - 未知

## 性能优化

1. **反向索引** - Callee index 实现 O(1) 反向查找
2. **DashMap** - 所有内部映射使用 DashMap 实现线程安全
3. **Arc 共享** - 使用 Arc 减少内存冗余
4. **选择性索引** - 支持选择性索引以节省内存
5. **依赖索引** - 高效的依赖查找结构

## 错误处理

模块定义了详细的错误类型：

- `RelationError` - 顶层错误
- `IndexError` - 索引相关错误
- `RelationQueryError` - 查询相关错误
- `ResolutionError` - 解析相关错误
- `PersistenceError` - 持久化错误
- `ConfigParseError` - 配置解析错误

## 使用示例

```rust
use crate::relation::{
    IndexBuilder, RelationIndex, CallChainQuery, LocalCallResolver,
    RelationResolver, ProjectSymbolTable
};

// 1. 创建索引
let index = RelationIndex::new();

// 2. 构建索引
let builder = IndexBuilder::new();
builder.build(&parsed_files, &symbol_table, &index);

// 3. 查询调用链
let query = CallChainQuery::from_index(index.clone());
let callees = query.get_callees_by_entity(entity_id)?;
let callers = query.get_callers_by_entity(entity_id);

// 4. 查找调用路径
let path = query.find_call_chain(start_id, end_id, max_depth)?;
```
