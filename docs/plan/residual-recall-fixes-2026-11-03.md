# 残留召回问题的解法与影响面分析

状态：分析完成，未改代码。基于 2026-11-03 新鲜主输出（`per_query_results_top*.md`，
`variant=all`，`emb` / `BM25` 为主口径，`_group` 为诊断口径）。
`retrieval_method/` 与场景转储为 10-15 旧产物，本分析不引用其中任何结论；
任何融合相关判断需重跑后再下。

## 1. 残留清单与机制分类

顶层 6 个（`full=0` 且 `direct/raw` 任一为 1），随切口衰减为 4、1、1。
按机制分为四类，未按查询罗列（逐查询证据见第 5 节）。

### 类 A：单成员超限多分片（边界，需多命中）

成员转换文本超过预算，被 `SentenceBoundary` / `HardLimit` 切成同成员多片，
单次检索只能命中一片，无法一次覆盖标注区间。
属于此类：`add_url_rule`（两片）、`make_response`（词项六片以上）、
`Blueprint.register`（词项三片）、`handle exception`（`G2Q7`）、
`send_file`（`G2Q17` 长方法部分原因）。

### 类 B：小实体被邻联合并稀释（边界，合并过度）

完整但弱小的成员与邻居合并后词项密度下降，精确查询排不上。
属于此类：`is_match` 与 `is_match_candidate` 合为 77 词元一块、
`Match::new` 与四个兄弟方法合为 147 词元一块。
注意与首轮合并的关系：组内跨成员合并是既有行为（早于首轮修改），
首轮只是把它推广到了词项跨组；稀释机制本身不是首轮引入的。

### 类 C：原生文本胜出（词项密度与词汇竞争）

原生切片恰好以更高密度命中查询词，而转换文本因改写或稀释落选。
属于此类：`FZ-G1Q7` / `G2Q11`（`attach` / `merge` 查询词在源码中不存在或稀少，
原生靠 `blueprint` 密度胜出）、`find_at`、飓风 `342-344` 三处向量
（原生 3 行超密，转换块附带兄弟方法被稀释）、`G2Q18` 向量。

### 类 D：聚焦单块存在但排不上（竞争与词汇缺口）

块本身已理想（精确区间、主题集中），失败与分块无关。
属于此类：`dispatch_request`（向量，兄弟成员语义拥挤）、
`process_response`（`G2Q6`，词项，高频词竞争加 `callbacks` / `run` 缺失，
持续到 `top50`）、`flash`（`G2Q18` 词项，全基线为零，`store` 缺失）。
这类在分块层无操作杆，硬改文本等于对评测查询过拟合，明确不做。

## 2. 解法 S1：超限成员概览卡（对应类 A）

原理：成员被切成多片时，额外产生一张概览卡。文本取首片头部截断
（头部天然包含身份、签名、摘要与主题，无需改转换器），区间取同成员
各分片的并集（满足单次命中覆盖），计入正常块预算，不设重叠链。
只有被切散的成员才产生卡片，单片成员不受影响。

改动位置：分块器文件级后处理（`chunk_groups` 末尾，按实体标识跨块归组），
转换器、模板、合并器、配置均不动，纯加法。

影响面：

- 代码：分块器内一处后处理加一个小模块，无语言相关分支，
  所有语言均匀受益；单测覆盖成卡条件、区间并集、上限截断三点即可。
- 块数与成本：按当前导出中 `SentenceBoundary` / `HardLimit`
  切分事件计数，卡片增量约为向量 3% 到 5%、词项 6% 到 10%，
  嵌入与索引成本同比增加，无量级变化。
- 风险：卡片与自身分片同场竞争，可能轻微挤占精确分片的排名，
  但召回方向为正；双向翻转以验证为准。爆破半径限于超限成员，
  已通过的单片成员查询不受影响。
- 验证成本：一轮全量验证（单测一次编译，导出无外部调用，
  两次 bench 生成需嵌入接口，两次离线评测）。

预期收益：覆盖顶层残留中的四个（`FZ-G1Q5`、`G1Q3`、`G2Q11` 词项侧、
`G2Q17` 大概率），`top10` 的 `G2Q3` / `G2Q7` 同理。
`FZ-G1Q7`（`attach` 词汇缺口）与 `G2Q1`（类 D）不在覆盖内。

## 3. 解法 S2：完整单元合并否决（对应类 B）

原理：跨实体合并只允许抢救碎片，不允许粘连完整单元。
判定为完整单元的条件是单侧区间覆盖其自身组跨度约完整，
且两侧区间互不包含（包含关系仍走原有的重复声明例外）。
同实体分片填充上限、包含关系抢救两条规则保持不变，
因此爆破半径被构造性地限制在完整小实体的粘连上。

改动位置：组内跨成员合并臂与跨组合并判定两处，
需把组跨度查表传入判定点；其余逻辑不动。

影响面：

- 代码：合并器两处加否决条件，语言无关；现有合并单测需补完整单元用例。
- 块数与成本：仅解绑完整小实体的粘连，增量为小个位数百分比，
  嵌入成本可忽略。
- 风险：中等。全语料小实体合并形状变化，已通过查询可能双向翻转，
  必须以双项目验证为准。注意与类 C 中 `is_hidden` 三胞胎的张力：
  三胞胎是同主题三份希望合，`is_match` 对是异主题希望拆，
  仅靠尺寸规则无法同时满足两者；彻底解决需要相似度门控合并，
  属更大改动，见第 4 节后续。
- 验证成本：与 S1 相同的一轮全量验证，建议在 S1 之后独立执行以便归因。

预期收益：`ripgrep` 词项新增的三处翻转（`is_match` 对、`Match::new`）
回到通过；`flask` 词项侧基本不受影响（其合并以同实体填充为主）。

## 4. 检索层解法与明确不做项（对应类 C、类 D）

类 C 与类 D 在分块层或无操作杆，或操作即过拟合，正确分层如下：

- 同义词扩展（`callbacks` 到函数、`store` 到 `flash` / `append`、
  `attach` 到 `register`、`constructor` 到 `new`）属于词项检索引擎层，
  不属于分块管线。本次不做，记为检索层后续。
- 融合路径（`minmax` / `rrf`）天然覆盖单路缺失，
  但现有融合输出已过期，需重跑后才能确认 `G2Q6`、`G2Q18` 等在融合下恢复。
  重跑零代码改动，可与 S1 或 S2 的验证轮合并执行。
- 明确拒绝：整体抬高预算（全局稀释加索引膨胀）、
  模板为评测查询加词（过拟合，中长期污染所有查询）、
  为 `dispatch_request` 兄弟竞争改分块（块已理想，杠杆在检索多样性）。
- 永久接受：`FZ-G1Q7` 的 `attach`（源码中不存在该词，纯词汇噪音下限）。

`is_hidden` 三胞胎（同名同类跨组三份）需要相似度门控合并或分组层
同形折叠，两者都触及分组与合并的核心不变量，风险高于其单个查询收益，
记为后续，不进入本轮。
