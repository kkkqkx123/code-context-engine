# 关系构建期常驻内存收敛设计

## 背景

模块表磁盘化后，medium 档关系阶段增量已降到 112,328 KiB，峰值 RSS 为 488,736 KiB，达到当前验收线。剩余工作不再追求严格 RSS 硬上限，而是继续消除随项目规模线性增长的全量驻留，并让已有软性预算有真实字节口径。

当前仍有四类常驻来源：

- artifact 写出前把文件、实体、关系、依赖整表收集到内存；
- `for_each_import` 把导入表整表收集到内存；
- `ProjectSymbolTable` 的全局名称、命名空间、频率、类型贡献和跨文件传播缓存随符号数增长；
- 文件清单、导出摘要和上一代查询快照在进程内完整保留。

## 设计原则

- 磁盘化只改变数据存放位置，不引入第二套解析算法；内存路径继续作为单测对照。
- 工作集按条目数和估算字节数双重约束；驱逐必须回源 SQLite，不得静默丢弃语义数据。
- 语义候选超限继续让 operation manifest 失败，不激活 generation。
- 新增指标只描述已发生的驻留，不伪装成运行时硬限制。
- 参数按内存档位预设，显式配置优先；不保留旧数据迁移路径。

## 流式写出

artifact 阶段保留 SQL 的确定性排序，但逐行读取并向 `SnapshotArtifactBuilder` 推送。每行的稳定符号键、导入表和导出表查询使用独立的只读 SQLite 连接，避免与主游标争用同一个连接锁。外部排序器继续按固定块落盘，写出过程的峰值内存只由单个行、排序块和文件缓冲决定。

`for_each_import` 同样改为逐行回调。调用方不得在该回调内重入同一个构建库连接；需要反查时走只读连接。

## 磁盘化符号索引

全量构建路径把 `global_index` 和 `namespace_index` 写入操作本地 SQLite，按需回源，不再初始化对应的进程内全量表。`call_frequency` 已体现在候选排序键中，全量路径不再常驻。`file_type_contrib` 只在增量路径使用，全量路径以 `module_types` 表为事实来源。

`CrossFilePropagator` 保留按 `(name, arity)` 分桶的候选 ID 集合；函数返回类型、参数类型和字段类型改为按 EntityId 从 SQLite 读取并进入小型工作集。分桶裁剪仍计入 manifest 失败条件。

## 文件清单、摘要与快照

扫描结果写入操作本地 `scan_files` 表，按序号分批读取，文件列表哈希在扫描时流式计算。导出摘要写入 `ExportSpool`，与 chunk 共用生命周期，最终导出阶段按路径逐文件回放。

全量构建开始时释放进程内持有的上一代查询快照；已持有引用的在线请求继续完成。新快照发布前，关系查询显式报告重建状态，不返回空图。

## 工作集字节预算

`BuildSymbolView` 为模块记录和名称候选桶维护真实条目字节账本，驱逐时减去入账字节，峰值指标取实际驻留字节的最大值。模块记录以序列化 JSON 长度估算，候选桶以候选的序列化估算长度求和。

`LocalSymbolStore` 修正字节账本口径：入账和出账统一使用同一份估算值，避免计数器漂移导致过度驱逐或低估。

新增 `name_bucket_peak_candidates` 指标，用于把候选桶上限从经验值调整到基于峰值的值。该指标进入 operation manifest。

## 参数分档

参数分为三档，默认档为 `balanced`：

- `low-memory`：小批、低并发、小工作集、小排序块、小查询分片缓存。适合容器和内存受限部署。
- `balanced`：保持当前 medium 性能，限制处理并发到大核机器的合理区间，查询分片缓存降到 64 MiB。
- `high-throughput`：大批、高并发、大工作集、大排序块和 256 MiB 查询分片缓存，适合专用索引节点。

必须进入预设的参数包括批量大小、解析与处理并发、符号工作集条目与字节、候选桶上限、解析缓存、通配符展开上限、artifact 排序块、查询分片缓存和单文件关系上限。全局配置和项目 patch 都能覆盖默认值；项目 patch 只覆盖显式给出的字段。

## 验证

medium 作为主回归：实体、关系、向量计数和双指纹不变，候选裁剪为零，artifact 阶段不再随实体数线性增长，查询 p95 不明显回退。large 只做最终冒烟，重点确认峰值不回到数 GiB、关系计数比例一致、无裁剪失败。
