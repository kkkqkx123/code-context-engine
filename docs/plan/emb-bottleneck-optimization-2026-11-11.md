# emb 转换瓶颈分析与改进方案（2026-11-11）

日期：2026-11-11
范围：gin、media_server、ripgrep、oncecell 四个 emb 弱于 BM25 的项目，flask 为 emb 占优的对照
上游结论：同一向量模型下 flask 语义大胜，说明 emb 文本在信号充分时足够；四个项目的落后来自转换结果的信号缺失与稀释，而非模型本身

## 1. 基准口径与总体结论

评测为两种口径。range 口径统计实现限定变体下各检索形态的强弱相关召回；retrieval 口径复用 bench_data 做离线余弦与词项重放。gin 与 media_server 只有 range 口径，oncecell、ripgrep、flask 两种口径齐备。

顶层上 gin 全类型落后约十个百分点；oncecell 落后集中在语义类，向量约四成五对词项约八成三；ripgrep 在 range 口径向量略优、retrieval 口径打平偏弱、模糊类落后约七个百分点，直接切分下向量远优说明全管线文本有稀释；media_server 落后集中在模糊类约十三分。flask 则向量全面领先，语义类向量满分对词项七成五。

逐查询上 gin 七个查询向量为零而词项为一；oncecell 语义类多为部分召回；ripgrep 与 media_server 的落后多为模糊扰动查询；flask 仅一个语义查询向量弱于词项。落后可复现且集中，具备文本侧归因条件。

## 2. 项目特征对比

文档维度上 flask 方法几乎全带长而独特的大段文档字符串，查询多为文档的近义改写；gin 重载族文档近乎雷同；oncecell 公共接口文档丰富但被考的三个后端实现文档稀薄；media_server 与 ripgrep 内部函数多为裸代码。emb 有独特文档时赢，无文档或文档雷同时输；词项有原文词项兜底。

命名维度上 flask 类名互不相同且查询用原大小写；四个项目全是重名重灾区：三文件各一个同名单元、遍地新建构建查找、连字符文件名加蛇形函数、大小写下划线扰动。emb 限定词只写一次且淹没在样板里；词项靠分词加关键词加权加逆文档频率把稀有词顶上去。

分块维度上 flask 大类按方法单切；ripgrep 一个实现块塞六个方法、gin 三个方法一块、media_server 语义相反的一对同块。emb 同主题兄弟互为竞争者，向量取平均后目标查询两头不靠；词项析取匹配不受影响。emb 块数比词项多约三到四成，多出的是碎片与重复头而非更准的切分。

## 3. 瓶颈归因

同组多方法稀释为最主要瓶颈。组头的方法签名汇总、实现声明汇总、包含关系、调用聚合在每个块重复，大组每个块背十几个签名。证据为多处向量为零而分组为一，说明块级稀释、组级可救；部分查询组级亦为零，说明稀释已伤及组向量。

标识符归一化缺失为模糊类主因。词项分词切驼峰蛇形连字符并转小写，关键词另存组合形态；向量只写原始限定名，大小写空格扰动、下划线连字符差异、同义动词、种类词错位全靠模型 bridging，稀有领域词基本失败。

文档缺失无补偿且正文尾部易被截。词数硬截断先保头丢尾，而区分信号多在尾部调用与注释；变量关系行与签名重复行挤占预算；套话文档与相邻兄弟文档互为干扰。

样板权重过大且无逆文档频率等价物。可见性修饰、双重身份行、变量三行式在小函数中占比近半；稀有归属词只出现一次。词项侧逆文档频率自动压样板抬稀有词，向量侧注意力被高频样板吃掉。

进口与文件信号被主动丢掉。进口类实体按样板跳过，方法只按类型限定不带文件，同名类型跨文件文本完全一样，调用聚合还可能把基础设施调用当样板剪掉。跨后端区分查询因此无信号可用。

多子句跨文件查询的单向量平均。两地答案拼一句查询时向量取平均两头不靠，词项析取两头各中；跨行为边界的合并块直接毁掉弱相关召回。

## 4. 修改方案

只动向量模板原模块，不新增模块，不改词项路、预算数值、评测与对齐口径。

第一处为标识符别名行。向量成员描述与组描述在身份行之后增补一行自然词别名，把限定名中的驼峰蛇形连字符路径分隔拆成空格小写词，去重后输出，单行封顶。目标是模糊扰动查询的符号映射进入向量文本，词项路不受影响。

第二处为向量身份去可见性修饰。向量模板的修饰词保留逻辑改为丢弃公开性修饰，只保留行为修饰如异步静态等。目标是压低每块共有的高频样板，查询从不提及可见性故无信号损失。

第三处为循环变量三行合一。循环变量的关系行、签名行、来源行在同时出现时只保留一行，优先保留含调用或来源的行。目标是削减 gin 类大函数块中的变量水文占比，把预算还给调用与注释锚点。

明确不做项为方法签名汇总上限调整、调用聚合截断调整、跨函数合并阈值调整、文件提示注入，以上留待本轮验证后再议，避免一次改动过大无法归因。

## 5. 影响面

改动集中在向量模板一个文件内的三个位置，均为向量路内加减，不涉及解析器、分组器、切分器、存储与评测。块数与区间逻辑不变，嵌入与索引成本不变。排序上扰动查询与变量密集块的排名预期上升，独特文档查询因增量为加法而基本不动。词项输出逐字节不变，分组覆盖保持诚实。
