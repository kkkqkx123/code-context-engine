# 文件折叠无状态工具改造方案

本文是独立折叠服务设计在代码解析引擎侧的落地计划，只新增一个无状态工具，不改动现有压缩、符号、诊断工具的行为。

## 1. 现状缺口

解析器的文件折叠模块已存在，基于已解析文件的实体列表抽取顶层类型与函数骨架，支持详细与极简两种模式与 token 上限截断。但该模块没有对外出口，只能在索引链路内部使用。

编排层的语义压缩工具要求文件路径落在服务端磁盘上，走校验、解析、分组、自然语言转换全链路，语义是文件摘要而非符号骨架，不接受原始文本。符号类工具要求项目标识与关系快照，依赖预先索引。诊断工具是当前唯一的无状态文本输入形状，可作为新工具的形态模板，但其职责是语法报错而非折叠。

因此工作流侧需要的按文本折叠能力在服务端没有对应端点，必须新增。

## 2. 新增工具形态

新增文件折叠工具，定位为诊断工具的姊妹工具：纯计算、无副作用、不读写索引、不要求项目上下文。

请求承载原始文本、可选的语言名、可选的文件名、可选的期望上限与模式。语言解析顺序为显式语言优先，其次按文件名后缀推断，最后按未知处理。未知语言不报错，走截断降级。

响应承载折叠文本、实际使用的语言、结构是否已知、折叠前后 token 估算、保留与丢弃的节数。未知或失败场景同样返回该形状，只是折叠文本为截断式并标记结构未知。

该工具复用解析协调器做语言解析与实体抽取，复用现有折叠模块做骨架格式化与上限截断，复用公共 token 估算。输入体量设全局上限，超限直接走截断降级，避免大文本拖慢解析。

## 3. 分层改动

类型层在共享接口模型中新增折叠请求与响应形状，字段全部可选或带默认值，老客户端不受影响。

编排层新增折叠工具模块，与诊断工具并列注册。内部只做三件事：解析语言、调用解析协调器得到实体、调用折叠模块得到骨架文本与估算。实体为空、解析失败、语言未知统一映射为截断降级，不向上传播错误。

服务端新增折叠处理器与路由，路径与现有工具族保持一致风格。处理器从共享状态借用解析协调器，无需新增状态字段。并发模型沿用诊断工具的互斥借用方式，首版不做额外池化。

模型网关层新增一个同名工具，参数不含项目标识，与现有需项目标识的工具形成明确区分。该工具只做透传与序列化，不做业务判断。

## 4. 落地顺序

先加共享接口模型与编排层工具，辅以单测覆盖骨架抽取、未知语言降级、超限降级、空输入降级。

再加服务端处理器与路由，辅以端到端用例覆盖文本输入到折叠输出的往返，以及服务端无索引启动时的可用性。

最后加模型网关工具与文档更新。批量折叠首版不做，调用方在压缩窗口内逐条折叠已满足需求，批量可按需后续扩展。

## 5. 测试与验收

单测覆盖各常用语言的骨架提取、降级路径、 token 估算存在性。集成测试覆盖服务端无项目上下文时的文本折叠往返。回归要求现有压缩、符号、诊断端点行为不变，全量测试不改即过。

验收以独立设计中的行为断言为准，另加两条本侧断言：未知语言返回成功且标记结构未知，超限输入返回成功且文本长度受全局上限约束。

## 6. 风险与取舍

大文本并发解析可能抬高尾延迟，首版以全局上限与调用方超时兜底，不做解析池化，后续按指标再定。

两侧 token 估算实现不同，折叠前后对比以服务端返回值为准，调用方预算校验仍以自身估算为准，两者差异只用于观测不用于阻断，需在联调时确认量级一致。

语言识别口径两侧可能不一致，服务端以实际使用语言回显为准，调用方透传的语言只作为提示，不作为断言条件。
