# 续写碎片身份复述与文本降噪方案

## 1. 背景

再生后的 gin 基准确认：向量侧模糊查询中，自然语言文本与原文各赢一部分查询，谁也代替不了谁。逐查询明细把跌点钉死在四类查询上：路由请求分发、树查路径、路由树找处理器、分发语义，目标分别落在请求分发主干与路由树查找两个大方法的续写碎片里。这些碎片的共同特征是头部匿名：只有结构名加碎片编号，不带方法名、参数与返回类型。

与此同时自然语言独赢三类查询：短方法签名句桥接了命名鸿沟，纯原文反而把短函数埋没。因此方向是混合文本，而不是倒向任一极端。

## 2. 目标

续写碎片复述其自身覆盖实体的属主身份，删除无检索价值的碎片元数据，压缩重复的成员名录前缀。验收以 gin 的续写碎片头部、字段名录行为准，并以现有单测与导出结果对照确认。

## 3. 非目标

不改动切分位置与合并策略，不改动混合召回权重与测试污染过滤，不做跨成员转换合并（循环变量跨行折叠依赖跨转换归因能力，列为后续工作）。

## 4. 改动

改动一：删除嵌入文本中的碎片计数与续写标记。碎片编号只说明切分历史，不说明内容，嵌入与词频两路都不需要。结构性元数据字段保留在块元数据中，仅供合并与诊断使用，不进入检索文本。

改动二：续写段按其自身内容实体复述身份。每个续写段的前缀由该段实际覆盖的实体决定，形式为类型加属主限定名；若该段首行已含该限定名则跳过，避免切分恰好落在实体边界时出现重复。无可归因实体时回退到组级身份行。

改动三：块级续写头去掉续写标记但保留身份。块头中的属主成员名是有效检索信号，只删除标记词本身。

改动四：裸字段的属主前缀去重。当字段成员文本已经是属主限定形式时，不再叠加字段归属前缀，因为属主信息已经存在，叠加只产生重复。方法与构造器的限定前缀保留，其调用形态本身是有效的逐字签名锚点。

## 5. 保留不动

尾部碎片中的原文代码行保持原样，分支条件、关键调用与错误码已经是逐字形态，这是原文独赢查询的来源。文档注释保持逐字保留，注释是源码中唯一的自然语言判别信号。短函数走摘要加原文体的短路行为不变，这是自然语言独赢查询的来源。

## 6. 验证

单测覆盖续写段身份前缀的生成与跳过逻辑、裸字段前缀去重逻辑。运行导出示例后对照检查：请求分发主干的尾部碎片头部是否带完整方法身份，路由树查找方法的各续写碎片头部是否带方法身份，字段名录行是否不再双重冠名。最后执行格式化、单测与静态检查。
