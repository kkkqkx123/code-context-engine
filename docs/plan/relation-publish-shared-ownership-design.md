# 全量发布共享所有权设计（任务二，可选改进）

本文是关系终结线性分析中任务二的落地设计，属可选后续项。仅在任务一落地后收益仍不满足时启动；若当前尾段成本可接受，则维持现状，不启动本设计。

预期收益为每十万实体再省约四百九十毫秒，即发布侧的一次全量深拷贝。复杂度类不变：规范快照转换、元数据库批量写、衍生查询结构的逐发布构建仍是线性的，本设计只消除映射克隆这一常数项。

## 现状（任务一落地后）

全量协调器常驻一个构建器，每轮原地清空后重放假脱机，发布时深拷贝一次，导出增强共享发布产物。运行期、基线缓存、热更新导出刷新均为只读消费，不拥有构建器。

复用加原地清空模型另有一处脆弱：清空覆盖十余张映射与计数器，唯独未覆盖名称倒排。复用轮次下名称查询可能命中已不存在实体的陈旧标识。本设计以消灭复用顺带消除该类别，无需为旧模型单独修补清空语义。

## 核心决策

每轮新建构建器替代原地清空复用，发布由深拷贝改共享。构建器在发布时移交所有权，退役后永不再被触碰，协调器不保留旧图引用。共享的安全完全建立在这条移交契约上，而非调用方自律。

## 分模块设计

终结模块当轮构造构建器。现有装配逻辑抽取为构造方法，配置、插件注册、度量、构建系统扫描接线全部复用，只是作用对象从常驻成员变为当轮局部变量。假脱机回放、校验文件注入、治理边派生、规范快照生成都写当轮。发布取当轮引用，发布成功与失败都丢弃当轮，不再调用清空。断点恢复的复水写入同样落在当轮内，与回放是同一轮次，不跨轮。

发布接口签名不变，内部实现由深拷贝改共享。深拷贝存在的原因是构建器长寿且会被清空，移交模型下该前提消失。发布失败路径同样丢弃当轮，失败快照随之释放，不存在半共享残留。差异发布与压实路径已经是共享语义，不在本设计范围内。

运行期不需要改动。它继续接收不可变的基底快照，只是该快照的映射来源从深拷贝变为退役构建器。现有发布串行锁与非单调 epoch 拒绝逻辑保留，覆盖共享模型的并发发布。

基线缓存不需要改动。全量后活跃 epoch 前进，下一次热更新经基线读不到对应 epoch，自然走存储冷加载，这正是现状的失效机制，不新增失效钩子。

导出增强不需要改动。任务一已使其持有发布产物，本任务下同一产物的来源由深拷贝变为共享，接口与查询语义都不变。

附属调用方迁移必须与本设计同轮完成，否则共享会被旁路写入破坏。单文件增量操作与存储删除处理器中的构建器直写改走热更新协调器增量路径，禁止再直写构建器；构建器的可变访问子移除，只读访问子改为返回已发布快照或直接移除。维护重发布不再从构建器取图，改走存储或运行时重载；这一点最关键，因为全量后构建器为空或不存在，沿用旧路径会把空图当成完整候选发布。查询与调试读点、回归测试中对构建器内容的断言，迁移到快照只读查询面。

## 正确性要点

移交必须单次消费：当轮构建器只被发布消费一次，消费后协调器不再持有引用，任何后续全量使用全新构建器。旁路写入全部移除后，不存在第二个写者，共享映射事实上不可变。

峰值内存不增加。现状峰值为构建器图加发布深拷贝两份；新模型峰值为退役图（由快照持有）加新轮构建两份，同量级。

实体标识与指纹不受影响。规范快照与指纹走稳定符号键，与运行时标识无关；计数器每轮归零与现状清空语义一致；名称映射每轮新鲜构建，顺带修复陈旧命中。

剩余线性成本如实保留：共享消除的是映射克隆，衍生查询结构仍逐发布构建一次；规范快照转换与批量写入仍线性。这些是该语义的内禀成本，不在本设计目标内。

## 验证

基准侧确认发布侧一次全量深拷贝消失，全量重建与物料化基准对比无系统性回归。回归侧覆盖连续两轮全量后导出增强不断且内容更新、运行期查询一致、全量后热更新仍能冷加载、维护重发布不再读取空构建器。并发侧覆盖删除与增量请求在全量进行时改走增量路径，无旁路写入。

## 启动条件与非目标

任务一满足性能要求则不启动本设计。若全量入口出现高频自动触发，或暂存提交被证实为小而频繁模式，优先重估入口层决策，而非提前启动本设计。本设计不触碰增量化终结，不做兼容层，不保留旧路径。
