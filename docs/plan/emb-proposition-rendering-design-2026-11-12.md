# emb 命题级渲染：细化设计与修改方案（2026-11-12）

本档是需求文档 `emb-proposition-rendering-2026-11-12.md` 的细化实现方案。
只做一件事：把向量路已抽取的控制流与行为事实，从无修饰的原始代码转写为
受控命题句。其余路径与预算一律不动。

## 1. 现状分析

向量文本与词项文本在 `IndexTextEnricher::enrich_conversion` 处分叉。
两路共享同一份模板正文（身份行、文档、调用行、文件角色行），分叉点之后：

- 词项路取全部事实片段并回填无事实间隙与尾部，还原完整函数体，最大化词面覆盖。
- 向量路只取事实片段，跳过间隙与尾部回填；无事实实体回退到完整函数体。
  片段是源码原样重排，做法细节与语法符号一并进入平均池化。

分支锚点（`branches on:`）已通过首行后插入进入两路正文头部，是目前唯一的
命题形态信号。调用行已封顶八个目标并去噪。文件角色行（`In file ...`）已就位。
按实体切块已保证向量侧兄弟稀释不再恶化。剩余差距是意图真空：
目标块谈做法，查询问意图，两者在向量空间中无法对齐。

事实库存按语言以不同捕获产出，但归一到同一组稳定的事实类型：
绑定、引用、对象、数组、查询、陈述、错误效应、位移操作，
以及分支、匹配、循环、返回、终止、尝试等控制流类型。
命题渲染消费归一后的事实类型，不直接依赖语言特有捕获，与语言解耦。

## 2. 设计决策

### D1 替代而非并存，溢出为例外

存在任一命题时，该实体向量路不再保留任何无修饰原始代码尾巴。
并存会把刚提纯的分母重新拉长。词项路保持逐字节不变，这是硬护栏。

例外：映射事实超出八句预算的长实体，
未被命题覆盖的剩余事实仍以原始代码保留在尾部。
八句讲不完一个大函数，丢尾部等于删深部 token，
此前已证实这是确定性损伤。短实体保持纯命题，长实体为命题头加代码尾。

### D2 命题位置：首行之后，锚点之下

命题块插入身份行之后。分支锚点保持在命题块之前，
顺序为身份行、锚点、命题、正文余部。命题早出现才能在截断与分块中存活，
也符合人工审查先读断言后读细节的顺序。

### D3 类型到句式的封闭映射

动词只取封闭集合，实质词全部原样取自事实文本、签名或元数据：

- 分支给条件命题，匹配给分发命题，锚点保留，两者互补不重复。
- 错误效应给报告错误命题，但要求文本自带错误词形，
  否则跳过（例如把非受控块标为错误是不诚实的）。
- 数据绑定按右值形态区分：调用右值得出自调用命题，非调用右值得出自标识符命题。
- 陈述若是调用形态，给调用命题；非调用形态不渲染。
- 返回给返回命题，裸返回跳过（无信息量）。
- 循环给遍历命题，循环头为空时跳过。
- 数据查询给查询命题。
- 对象与数组字面量给构造命题，宏体给定义命题。

位移操作、纯控制流终止、引用类子表达式不渲染，
按需求文档允许的降权处理，即从向量路移除。
引用类事实多为外层绑定或陈述的子区间，外层已有命题覆盖，
单独成句只会挤占八句预算。

### D4 内层事实不再跳过

词项路为去重会跳过控制流区间内部的行为事实，
因为外层原始代码已包含内层文本。命题路外层只剩条件句，
内层信号必须逐条独立成句，否则分支体内的调用与返回会整体丢失。
因此命题收集不做区间包含跳过，只做句子级去重。
这是与词项路有意的、记名的口径分叉。

### D5 封顶、排序、去重与溢出尾部

每实体命题头最多八句，与调用行封顶和锚点预算同量级。
按源码字节序排列，整句精确去重，超限截断尾部。
字节序保证同一实体的命题顺序稳定可复现。

去重后仍未进入头部的映射事实，其原始片段按字节序合并去重后
保留在向量正文尾部（只含事实片段，不回填无事实间隙）。
因此短实体为纯命题，长实体为命题头加代码尾，词项路不受任何影响。

### D6 片段过长只取首行

单个事实可能覆盖整个分支体，命题只取首行并截断到合理长度。
条件与分发类命题只取关键字到左花括号之间的判别部分。
截断只做前缀保留，不改写词序与大小写，保证可溯源。

### D7 无事实实体不受影响

无任何事实的实体保持现有回退（完整函数体），命题块为空。
存在事实但全部不可映射的实体同样走现有回退，
避免把仅有噪声的实体洗成空壳。

### D8 模板噪声行不进入命题

Go 错误守卫等模板样板不生成条件命题，
否则每个函数都会多出一句相同的守卫句，形成新的公共成分。
命题只陈述该实体特有的判别信息。

### D9 借命题默认关闭

无文档实体的父容器文档首句出借，本轮不实现。
理由是跨实体信息注入需要独立的回归评估，
与本轮单实体、可溯源的范围不符。记为后续事项。

### D10 不做事项

调用边单独命题化、用法收集、导入收集、签名命题化一律不做。
调用信号已由绑定与陈述的调用形态命题覆盖，
签名保持代码形态信息损失最小。

## 3. 修改点

全部改动收敛在转换原模块的向量路富化阶段，共两处文件动作：

- 新增命题渲染子模块，归 `index_enrichment` 下，
  与分支锚点、调用裁剪、语法剥离、源码重提并列。
  内含预算常量、类型到句式的渲染函数、标识符提取与审计测试。
- 修改富化器主流程：计算命题并插入向量正文首行之后；
  存在命题且未溢出时跳过向量路原始代码尾巴的追加；
  溢出时追加未覆盖事实的原始尾部；无命题时走原有回退；
  词项路代码逐行不变。

不碰切块器、词项清洗、评测与对齐口径、任何既有预算数值。

## 4. 细化修改步骤

1. 新增子模块并在富化器模块树中注册，与现有子模块同级。
2. 实现命题收集：遍历该实体的控制流与行为事实，
   按 D3 映射逐条渲染，跳过 D3 与 D8 规定的无意义形态，
   跳过体部之前的事实与文档串陈述，按字节序排序、整句去重、
   截断到八句；记录未被头部覆盖的映射事实作溢出尾部。
3. 实现对象截断：首行优先，超长前缀保留，保留原始大小写与符号。
4. 修改富化流程：先算命题并插入向量正文首行之后，
   再走现有锚点插入；存在命题且未溢出则向量路不再追加原始代码尾巴；
   溢出则追加未覆盖事实的原始尾部；无命题则保持现有向量路逻辑不变；
   词项路逻辑文本不动。
5. 新增单测：映射形状覆盖、封顶与去重、溢出尾部、
   体前事实与文档串跳过、裸返回与样板守卫跳过、
   错误词形守卫、命题实质词可溯源（分词后实质词必须出自输入事实文本）。
6. 全量复核：格式整理、静态检查、富化器现有单测通过。

## 5. 验证计划

形态先行，数值随后。

- 导出四个语言，人工核对差距目标块出现对应命题句，
  命题句实质词可在源码中逐字找到，词项全项目逐字节一致，
  向量路无事实目标保持完整体。
- 数值验证需要重嵌五项目并离线评测。
  当前环境无可用的嵌入服务密钥，重嵌步骤阻塞；
  阻塞期间以形态审查、词项护栏与单测为通过标准，
  数值对比留待具备密钥的环境按固定向量或多次重生取均值的口径执行，
  落抖动带记为未证实。
- 回归门槛沿用需求文档：三项目无严重退化且词项行零变化。

## 6. 执行记录

实现已落地，形态与数值审查结论如下。

- 代码改动：新增命题渲染子模块，富化器向量路按事实预算分三路：
  无命题走原有回退（无事实实体恢复完整体）；
  命题未溢出去原始代码尾巴，命题块置于身份行之后、分支锚点之下；
  溢出时长实体保留未覆盖事实的原始尾部。词项路逐行未动；
  借命题、用法收集、导入收集、签名命题化均未做。
- 形态审查：四个语言导出成功。差距目标块均出现对应命题句：
  请求体绑定目标出现派生命题与调用命题；模板渲染与格式化输出目标出现调用命题；
  分发目标出现分发命题与条件命题；会话头解析目标出现绑定与调用命题；
  读流搜索目标出现读取器与搜索策略命题。命题实质词均可在源码中找到。
  无事实实体保持完整体。词项全项目逐字节一致（761 文件），
  离线评测词项行零翻转（四项目各 810 行）。
- 基线备份：四个项目的离线评测输出与三基线向量数据已覆盖写入 `ref/backup`，
  与改动前最新状态一致，可作回归对照。改动后数据只留在工作区，不进备份。
- 数值验证：执行数据重生四项目与离线评测。
  结论按项目取三档，如下所列。重嵌本身带抖动带，
  单轮结论以多 K 与双口径一致性为准，落带记为未证实。
- media_server：证实。分发查询由三十至五十位进入前十（双口径，两轮一致），
  会话头解析由全零进入五十位内（双口径，两轮一致，深度随重嵌浮动），
  文件头编码进入前十（两轮一致）。参数集解析由全零进入五十位，记为边际增益。
  包序列化在十位边界来回，不计。反向移动均为部分或 top5 边界性质。
- ripgrep：未证实。读流搜索单路仍零，分组在放宽 K 下保持；
  长尾有增益，个别分组 top10 边界下滑但放宽 K 即恢复。无确定性回归。
- gin：未证实，且有局部单视图回归。三差距纹丝不动；
  同一 mega 函数上的同义改写查询在单视图多 K 下滑（两轮重生一致），
  分组口径完好。属命题头挤占深部信号的已知代价，列为后续事项，不回退。
- flask：保持。top20 及以上全同，分组 top5 持平；
  单路 top5/10 在一个查询上边界下滑（放宽即恢复，分组完好）。
- 回归门槛：三项目分组口径无严重退化，词项行零变化，不回退。
