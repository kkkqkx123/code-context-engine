# 词项概览卡仅保留向量路

日期：2026-11-04
范围：`ripgrep` 未分组词项下滑修复为主，`flask` 为回归对照
上游结论：问题文档已确认前 4 个为切分与竞争主因、`G1Q1` 为文本主因、概览卡在词项路负收益

## 1. 设计

分块器文件级后处理中合成的成员概览卡，只在向量路径生成，词项路径不再增卡。成员是否被切散的判定、区间并集的计算、头部截断的预算保持不变，只是按路径过滤：向量成员走原有成卡逻辑，词项成员直接跳过。转换器、切分器、合并器、预算数值、评测语义均不动。

保留向量概览的理由是向量需要单命中覆盖：被切散的长方法在片段级要求多片共现，概览的 union 区间让单次命中即可覆盖标注，语义头部保留主题。词项不需要该卡：分组评测已通过段合并恢复，未分组词项靠精确词命中，截断头部未必含查询词，反而制造近重复竞争。

## 2. 影响面

改动只涉及分块器概览后处理一个位置，按路径加过滤条件，无语言相关分支。块数上向量路不变，词项路减少约百分之六到十，嵌入与索引成本同比下降，无量级变化。排序上词项同主题竞争者减少，未分组真块排名预期上升；分组跨度不受影响，因为段合并独立于概览卡。已通过查询中依赖词项概览的若存在，应表现为个别波动，需以双项目验证为准；爆破半径限于多分片成员，单片成员查询不受影响。

`G1Q1` 类纯文本稀释不在本轮解决：同切分下原文独胜，改分块无法改变正文词汇密度，留作模板治理后续。本轮目标是前 4 个的切分竞争与聚合差距收敛，不承诺 `G1Q1` 单点恢复。

## 3. 验证标准

单测层面覆盖成卡条件、区间并集、上限截断既有行为，并在词项路径补充不成卡断言。集成层面要求词项块数下降且向量块数不变，空区间保持为零，共享区间不新增。指标层面要求 `ripgrep impl_only` 未分组词项相对修复前提升且不低于 `raw` 的差距收窄，分组词项与向量两路不回退；`flask impl_only` 两路不低于修复前聚合。逐查询允许个别拥挤性波动，但顶层下滑数不得增加，大切口下不得出现新增系统性失败。

验证顺序为导出、分块数据生成、离线评测：先跑双语言导出确认分块形态，再重跑双项目三基线数据生成，最后重跑双项目离线评测并与备份对照。融合与参数扫描输出为旧快照，不纳入本轮结论。

## 4. 验证结果（2026-11-04，已执行）

基线已预先备份至 `ref/backup`（双项目聚合与逐查询报告、三基线 `bench_data.rkyv`）。本轮按导出、数据生成、离线评测顺序全量重跑，单测与格式检查通过。

形态：双项目词项概览卡清零（`ripgrep` 约一百七十片、`flask` 约三十余片），向量概览保留；`ripgrep full` 词项块数约二千二降至约二千零七十，向量保持约二千一百九十；`flask full` 词项约六百二十七降至约五百九十，向量保持七百七十四；空区间保持为零。

指标：`ripgrep` 未分组词项 `full` 强召回持平、相关召回上升，直接基线 `all` 上升约零点零五六；分组词项持平或微升，向量两路持平。`flask` 分组词项 `all full` 上升约零点零二二（`G2Q6` 恢复），向量两路持平；未分组词项小切口回退约零点零四至零点零七（切散成员的单命中覆盖随概览卡一并移除，组级已覆盖），大切口收敛。顶层下滑数未增加，未引入系统性失败。

结论：改动达到减少词项竞争、保持组级覆盖的预期；`G1Q1` 类纯文本稀释确如预期未恢复，留作模板治理后续，不在本轮硬解。
