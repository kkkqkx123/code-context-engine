# 索引增强拆分与调用裁剪全语言覆盖设计方案

## 1. 背景与目标

索引增强模块负责索引阶段的向量文本增强：分支主题锚点、行为体裁剪、调用行裁剪、术语表计算。原实现集中在单个文件中，承担编排、语言名单、文本手术、源码抽取四类职责，且调用裁剪的样板名单只覆盖少数语言。

本方案完成两件事：调用裁剪按全部树解析语言分发；把索引增强拆成高内聚子模块。另四个超千行文件一并给出拆分边界，分阶段落地。

## 2. 调用裁剪的全语言覆盖

### 2.1 问题

首轮实现只手写了五个语言分组的样板表。仓库实际支持的树解析语言远多于此，手写表注定长期不全，且与已有标准库识别能力重复。

### 2.2 决策

裁剪判断保持三层结构，逐层收窄：

* 通用复述判断与语言无关：原文逐字出现，或限定头尾同时出现在词表中，直接删除。
* 语言分发以共享标准库识别器为主：识别器已覆盖全部十五种树解析语言的限定路径与内建函数，调用裁剪直接复用它，不再自建第二份语言知识。
* 手写表只补识别器的盲区：按名无法判定的裸方法，如各语言无接收者类型信息时的高频低信号方法。每个语言保留最小集合，有识别器全覆盖的语言留空表并注明原因。

未知语言与插件语言回落到保守策略：只执行通用复述判断与通用断言类名单，不猜测语言专有样板。

### 2.3 取舍

标准库调用整体视为低主题信号，与分组器把标准库调用排除在业务关系外的口径一致。裸方法的激进删除只保留给高置信名单，避免把唯一信号删空。

## 3. 索引增强的拆分

已落地：原单文件拆为一个目录，编排器保留，其余下沉。

* 编排器：持有清洗器，决定锚点、体裁剪、调用裁剪、术语表的执行顺序，并承担体裁剪的合并策略。
* 调用裁剪单元：样板表、语言分发、冗余判断、行裁剪。语言扩展只动此处。
* 主题锚点单元：分支判别与行插入，与调用逻辑解耦。
* 源码抽取单元：字节区间抽取、去缩进、实体定位、体裁剪。最稳定，可被复用。
* 语法去噪单元：与语言噪声画像同构，长期评估并入噪声模块的可行性。

单测随模块迁移，行为不变，全量通过。

## 4. 其余四个大文件的拆分边界

### 4.1 分组转换器

现状按执行阶段自然分块：批量插件流水线、单组转换、层级描述增强的四个子阶段、成员过滤与插件回退。拆分时按阶段设子模块，编排器只保留入口与阶段装配。注意其依赖的分组类型定义不在本文件，拆分不移动类型归属。

### 4.2 头块

现状由三类内容组成：分组切分编排、按路径处理与合并、段预算强制执行的大量用例。拆分方向是编排与预算执行分离，用例随各自单元迁移。预算执行是独立策略，适合单独成模块。

### 4.3 切分器

现状由边界枚举、预算计算、范围切分、段合并四类逻辑组成。拆分方向是边界策略、预算、合并各自独立，范围切分保留为编排。合并阈值与预算上限的耦合点在拆分时需要显式接口，避免隐式共享。

### 4.4 块构建器

现状由身份命名、标题关键词装配、源码窗口、重叠与延续四类逻辑组成。拆分方向是身份与标题装配独立为命名单元，源码窗口与重叠独立为定位单元，构建器保留装配顺序。主题行前缀等微型规则随命名单元迁移。

## 5. 落地顺序与验证

已完成索引增强拆分与全语言裁剪。后续按分组转换器、块构建器、切分器、头块的顺序逐个拆分，每次只拆一个文件，每次保持单测全绿与静态检查干净。禁止一次合并不相关的多文件拆分。
