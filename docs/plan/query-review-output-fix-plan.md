# query_review 输出问题修复方案

本文是对 `crates/app/cce-e2e-tests/docs/issue/query-review-output-problems.md` 全部 10 项的根因确认与修改计划。根因均已定位到具体文件与行为，本方案只写改什么、为什么、按什么顺序，不贴完整代码。

## 1. 根因确认结论

富化缺失是根因。`QueryWorkflowTest::index` 装配了内存 SQLite（仅作 checkpoint 用）、BM25 客户端与 embedder，但从未把该 SQLite 以元存储身份交给索引编排器。索引侧所有 SQLite 持久化（文件、实体、chunk 记录、实体映射）在元存储缺席时静默跳过，而查询侧富化从同一个空库查 chunk 记录，必然全 miss。表现为全部命中空正文、0 行号、空 kind，并连锁导致标注 100% 失败。生产路径已有回归测试覆盖此语义，harness 是另一条没接线的路径。

关系数为 0 是独立问题。符号按批喂入与配置默认值经核对均无异常（与离线结构化路径的 builder 配置一致），断点需一次带日志运行定位（见 D1）。发布器缺失是另一处 harness 接线缺口：每次运行都会向错误表写入常驻错误。

去重不一致是真实行为差异：聚合查询在合并后按对齐键去重，单查管线中没有任何等价步骤（富化内的去重只处理引用态），BM25-only 下同实体子 chunk 全部保留。

其余为渲染层与方法学缺口，无需动生产逻辑（缓存命中标记除外，见 F）。

## 2. 修改项（按依赖顺序）

### A. harness 索引接线（对应问题 1，最高优）

位置：`crates/app/cce-e2e-tests/src/query_test.rs` 的 `index` 方法。

- 建库后先用项目仓储的 ensure 语义注册项目行，ID 取当前 project_id，根路径取 fixture 真实根目录。该行同时满足外键写入与查询时源码文件定位两个需求，缺一不可。
- 把同一 SQLite 以元存储身份装配给索引编排器（编排器侧已提供对应装配入口，照抄生产接线）。
- 把测试专用关系发布器以共享同一内存库的方式装配给索引编排器，消除每次运行的常驻发布错误。注意发布器内部也是 ensure 语义，先写入真实根路径的行就不会被占位值覆盖。

影响面：所有 `QueryWorkflowTest` 消费者的查询结果都会变富（正文、行号、kind 被填实），实体映射走 epoch 作用域分支。超预算 chunk 可能降级扣分从而轻微改变排序，验证阶段以基准指标零回归为通过标准，不通过则回滚本项并重新评估。

### B. 富化缺失时诚实降级（对应问题 2）

位置：`crates/app/cce-orchestrator/src/query/retrieval/post_processing/entity_mapper.rs` 的物化函数，及 `crates/app/cce-orchestrator/src/query/types/content_reference.rs` 的降级原因枚举。

- 查不到 chunk 记录且正文为空时，不再保留召回阶段预设的 Full 状态，改为引用态并按既有规则扣分，与文件缺失、超预算两条路径一致。
- 需新增一个降级原因变体表达记录缺失并配一句排查文案，同步更新该枚举的全部穷举匹配（约六处）。否决复用文件缺失原因的备选方案，语义错误会误导排查。

### C. 单查对齐键去重（对应问题 5）

位置：`crates/app/cce-orchestrator/src/query/searcher/post_processing.rs` 的后处理入口顶部。

- 复用融合模块已有的对齐键推导函数，保留最高分，丢弃同键其余项，与聚合查询的合并去重落在同一键空间。
- 放在富化之后（键质量最好，SQLite 可补齐索引缺失的实体归属）、重排之前（避免把预算花在注定被丢弃的重复项上）。混合路径经融合已对齐，该操作对其幂等。

### D. 关系数为 0 的诊断与修复（对应问题 4）

分两步，先诊断后修，不预设结论。

- D1（不改代码）：以 once_cell fixture 做一次带日志的索引运行，依次确认批处理错误表、spool 回放条目数、注册后实体数、解析后关系数四处既有日志，定位断点在馈送、回放还是解析环节。若回放与解析都正常而计数仍为 0，则用裸 builder 直喂同一批解析产物做对照，区分编排器侧与图侧。
- D2 按 D1 结论修。若断点在回放物或配置，修编排器侧；若在解析环节且与 fixture 无构建清单有关，把清单扫描深度默认值与无清单场景作为修复变量之一。
- D1 需要 manifest 展示索引 outcome 与错误摘要，见 F 项先行补齐渲染。

### E. 标注传入真实扩展单元（对应问题 3 的结构性一半）

位置：仅 `crates/app/cce-e2e-tests/src/query_review.rs`，不动生产标注器。

- 每个命中取首个实体 ID，经关系搜索查调用与被调用实体（各自限量），从 fixture 源码读取片段拼出扩展单元，传入标注调用。渲染已有的扩展计数栏位将首次出现真实非零值。
- 前置依赖 A（行号正文）与 D（关系数据），二者未就绪前本项无法验收。

### F. 渲染补齐（对应问题 7，部分含问题 6 所需）

位置：仅 `crates/app/cce-e2e-tests/src/query_review.rs`，另有一个可选的小生产类型改动。

- 文件头改用请求来源与执行策略两套标签分别渲染（两者本就来自不同类型，之前标签相近造成混淆）；融合权重直接取查询配置中的融合节（执行策略的权重即由此派生，无需动生产）；意图栏渲染配置与请求覆写。
- Top-K 表增加 boost 原因列；manifest 插值项目名；manifest 增加 outcome、错误摘要、后端可用性边界声明（D1 诊断与问题 6 的解读边界都需要它）。
- 缓存命中标记需要给查询结果类型加一个布尔字段并更新四处构造点（含测试与基准各一处），协调器在命中缓存分支置位。改动小且为加法字段，予以采纳。

### G. 注释英文化（对应问题 8）

`query_review.rs` 三处中文词改为英文，`relation_review.rs` 同步排查一遍。纯文本改动。

### H. 输出重跑与验收（对应问题 6、9）

- Qdrant 可用时输出仍落默认目录（即 hybrid 默认）；不可用时改用已支持的目录后缀机制落单路目录，manifest 中的边界声明同步生效。跨语言题在单路配置下不具代表性的结论写入 manifest 而不是丢题。
- D 解决后运行两个 relation_review 示例，验收种子清单、Mermaid 图与机器可读快照；设计要求的逐种子 JSON 若缺失一并补齐。

### I. 文档（对应问题 10）

`outputs_guide.md` 补一节：目录树、index 入口、manifest 字段含义、单路环境的解读注意事项。

## 3. 验证计划（合并为四轮）

第一轮覆盖 B、C 与结果类型改动：`cargo test -p cce-orchestrator` 加 `cargo clippy` 同包。第二轮覆盖 A 对 harness 消费者的影响：`cargo test -p cce-e2e-tests`，重点看基准指标类断言零回归。第三轮重跑四个 review 示例，按问题清单逐项复核（正文非空、行号有效、关系数、键唯一、标注成功）。第四轮收尾格式与全量质检。每轮失败即停，不进入下一轮。
