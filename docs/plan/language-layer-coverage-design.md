# 语言分层覆盖缺口分析与补充设计方案

## 1. 审计方法与结论

逐个检查全部语言分发点，区分三种情况：有意为之的降级（需文档锁定）、真正的缺口（需补代码）、历史遗留的不一致（需对齐）。测试套件的覆盖矩阵是好榜样：每个未覆盖语言都写明了降级理由。

## 2. 确认的缺口

### 2.1 PHP 修饰符未提取

查询已捕获方法可见性、静态、抽象、终结标记，但提取分发没有 PHP 分支，修饰符被清空。可见性检测退化为默认公开，转换文本丢失静态与抽象信息。补充专用提取器并接入分发。

### 2.2 标准库分类缺分支

调用分类只给六个语言接了具体分类器，其余标准库调用统一归入未分类桶。各语言检测器都已具备分类能力，补充分支是机械工作，一并让复用插件语言走有效语言解析。

### 2.3 JSX 与 TSX 被排除在方法模式之外

取值器与设值器的参数计数把 JS 与 TS 列出，却漏了同家族的 JSX 与 TSX，三者语法一致。补充分支并断言家族一致性。

## 3. 有意为之，测试锁定即可

* 自引用参数只有四个语言具备显式写法，其余返回否定是正确语义，加期望表锁定。
* 测试套件对部分语言只做路径规则，已有文档说明降级理由，不动。
* 模板语言的标准库与裁剪回落已由上一阶段的同步测试锁定，不动。

## 4. 暂不处理

* 相对导入解析只覆盖五个语言，其余返回空。它影响依赖边精度，但各语言导入语义差异大，需要逐语言设计而非批量补充，列为后续工作。
* C++ 访问段标签等细粒度可见性信号，查询层未捕获，超出本次范围。

## 5. 验证

每个补充带单测；全量单测、裁剪与格式检查干净。
