# 命题噪声审计、覆盖面盘点与可维护性改进设计（2026-11-12）

本文档回答三个问题：当前命题引入了哪些噪声、哪些是预存问题、
命题机制实际覆盖了什么；并给出改进设计。只谈向量路，
词项路逐字节一致仍是硬护栏。

## 1. 噪声审计：引入的与预存的

### 1.1 本轮引入的噪声（按严重度）

- 畸形条件句。无大括号守卫的回退把函数体粘进条件，
  如 `checks (period->event_streams) free(period->event_streams).`。
  根因是尾部切割只认识 return、break、continue，
  而 C 允许 `if (x) free(y);` 这类裸调用体。
- C 错误码样板句。`returns -ENOMEM.` 在单个文件中出现二十七次，
  `returns 0.`、`checks 0 != r.` 同理跨实体同步。
  Go 有错误守卫而 C 没有对应守卫，失败语义被逐实体复述成公共成分。
- 空虚绑定句。`derived from 0`、`derived from 1`、`derived from NULL`、
  `derived from "字面量"`、纯类型转换右值。计数器初始化之类的句子
  只占预算不给信号。
- with 误标。`reports error via with open(...) as f:.`
  把资源管理说成错误报告，属事实性错误而非一般噪声。
  根因是错误词形表把行首的 with 一并收录。
- 空虚条件句。`checks p.`、`checks !ptr1.`、`checks mpd && *mpd.`
  这类单标识符真值检查几乎无判别力，且同样挤占八句预算。
- 同一事实多种说法。调用边出现两次（预存的 `calls: X` 加新增的
  `invokes X(...)`）；溢出长实体的绑定出现三次
  （模板变量行加命题加尾部原文）。同义词复述稀释了 distinctive token。
- 重复放大。同一句子跨相邻 chunk 各出现一次
  （分块重叠机制，预存），再叠加跨实体的样板同步，
  高频句的实际曝光是其出现次数的数倍。

### 1.2 预存问题（被本轮确认或放大）

- `In file X.` 逐成员重复。四语言向量 chunk 中占总行数约一成
  （Go 约百分之九，C++ 约百分之十二），高于任何单个命题动词的份额。
  正文缩短后其密度进一步上升，但该行来自更早的文件角色行改动，
  不属本轮引入。
- 模板变量行复述代码。如 `init variable n.` 紧跟原始声明行，
  与命题、尾部叠加后同一绑定最多出现三次。
- 宏与枚举的裸身份清单。一个 chunk 内二十个 `macro X.` 只有名字，
  无行为无文档，属预存的低价值 bulk。
- 分块重叠复述。相邻 chunk 按设计共享 tokens，任何高频句都被动加倍。

### 1.3 量级参照

- dash-parser 单文件：命题 382 行、`In file` 93 行（基线 102 行）、
  调用行 40 行（基线 49 行）。命题是最大增量，`In file` 是最大预存项。
- 四语言命题行占比：Go 约百分之二十二、C++ 约百分之二十一、
  Python 约百分之十九、Rust 仅约百分之六点六。
  Rust 点火率显著偏低，见第 2 节。

## 2. 命题覆盖面盘点

### 2.1 实际点火情况

命题在四语言全面点火，动词分布与语言惯用法一致：
Go 以调用句为主，C++ 以条件句为主且量大，
Rust 以分发句见长，Python 有错误效应句。
因此“覆盖面窄”不是指语言覆盖，而是指类型覆盖的结构性偏斜。

### 2.2 类型与语言矩阵中的沉默格

- 数据引用在全部语言被丢弃。引用标识符实际由绑定句与调用句的对象部携带
  （如 `c.Get(BodyBytesKey)`），独立引用句多为外层片段的子区间，
  丢弃基本无害，但这是假设而非度量，需要一次事实分布度量来坐实。
- 位移操作仅 Rust 有捕获且被丢弃；终止与尝试类控制流全部丢弃。
  纯控制终端无命题价值，属合理沉默。
- 错误效应在 Go、Lua、Bash、C 中根本无捕获，命题不可能点火；
  在 Rust 中捕获的是非受控块与外部模块项，因不含错误词形而永假，
  该映射臂实际 dormant。
- 数据查询仅 C# 有捕获，对象与数组字面量仅 JavaScript 有捕获，
  对应句式在其他语言永不点火。
- 真正的窄口有三处：C 系错误码守卫缺失导致样板句泛滥；
  Rust 以引用为主导致点火率只有其他语言约三分之一，
  其读流类查询的信号恰落在引用密集区；
  with 语句被误标为错误。

## 3. 可维护性分析

当前九百行单文件混合了三层职责：

- 语言模板层：封闭动词、句式、审计词表。
- 代码文本外科层：条件提取、括号配平、赋值切分、守卫判断。
  这些函数隐含语言假设（Go 的 `init; cond` 分号、
  C 的无大括号单语句体、Rust 的 `let mut` 链），
  却没有任何语言参数，扩展新语言只能加分支。
- 预算装配层：排序、去重、封顶、溢出尾部合并、体部卫生。

十七个单测与实现同处一文件。新增一种句式要改映射表与外科函数两处；
新增一个语言守卫要在多个 `matches!` 里各加一笔；
修畸形条件要动被多处调用的共享函数，回归面不可见。
继续堆叠只会重演调用裁剪模块此前的蔓延。
按只按职责拆分的原则，应当拆成四个模块，
扩展新内容时只动其中一个。

## 4. 改进设计

### M1 按职责拆模块

- 词汇模块：封闭动词、句式模板、审计词表与审计测试。
- 文本外科模块：条件、判别式、对象、赋值切分的纯字符串函数，
  加按语言的守卫表。不再出现裸露的语言分支。
- 渲染模块：仅保留类型到句式的决策表，调用前两者。
- 装配模块：排序、去重、封顶、溢出尾部合并、体部卫生。
- 原文件退化为门面重导出。测试随各自模块走，
  跨模块只测渲染决策与装配不变式。

### M2 守卫表数据化

把错误守卫、错误词形、空虚右值等硬编码改成按语言的守卫表。
扩展覆盖等于加表行，不改分支逻辑。
首批表项：Go 错误守卫保持；C 系错误码返回与状态比较守卫；
空虚右值字面量表；with 移出错误映射。

### M3 条件提取改括号配平

C 系从关键字后做括号配平取条件，不再依赖大括号搜索加关键字切割；
Go 保留 `init; cond` 形态。消灭畸形条件句整类。
回退路径只处理实在无括号的退化形态，并加单测锁定。

### M4 错误码返回守卫（先 A/B）

裸字面量返回（错误码、零值、NULL）不渲染，
失败语义由配对的条件句承载。这是在删除既有信号，
必须先走固定向量 A/B，落抖动带则维持现状。

### M5 空虚右值守卫

`derived from NULL`、`derived from 0`、`derived from 1` 不渲染；
有业务含义的字面量（如超时毫秒数）保留。
纯初始化噪声与有意义字面量的界线由表驱动，日后可调。

### M6 with 移出错误映射

with 语句改为沉默，其内层绑定已各自发声。
属事实性修正，无需 A/B，直接做并加回归单测。

### M7 空虚条件守卫（先 A/B）

无运算符、无调用的单标识符条件不渲染，
配对的返回句保留。与 M4 同理，先 A/B 再定夺，
因 C 空检查在分发逻辑中有意义，不可一刀切。

### M8 重复度量进审查

新增 chunk 级公共句份额诊断（与近重复块份额同口径），
任何新句式在合入前必须过这一关。属流程修正，不改文本。

### M9 相邻模板项单独立项

`In file` 逐成员重复、变量行三重陈述、调用行与调用句复述，
归属模板与分块器，不在命题模块内解决。
选项是文件角色行按 chunk 去重、变量行在有同名命题时降级，
但需跨阶段传信号，耦合代价高。本轮只给出度量与选项，
不合入实现。

### 非目标

不动词项路、不动预算数值、不做跨实体信息、不改切块器。
M4 与 M7 这类删除既有信号的改动一律先 A/B，
结论只取证实、未证实、证伪三档。

## 5. 验证计划

- 单测：各守卫正反例、畸形条件消除、with 沉默、审计词表同步。
- 形态：以 dash-parser 类文件复查公共句前十、
  `In file` 占比、命题动词分布；Rust 点火率回升到与其他语言同量级。
- 数值：固定向量 A/B 或两次重嵌取均值；
  门槛为差距翻转保持、单视图不新增确定性回归、词项行零变化。
