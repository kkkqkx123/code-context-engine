# 描述符访问器降级方案

## 背景

`Object.defineProperty` 与 `Object.defineProperties` 的描述符字面量中的函数键（`get`、`set`）声明的是属性访问器，不是可调用方法。若将其提取为方法实体，每个 `this.get(...)` 调用点都会误绑到访问器上。

当前实现采取跳过策略：可证明的直接字面量形态直接丢弃实体，不可证明的间接形态（先赋值给变量再传入）保留为方法实体。前者丢失信息，后者保留误绑风险。测试已把间接形态的保留行为钉死，作为已知局限。

## 目标

把描述符中的函数从跳过改为降级：提取为不可调用的访问器实体，保留参数与函数体；调用解析增加可调用目标过滤，使访问器实体仍可参与体内的向外调用边，但永远不作为调用边的落点。

非目标：不做跨函数的值追踪，不处理多层转发的描述符变量。

## 种类设计

复用属性种类语义冲突：属性是变量型、无参数体预期，分组与摘要按字段处理；访问器携带参数与函数体，需要保留体内的向外调用边。因此新增专用访问器种类，归属代码域。

关键拆分是两个谓词：可作为调用者与可作为调用目标。访问器需要保留前者、去掉后者。函数型判断保持包含访问器（函数形状、有参数体、可作为调用者与可被父子归属），新增可调用目标判断，仅函数、方法、构造、析构、操作符为真。命名语义提取排除访问器，通用 `get` 与 `set` 名称不进入关键词种子。

## 提取器改动

直接形态不再丢弃，改为降级。外层定义的业务属性名与内层访问器函数区分处理：内层键为访问器的函数体保留参数与签名，记录访问器角色与所属属性名元数据。键值对方法捕获横跨整个对象字面量，降级同时把实体跨度收窄到所属键值对，避免同一描述符内的多个访问器共享跨度被去重合并。

间接形态增加一跳后处理：收集描述符位置传入变量的定义调用，定位该变量初始化对象字面量的范围，对范围内键名为访问器键的函数实体同样降级。后处理位于实体收集之后、去重之前，仅依赖跨度包含关系，不做跨函数追踪。多层转发保持原样，宁可多留悬空实体也不删除信息。

## 解析器改动

调用边在确定候选后增加可调用目标门：直接调用、方法调用、链式调用若命中不可调用目标，视为该候选无效，继续尝试下一个候选，而非直接丢弃整条边。只有当全部候选均不可调用时才放弃内部分辨。函数引用通路统一收敛到同一谓词，替代现有的函数型检查。符号快照与类型成员索引不受影响，访问器仍可按名查询，仅不可作为调用落点。

亲和仲裁在过滤之后再选优，避免不可调用实体凭借同文件优先抢占获胜位。构造类型升级判断保持不变，访问器永不触发构造升级。

## 分组与检索影响

访问器拥有独立实体与函数体，分组时作为附属内容跟随宿主属性或就近函数，不单独作为可调用摘要。调用链查询按种类过滤后，访问器节点仅出现在定义关系中，不出现在调用边端点。快照校验接受访问器作为合法实体。

## 测试与迁移

覆盖直接单数形态、复数嵌套形态、间接变量形态，以及调用点不再误绑的回归。新增种类改变序列化形状，需全量重建索引，不做跨版本迁移。
