# 回归检查覆盖补充：缺口分析与用例设计

日期：2026-11-11。针对 e2e 回归检查只覆盖既往修复点、未覆盖各语言主要查询形态与边缘情况的问题，先做缺口盘点与用例设计，再正式实现。所有缺口结论均经真实解析验证，验证手段为临时的全语言探针（解析协调器输出实体与原始关系，另对疑难形态打印查询命中明细与语法树），探针在验证后删除，不进入正式代码。

配套修复说明：本轮在补用例过程中确认了一批新的查询漏抽与提取噪声，均为既往同类问题（查询误伤、捕获选择错误）的延续。文档第五章列出纳入本轮一并修复的清单（小幅查询与提取器改动）与明确延后的清单；回归用例只锁定修复后验证为正确的行为，不把噪声写进断言。

## 1. 现状盘点

现有回归检查共两层。解析器层 `tree_sitter_query_regression` 用十二个内联片段断言实体与原始关系；e2e 层 `tree_sitter_queries` 用八个最小 fixture 工程断言文件级依赖边（个别加同文件调用解析）。两层合计覆盖的语言为 Go、C#、Rust、Ruby、PHP、C、Python、Scala，且每个语言只覆盖当初出问题的两三个形态。

断言口径分三级，后文用 L1、L2、L3 指代。L1 为解析器层原始关系与实体存在性；L2 为 e2e 层文件级依赖目标集合；L3 为 e2e 层解析后调用边归属（调用者到被调用实体的精确指向）。现有用例中只有 C# 的 this 与 base 调用达到 L3，其余均为 L1 或 L2。

## 2. 缺口矩阵

### 2.1 已确认的漏抽（本轮修复，修后纳入回归）

以下每条均经探针复现，根因定位到查询形态或捕获选择规则。

Rust 相关：通配导入（路径加星号）整条丢失，实体存在但零关系边，原因是通配形态的查询只捕获整个通配节点而提取规则没有任何后缀能命中它；嵌套列表导入（两层花括号）零边，原因是查询只建模了一层列表；多段 controversy 不在此列。

Python 相关：普通 from 导入的条目边丢失，只剩模块边，原因是通用捕获选择规则把模块后缀排在名称后缀之前，同一匹配内模块捕获永远胜出，括号多条目形态同理；别名导入的别名丢失且多段模块被拆成逐段多边，原因是别名形态把点分路径的子标识逐个捕获；通配导入零边，原因是通配形态没有锚定模块名且无规则命中；裸相对导入此前已修复，不受影响。

JavaScript 与 TypeScript 相关：再导出形态查询命中但提取丢失，原因是通用依赖规则缺少来源后缀；动态导入零匹配，原因是 import 在语法中为匿名 token 而查询要求具名函数标识；类继承在查询层全部命中，丢失发生在提取层（见下）。

Ruby 相关：带超类的类定义在无方法体时实体缺失，原因是实体形态要求方法体必填且超类建模为裸常量而非超类包装节点；混入调用的依赖边被错误归类为文件包含或继承，原因是混入形态复用了包含类别的捕获名；继承依赖形态过于宽松，类内任意常量都会命中，导致自身误伤。

C# 相关：空条件调用丢失，原因是调用查询未建模条件访问表达式做宿主的形态。

C++ 相关：新建表达式与显式模板实参调用丢失，原因是调用查询没有这两种形态；using 指令的目标为整句文本，原因是依赖形态捕获了整个指令节点而非名称部分。

Scala 相关：新建表达式丢失，原因是调用查询没有实例化表达式形态。

TypeScript 继承边丢失的根因在提取层：继承形态内嵌了实体名称子捕获，通用名称规则按捕获顺序命中了实体捕获而非依赖捕获，导致目标被类名污染。这是一个跨语言的提取器缺陷，同类形态在别处也可能中招，修复放在通用规则层。

### 2.2 已确认的噪声（本轮顺手消除，回归中加否定断言）

C# using 指令内层的限定名片段会产生多余的依赖边，例如静态 using 会多出一段短名边、嵌套 using 与泛型别名同理。根因是限定名片段形态在 using 语句内部同样命中。消除手段为跨度包含去重：同为依赖边且跨度被另一条同类边严格包含时去内层。该去重只作用于依赖类别，不碰调用边。

TypeScript 的单接口与多接口实现形态会重复命中同一实现边。非导入类边此前没有去重，消除手段为同跨度同类型同目标的精确重复去重。该去重是纯噪声消除，不改变任何有效边。

### 2.3 明确延后（只记录，不纳入本轮用例）

以下均为探针中观察到的真实问题，但涉及提取语义取舍或改动面超出查询层，记入后续工作清单，不在本轮断言中锁定：

- Python 别名导入的本地别名是否成边、Ruby 单例调用接收者丢失、PHP 特质引入目标为整句文本、Dart 的取值器与函数名误匹配噪声与延迟导入形态、JavaScript 箭头函数实体的过度匹配、C++ 异文件定义的限定名误判为依赖与类内无体运算符声明缺失、链式调用的中间段残留边、目标类型新建的无信息边、Kotlin 别名导入的区分局限、Java 静态星号近似处理。
- 上述条目在用例中遵循只断言已验证正确的子集、不把噪声写进断言的原则，设计文档中保留清单以便后续认领。

## 3. 用例设计

### 3.1 设计原则

每个语言一个 fixture 工程，片段按形态家族组织，家族内覆盖全部子形态。断言分层：L1 锁定实体存在性与原始关系目标；L2 锁定文件级依赖目标集合，包含肯定断言与针对已消除噪声的否定断言；L3 只用于既往解析归属出过问题的路径。Fixture 保持最小可解析，不引入外部依赖；凡涉及跨文件解析的用例，fixture 内自带被引用的对端文件。

Fixture 选材三条约束（均为本轮实测确认的既有机制，不是临时假设）：第一，内部边按调用者加被调用编号加类型合并身份，外部边才保留完整书写名，因此同一文件内会解析到同一实体的多条同类边在 L2 只呈现为一条，fixture 中避免让被断言的外部全路径与同文件实体同名；第二，内部分辨的边其目标名会被改写为实体的注册名，L2 断言外部全路径时确保工程内无同名实体；第三，标准库过滤在解析后生效，L2 肯定断言不得使用各语言标准库名单中的名字（如常见构建工具、系统模块名），以免把按设计过滤的边误判为漏抽。

既有八个 fixture 做扩展，不新建平行的第二套；新增语言各建一个 fixture。解析器层测试与 e2e 测试一一对应同一组形态，命名保持一致以便对照。

### 3.2 既有 fixture 扩展内容

Go：在已有单行与分组全形态基础上，补结构体与接口嵌入（三种嵌入形态与接口嵌入）、协程与延迟调用、链式调用。L2 锁定嵌入边类型，L1 锁定调用边类型。

C#：在已有五种 using 与 this、base、静态调用基础上，补全局静态 using、命名空间内 using、泛型别名、构造器调用、目标类型新建（无边）、链式与空条件调用、泛型调用、基类构造器初始化。L2 加否定断言锁定内层片段噪声消除；L3 保持 this 与 base 并补构造器调用归属。

Rust：在已有五种 use 形态基础上，补通配、自路径、父路径、 crate 路径、嵌套两层列表、公开重导出、自列表项、外部 crate 声明、深路径。调用补关联函数、方法、自调用、链式、泛型函数与泛型方法、常用宏调用。L3 加多 use 文件的边归属断言，锁定解析器 stale 编号修复（自解析的 use 边落在自身导入实体而非同名函数）。

Ruby：在已有三种加载形态基础上，补混入三种形态、自动加载、gem 声明、带超类定义（含无方法体形态）、单例调用、超调用、安全导航调用、链式调用。继承边类型锁定为继承而非包含。

PHP：在已有单用、分组、别名排除基础上，补函数与常量用、单别名用、类内特质引入（仅锁定存在性，目标精度延后）、新建调用、静态与自与父调用、空安全调用、链式调用。

C：在已有两种包含形态上，补条件包含块、函数指针调用、宏调用。条件包含的宏依赖边一并锁定。

Python：在已有裸相对导入基础上，补普通导入别名、from 条目单与多（括号）形态、from 别名、通配导入、未来导入、条件与类型检查导入、多层相对导入。调用补超调用、自调用、构造器调用、链式、异步调用。L2 锁定条目边出现且多段模块为整路径单边。

Scala：在已有重命名选择器基础上，补通配导入、排除导入、多条目导入、新建表达式、普通方法调用、中缀调用。

### 3.3 新增 fixture 清单

C++：using 指令两种形态、命名空间定义与嵌套、模板类与模板函数、构造与析构定义、自由函数运算符重载存在性、新建调用、模板实参调用、标准库限定调用。L2 锁定 using 目标为名称而非整句。

Java：普通导入、静态导入、星号导入、模块描述的依赖声明、构造器调用、静态调用、链式调用、超调用、方法引用存在性。调用接收者丢失为已知延后项，只断言边存在不断言接收者归属。

JavaScript：默认、命名、命名空间、副作用四种导入，再导出、命令式加载、动态导入、新建调用、承诺链调用、可选链调用。L2 锁定再导出源与动态导入目标出现。

TypeScript：在 JavaScript 子集基础上加类型导入、接口继承、类继承与接口实现、枚举定义。L2 锁定继承边目标为超类且无自身误伤，L1 锁定重复实现边合并。

Kotlin：普通导入、星号导入、别名导入（别名区分局限为已知延后项，只锁定存在性）、构造器风格调用、普通与空安全调用、链式调用、扩展函数定义存在性。

Lua：在已有加载断言基础上补冒号方法调用、普通调用、文件执行调用的存在性。

Dart：导入、导出、部件与部件归属声明、构造器调用、普通方法调用。取值器误匹配与延迟导入形态为已知延后项，只锁定正确边。

Bash：来源包含两种写法、导出变量、普通命令调用。命令调用边存在性为 L1 断言。

### 3.4 否定断言清单（噪声消除的回归锁）

C# 的 using 短名片段、TypeScript 的重复实现边、C 的引号包含重复边、Rust 的整列表与裸前缀目标、PHP 与 C# 的别名目标污染、Python 多段模块拆分边，以上在对应 e2e 测试中以否定断言锁定。否定断言只针对本轮已消除的噪声，不对延后清单中的噪声加锁。

### 3.5 修复清单（用例的前置依赖）

查询层：Rust 通配前缀捕获、Rust 两层嵌套列表三形态、Python 通配锚定模块、Python from 与别名形态的拆对（模块孪生形态与条目孪生形态，沿用分组导入的孪生 handling）、JavaScript 动态导入的匿名导入 token 形态、C++ using 名称捕获、C++ 新建与模板函数调用形态、Scala 实例化调用形态、C# 条件访问调用形态、Ruby 类实体超类包装与方法体可选、Ruby 继承依赖锚定超类、Ruby 混入捕获改名。
