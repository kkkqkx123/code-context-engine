# BM25 单实体超限刷屏与空覆盖崩溃问题清单与修改方案（2026-11-10）

日期：2026-11-10
范围：`media-server` 全量 `C` 文件在 `export_cpp` 与索引链路中 `BM25` 路径的超限告警，以及 `full_pipeline_raw_source` 在 `rtp-ext-absolute-capture-time.c` 的空覆盖断言崩溃
关联结论：词项单位已由空白词改为索引分词器位置计数，同为 `150` 时代码实际容量收紧约三到五倍，预算数值本轮不调

## 1. 现象与问题清单

`export_cpp` 处理 `media-server` 时对同一组文件反复输出两类日志：

* 装饰溢出回修：`decoration overflow folds back into the body budget`，`body` 从 `148` 压到 `1` 仍 `cost 152-435 pre 150`，最终 `combination text still exceeds the pre-injection limit after repair`。
* 原子块放行：`atomic single-entity BM25 chunk exceeds the hard limit; keeping it whole`，`cost 152-435 hard 150`。

代表文件与量级：`sip-header-uri.c` 单实体 `435/251/308/188`，`sip-header-contact.c` 单实体 `400/192`，`hls-segmenter-mp4.cpp 218`、`hls-m3u8.c 160`、`hls-fmp4.c 152`、`hls-media.c 174`、`flv2ts-test.cpp 163`、`flv-reader-test.cpp 179`。共同点是单函数体很长，多为 `#if DEBUG` 测试函数的大量断言与长字面量。

直接执行基线时出现硬崩溃：`raw-source extraction: chunk has no source coverage: file=librtp/rtpext/rtp-ext-absolute-capture-time.c chunk_id=group_10494_bm25_3`。复现扫描确认 `538` 文件中有 `2` 个空覆盖块，均为单实体细分后落在空白行上的分片，行窗为单空白行如 `(73,73)`，抽取为空。

语法缺口告警 `Parsed with syntax errors` 与分块无关，属文法缺口，真实信号，保留。

## 2. 根因分析

第一，词项文本天然很长。词项文本由模板签名文档调用成员表加索引侧车全量函数体拼接而成。模板本身只有几十词项，侧车把函数体逐行带回。测试函数上百行断言与字面量经分词后即达两百到七百词项，单实体即超 `body 148`。

第二，细分与截断到预算并不能达成目标。细分把一个函数变成多块，索引条目变多，总体索引不胀反增，且词汇分摊，精确符号查询反而需要多命中。截断到预算会丢掉尾部标识符，且块的来源覆盖仍声明整函数区间，返回跨度不变，查准率不可能因此提高。之前的内容丢失治理要求信息不丢、索引不胀、返回跨度不变，严格卡预算与之相悖。

第三，细分还会产生空覆盖分片。单实体长文本按词项比例切分行窗时，某一分片可恰好落到空白行上。分片文本非空但行窗空白，`raw` 基线抽取为空即断言崩溃。这是切分器层面的不变违反，不是基线口径过严。

## 3. 修改方案

只改原模块，不新增模块，不调预算数值，不改评测口径。核心为整块加有界截断：切分器对单实体词项块保持整块，限额对超界整块截断到三倍。

第一处为切分器整块。单实体词项块直接整块返回，模块实体除外仍按体细分。不再按三倍体预算决定是否细分，避免任何细分分片落到空白行。三倍系数不再作为切分门限，只作为截断与免打扰 bound。

第二处为回修免打扰。单路中凡超预注入的块全部为单实体词项块时直接跳过回修，不折叠体预算，不输出装饰溢出与修复失败日志。多实体超限仍按原预注入门限回修。

第三处为硬上限有界截断。单实体词项块在三倍硬上限内整块保留且不告警，超三倍才截断到三倍硬上限并置截断标记。普通多实体与嵌入块仍截断到硬上限。存储收到的单实体词项块上界为三倍硬上限，病态大文件仍有界。观测到的 `152-435` 全部零丢失，`767` 类截断到 `450` 仅丢超长尾部。

第四处为预注入免打扰。单实体词项块不再触发预注入告警，避免把正常整块误报为违规。

明确不做项为调大 `max_bm25_terms`、为测试代码加语言分支、为评测加词、改合并与重叠策略。三倍系数的选择依据是覆盖观测主流 `435` 的同时卡住病态输入，系数写死在切分、单路与限额模块并保持一致，不引入新配置。

## 4. 影响面

改动集中在切分器体判定、单路回修门限、硬上限与预注入兜底，不涉及解析器、分组器、模板、合并、重叠、评测。块数上观测文件保持一块一种函数，索引不膨胀；内容上三倍内零丢失，三倍外仅丢超长尾部；返回跨度不变，查准率口径不变；空覆盖分片不再产生，`raw` 基线不再崩溃。超限日志预期清零，语法错误告警保留。

## 5. 验证标准与执行记录

形态层面要求单实体词项文本为整块且无回修日志，硬上限截断到三倍并置标记，空块为零。单测层面覆盖整块、模块仍细分、超三倍截断到三倍、合规直通、回修不丢文件。集成层面要求 `media-server` 代表文件不再出现回修与超限告警，且 `raw` 抽取无空覆盖。
