# BM25 单实体超限刷屏问题清单与修改方案（2026-11-10）

日期：2026-11-10
范围：`media-server` 全量 `C` 文件在 `export_cpp` 与索引链路中 `BM25` 路径的超限告警，以 `libsip/src/header/sip-header-uri.c`、`sip-header-contact.c`、`libhls`、`libflv` 为代表
关联结论：词项单位已由空白词改为索引分词器位置计数，同为 `150` 时代码实际容量收紧约三到五倍，预算数值本轮不调

## 1. 现象与问题清单

`export_cpp` 处理 `media-server` 时对同一组文件反复输出三类日志：

* 装饰溢出回修：`decoration overflow folds back into the body budget`，`body` 从 `148` 压到 `1` 仍 `cost 152-435 pre 150`，最终 `combination text still exceeds the pre-injection limit after repair`。
* 原子块放行：`atomic single-entity BM25 chunk exceeds the hard limit; keeping it whole`，`cost 152-435 hard 150`。
* 语法缺口告警：`Parsed with syntax errors`，如 `libhls/source/hls-m3u8.c`，与分块无关，属文法缺口，真实信号，保留。

代表文件与量级：`sip-header-uri.c` 单实体 `435/251/308/188`，`sip-header-contact.c` 单实体 `400/192`，`hls-segmenter-mp4.cpp 218`、`hls-m3u8.c 160`、`hls-fmp4.c 152`、`hls-media.c 174`、`flv2ts-test.cpp 163`、`flv-reader-test.cpp 179`。共同点是单函数体很长，多为 `#if DEBUG` 测试函数的大量断言与长字面量。

直接后果有三层：同一超限组触发三次重切加两次告警，日志被淹没；终态块仍超 `hard`，且回修对原子块完全无效，属于 wasted work。

## 2. 根因分析

第一，词项文本天然很长。词项文本由模板签名文档调用成员表加索引侧车全量函数体拼接而成。模板本身只有几十词项，侧车把函数体逐行带回。测试函数上百行断言与 `sip:alice@...` 类字面量经分词后即达两百到四百词项，单实体即超 `body 148`。

第二，单位收紧未配限额放大。词项按索引位置计数，代码中标点内的标识符逐个计数，`150` 仅能装约十行代码，而旧空白词口径可装三十到五十行。`media-server` 的长函数在新口径下必然超限。

第三，无界原子使回修失效。切分器对单实体词项块直接整块返回，无视体预算；硬上限同样只告警不截断。组合超限的主因正是块内单个原子成员，回修把体预算压到 `1` 也降不下极大值，三次重切注定失败。

第四，严格细分与截断到预算并不能达成目标。细分把一个函数变成多块，索引条目变多，总体索引不降反增，且词汇分摊到多块，精确符号查询反而需要多命中。截断到预算会丢掉尾部标识符，且块的来源覆盖仍声明整函数区间，返回跨度不变，查准率不可能因此提高。之前的内容丢失治理目标要求信息不丢、索引不胀、返回跨度不变，严格卡预算与之相悖。

## 3. 修改方案

只改原模块，不新增模块，不调预算数值，不改评测口径。核心改为有界容忍：单实体词项块在三倍预算内保持整块，超三倍才细分或截断到三倍。

第一处为切分器有界整块。单实体词项块在三倍体预算内整块返回，模块实体除外仍按体预算细分。超三倍体预算才按段落再到硬切逐级下钻。预期观测到的 `152-435` 全部落入三倍体内，首次切分即整块返回，回修不再触发。

第二处为回修免打扰。词项路以三倍预注入为修复门限，容忍内的整块不再折叠体预算，不再输出装饰溢出与修复失败日志。嵌入路门限不变。

第三处为硬上限有界截断。单实体词项块在三倍硬上限内整块保留且不告警，超三倍才截断到三倍硬上限并置截断标记。普通多实体与嵌入块仍截断到硬上限。存储收到的单实体词项块上界为三倍硬上限，病态大文件仍有界。

第四处为预注入免打扰。容忍内的单实体词项块不再触发预注入告警，避免把正常整块误报为违规。

明确不做项为调大 `max_bm25_terms`、为测试代码加语言分支、为评测加词、改合并与重叠策略。三倍系数的选择依据是覆盖观测最大值 `435` 的同时卡住病态输入，系数本身写死在切分与限额模块并保持一致，不引入新配置。

## 4. 影响面

改动集中在切分器体判定、单路回修门限、硬上限与预注入兜底，不涉及解析器、分组器、模板、合并、重叠、评测。块数上观测文件保持一块一种函数，索引不膨胀；内容上三倍内零丢失，三倍外仅丢超长尾部；返回跨度不变，查准率口径不变，排序上长函数权重稀释维持现状，召回不丢。超限日志预期清零，语法错误告警保留。

## 5. 验证标准与执行记录

形态层面要求三倍内单实体词项文本为整块且无回修日志，超三倍才细分且每片合规，硬上限截断到三倍并置标记，空块为零。单测层面覆盖容忍内整块、超容忍细分、超三倍截断到三倍、合规直通、回修不丢文件。集成层面要求 `media-server` 代表文件不再出现回修与超限告警。
