# 前端与桌面端共用样式设计

目标：Web 前端与 GPUI 桌面端共用一套样式事实，任何一端改色、改字号、改间距或改圆角，
另一端在构建或校验阶段失败，而不是在视觉上悄悄不一致。

## 借鉴 linkrs 的做法，调整后采用

linkrs 的做法是仓内 `design/tokens.json` 为单一数据源。Web 样式表是该目录的投影之一，
桌面端在编译期嵌入同一份文件并解析为主题色与度量；前端用脚本校验样式表与目录一致，
桌面端用单测校验关键色值与布局常量。目录分块与样式表分块一一对应，桌面专属内容单独成块，
不混入 Web 变量。

该机制可直接采用，但分区不能照搬。linkrs 前端基于 Tailwind，分区按主题、根、紧凑、深色划分；
CCE 前端是手写样式体系（瑞士极简加工业风），变量按语义分组，且无深色主题与密度模式。
因此 CCE 的目录分区应如实反映 `frontend/src/app.css` 现有分组，而不是复制 linkrs 的四个块。

## 目录分区建议

以当前样式表实际分组为基准，建议目录包含以下分区：铬壳（顶栏与输入框）、运维表面与文字、
品牌强调色、灰阶、语义状态色及其浅底、深底状态色、间距阶梯、语义边框、形状与圆角、断点、
关系图节点色板、字体字号字距行高。深色外观若前端后续引入再增分区，当前不需要为不存在的
深色主题编造变量。桌面专属块只放 Web 样式表没有对应物的内容，例如桌面字体栈与按下态颜色，
以及桌面布局常量中需要与 Web 对齐的部分。

别名关系要显式声明。样式表中已有语义别名（如文字、边框的次级命名），目录中保留别名映射，
桌面端解析时沿用同一映射，避免桌面侧自创别名。

## 同步与校验

单一数据源确立后，三处保持同步：目录文件、前端样式表、桌面端解析与主题应用逻辑。
新增一个前端校验脚本，对比目录与样式表的变量集合与取值，双向报错（目录多出的与样式表
多出的都算失败）。该脚本并入前端检查流程，与现有的契约检查、样式一致性检查并列。
桌面端嵌入目录文件，主题应用逻辑只从目录取值，不允许出现手写色值；关键语义色在桌面端
单测中断言，保证目录改动会传导到桌面视觉。桌面专属块的缺失同样判定为失败，避免静默回退
到默认值。

## 变更流程

修改样式只改目录与样式表两处，先更新目录，再更新样式表，最后运行前端校验与桌面构建检查。
桌面布局常量中与目录有对应关系的部分（如页面边距、卡片圆角、头部高度、行高），其取值注释
指向目录中的变量名，改目录时一并复核这些常量。关系图节点色板由图例与画布共享，桌面端图谱
面板沿用同一色板，不另起配色。

## 验收

- 目录文件存在且为唯一手写源，样式表与桌面端均从其投影或嵌入。
- 前端校验脚本在变量增删改时失败并指明分区与变量名。
- 桌面端无手写品牌色值，主题切换后浅色外观与 Web 视觉一致。
- 现有前端检查（契约、样式一致性、构建隔离）不受新增校验影响。
