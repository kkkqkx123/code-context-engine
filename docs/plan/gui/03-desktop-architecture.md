# 桌面端架构

## crate 选址与工作区隔离

新增 `crates/app/cce-desktop`，与 `cce-client`、`cce-cli`、`cce-gateway` 同层。
该 crate 只做视图与交互状态，不持有业务逻辑，不复制调用面。

采用独立工作区根，仿 linkrs-gpui，不并入根工作区。原因有二：桌面侧依赖的组件库工作区
与根工作区在传递依赖解析上存在冲突风险，且桌面构建需要独立的调试优化配置与系统库前提。
构建与测试统一使用清单路径方式，文档中写明子模块初始化、系统依赖与无头环境下仅构建测试
的约束。是否长期保持隔离以一次实际探针为准：若探针证明可合并不引入解析冲突，再合入；
探针之前默认隔离，避免为合入而改动根工作区的依赖表。

依赖方向严格单向：契约层无输入输出依赖，客户端依赖契约，桌面端依赖客户端与组件库，
服务端不依赖客户端与桌面端。桌面端不依赖编排器、存储与服务端实现，远程能力只经客户端，
本地能力（如确有需要）直接调编排器而不同时走网络语义，不为对称引入动态分发。

## 模块划分

- 应用入口：负责初始化顺序与主窗口打开，包括主题、全局状态、运行时、连接、快捷键、
  健康探测、托盘，登录态与工作态的根切换放在窗口壳层。
- 全局界面状态：只镜像渲染所需的连接状态、基地址、健康情况、语言与密度等快照，
  不持有网络会话本身。
- 运行时桥接：持有 tokio 运行时，将客户端请求转交 tokio 执行并以任务形式回到界面线程；
  取消语义为放弃本地等待，后台请求按 abandon 处理。
- 连接：持有可克隆的客户端句柄，提供连通性探测与令牌来源说明（显式令牌优先于环境变量，
  令牌不落盘、不进日志）。
- 服务：按资源一切分，每个服务对应客户端的一个或一组操作，负责参数组装、分页状态、
  结果缓存与错误分类转述，不写重试与调度策略。
- 视图：每个面板一个视图，主窗口承载侧边导航与可停靠面板，面板注册保证持久化布局恢复后
  身份稳定。
- 通用构件：页面头、页面体、卡片、数据表、空态、浮层、 Pill 与指标卡，桌面端不再自建第二套。
- 主题：目录解析加品牌覆盖应用，主题切换统一走单一入口，避免基座主题重载丢弃覆盖。
- 设置：窗口几何、主题、密度、语言与最近基地址落盘；凭据类信息永不落盘。
- 国际化：消息目录集中存放用户文本，源码保持英文，缺失条目回退到英文再回退到键名，
  保证不出现空白控件。
- 托盘：窗口关闭常驻、托盘菜单恢复与退出，托盘不可用时关闭窗口即退出进程，不阻塞启动。
- 度量：页面边距、卡片内边距与圆角、头部高度、行高等常量集中存放，与设计目录有对应关系的
  注明来源，无对应关系的注明其为桌面专属。

## 状态与数据流

界面状态分两层：全局快照供导航、状态栏与面板切换观察；面板本地状态持有各自的查询参数、
分页、选中与结果。跨面板传递（如检索结果送入图谱面板）通过全局投递槽加单调生成号实现，
接收方按生成号去重，避免重复打开。长任务（全量索引、批量操作、进程启停）使用长任务预算，
交互查询使用交互预算，预算划分沿用客户端已有分级，桌面端不自定超时。

## 守卫

桌面端不新增契约模型，所有线上传输类型来自契约层。客户端守卫（路径覆盖）保持有效，
桌面端新增设计 token 一致性单测。前端既有守卫（契约、样式一致性、构建隔离）不受桌面端影响。
