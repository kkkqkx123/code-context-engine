# 分阶段落地计划与验收

## 阶段划分

第一阶段先立样式事实。抽取前端样式表现有变量生成设计目录初版，补齐前端双向校验脚本并接入
前端检查流程，桌面端实现目录解析与主题应用并补齐关键色值单测。该阶段不写任何业务面板，
验收以校验脚本能捕获漂移为准。

第二阶段立桌面骨架。建独立工作区 crate，实现应用入口、运行时桥接、全局状态、连接、设置、
国际化、托盘、壳层、主窗口导航与通用构件，打通基地址连通与健康探测。该阶段结束时应能打开
空工作区并切换主题密度语言，常驻托盘可用。

第三阶段交付高频面板。按检索、图谱、实体、索引、项目的顺序逐个交付，每个面板包含视图、
服务、历史记录与空态错误态，图谱面板包含检索结果送入能力。每个面板独立可验收，不要求一次
合入。

第四阶段补齐运维面板组。交付工具、存储、监视、健康、指标、配置与任务队列面板，并收敛构建
文档、系统依赖说明与打包方式。

## 每阶段验收

- 设计阶段：增删任一变量，前端校验失败且指明分区；桌面端主题单测失败；现有前端检查全绿。
- 骨架阶段：清单路径构建与测试通过；无头环境下构建测试通过；窗口几何主题密度语言基地址
  在重启后恢复；令牌不出现在落盘文件、日志与错误文本中。
- 面板阶段：每个面板在无后端时展示空态，在有后端时完成一次真实往返；长任务使用长任务预算，
  交互查询使用交互预算；历史记录上限生效。
- 收尾阶段：全部面板经导航可达；持久化布局在版本升级后正确重置；托盘关闭常驻与退出行为符合
  设置；文档写明各平台系统依赖与排障对照。

## 验证命令收敛

桌面侧验证统一走清单路径，不使用根工作区命令覆盖桌面 crate。前端侧验证沿用现有检查目标，
新增的设计 token 校验并入其中。编译期优化配置沿用组件库已有做法，保证调试构建下渲染链路
可用。无自动化测试仅断言表现尺寸；凡涉及行为、交互、数据流与防回归的一律补单测。

## 风险

工作区隔离是否长期必要以探针为准，不预设合并时间。系统依赖（字体、窗口、密钥存储对应库）
按平台在文档中列出并提供排障对照，缺失时桌面端降级运行或明确报错，不静默空白。日志页是否进
桌面端取决于契约建模结论，见 `08-frontend-parity.md` 第 7.3 节。深色外观不超前实现，
避免桌面端自创 Web 侧不存在的语义。
