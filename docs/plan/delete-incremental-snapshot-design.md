# 删除、增量与快照语义审计与后续任务设计

本文为 P1 遗留闭环的复核结论。逐一核查删除合并、增量快路径、快照移交三条线的语义正确性，判定既有设计是否合理，给出后续任务。凡推翻此前闭环结论处，均同步说明对原闭环分析的修正。

## 审计方法与口径

以调用链实证为准，区分已确认事实与推测。作用域传递、事务边界、拷贝语义只采信代码路径，不采信注释自述。性能数值引用已归档基线，不新增测量。

## 删除路径语义

### 作用域传递正确，无丢失

全文存储与向量存储的两层分发均逐字透传作用域参数，工程标识、文件路径、轮次、索引名在 trait、枚举分发、客户端包装、引擎调用之间无丢失无错位。路径归一化收敛在删除实现内部完成。空匹配跳过书写器创建与提交的优化在四个按条件删除上全部落实。

### 脆弱点一：索引模式来源不一致

按轮次限定的两个删除包装使用客户端自持模式，而非守卫持有的管理器模式。当前两处模式字段序号一致故无事故，但索引打开路径会重建模式，依赖巧合而非不变量。后续任务应统一为管理器模式，消除错位风险。

### 缺陷一：热更新整文件函数为死代码且语义自删

整文件热更新函数先写入本轮数据，随后发起不限轮次的删除，删除条件恰好覆盖刚写入的行。核查确认该函数零调用方，属死代码叠加潜在自删语义。后续任务为直接删除该函数，不做修复性保留。

### 缺陷二：整文件删除缺候选守卫且调用重复

整文件删除不检查候选操作状态，若在候选操作内被调用将破坏父代不受影响的不变量。单文件删除编排先调通用删除再调摘要删除，全文侧第二次删除必为零命中，虽被早期返回吸收但仍有一次查询开销，向量侧则为一次完整的重复过滤删除。后续任务为补候选守卫并合并两次删除调用。

### 缺陷三：摘要删除的全文侧语义过宽

摘要删除在非候选分支调用不限类型的按文件删除，会连带清除该文件的普通分块文档，超出摘要范围。后续任务为按文档类型或标识前缀收窄删除条件，或如实更名并收敛调用方预期。

### 代价不对称：远端向量删除无批量无跳过

本地向量删除为进程内一次过滤扫描，单调用代价可控。远端分支每次删除为一次重试包装的 HTTP 往返，且返回类型不携带命中计数，无法实现零命中跳过。热更新每文件固定触发多次外部删除，远端部署下形成放大的小请求流。后续任务为先给远端删除补计数返回，再按操作累积过滤器批量提交。

## 增量路径语义

### 热更新增量语义正确，设计合理

增量处理器的拒绝条件完备，失败文件、无解析替换、重解析失败、内容漂移、配置扫描失败、指纹失配、边丢失超限、发布冲突重试均有明确分支。空变更短路不触发重建。差异比较覆盖文件、实体、边、文件级关系、导入导出依赖，悬空边强制移除。符号指纹守卫同时检测候选侧污染。整条路径予以保留，无需调整。

### 修正一：按影响集拷贝无生产调用方

按影响集写时复制仅被基准与一个未参与编译的文件引用，生产侧零调用。热更新增量走的是稀疏候选加差异发布路径，从未经过该原语。此前闭环中终结基准增量数值的表述需修正：该数值为原语表征，不对应任何生产回归路径。后续任务二选一：为其找到真实调用点并用生产流量验证，或按无死代码原则删除该方法及同文件中的零调用构造器与未编译的快照包装文件。倾向删除。

### 修正二：世代计数未接线

清空操作不推进世代，是否过期检查与刷新逻辑无调用方。运行时安全实际依赖快照整替加轮次单调守卫，与世代计数无关。后续任务为删除世代检查死代码，或在清空与发布点接线并补测试。倾向删除，除非导出增强修复需要它。

## 快照语义

### 全量发布深拷贝确为必需，维持原闭环

构建器索引在发布后仍被导出增强以只读方式使用，下一轮构建原地清空复用映射。零拷贝共享将被下一轮清空污染，按影响集复制共享的未变更部分同样如此。根治需重设计构建器生命周期，维持不改代码的闭环结论。

### 缺陷四：导出增强持有浅拷贝，存在清空污染

导出增强从构建器获取浅拷贝克隆并长期持有，下一轮构建的原地清空会将其可见内容置空，且清空不推进世代，任何过期检查均无法拦截。从持久化回源的增强路径不受影响。表现为关系增强静默退化，属正确性问题而非性能问题。后续任务为增强器改持发布时深拷贝产物，与构建器生命周期解耦。

### 其余构造器状态健康

拥有式移交与零拷贝共享的现有调用点均符合源不变更约束，压实路径、引擎重载路径、基线缓存路径的共享均安全。仅零调用的陈旧快照构造器随按影响集拷贝一并处理。

## 预编译复用去留结论：保留

生产元数据库为文件预写日志加同步常规模式，提交代价为日志追加与互斥往返。语句复用节省的是解析与查询规划 CPU，在内存基准中不可测，实测持平。保留理由为零语义差、已落地验证通过、符合常规写法，回退本身是一次无收益的代码 churn。去除理由不存在。结论为保留，但原方案中行吞吐提升一至两个数量级的预期为错误基线判断，实际有效方向始终是事务合并，且文件库下合并收益只会大于内存基准。

## 遗留闭环的同步修正

原 P1 方案文档需同步修改三处。写路径验证节中行吞吐提升一至两个数量级的表述改为事务合并一点五倍、语句复用无收益。终结基准增量数值的表述改为原语表征、非生产回归依据。快照闭环补充导出增强污染作为新的后续任务，增量闭环补充按影响集拷贝无调用方作为新的后续任务。

## 后续任务清单

按正确性优先于性能排序。每个任务独立可验证，改动约束在原模块内，不新增替代模块，不保留旧路径。

- 清理热更新整文件死函数，消除自删语义。
- 整文件删除补候选守卫，并合并通用删除与摘要删除的重复调用。
- 收窄摘要删除的全文侧条件，使其名实相符。
- 统一删除包装的索引模式来源，消除序号巧合依赖。
- 远端向量删除补计数返回，并按操作累积批量提交。
- 导出增强改持发布快照，消除构建器清空污染。
- 按影响集拷贝及零调用快照构造器二选一，为接线或删除，同步修正基准表述。
- 实体标识加载提出微批循环，全文与向量链路每微批各全表扫描一次，随微批数线性放大读。
