# 开销较大环节清单

本文按索引构建、热更新、代码解析、中断恢复、本地检索五类整理开销较大的环节。描述以自然语言为主，括号内标注关键实现位置，便于定位。外部远程调用不计入。

## 1. 索引构建

### 1.1 扫描与文件读取

- 每文件经历元数据读取、全文读取、哈希计算、二进制嗅探、语言判定，多个步骤各自触碰文件内容。实现位置为扫描器的目录遍历与文件处理模块，大文件虽有流式哈希分支，但常规路径仍以全文读取为主。
- 批处理内存在二次读取：扫描阶段读过一次，解析前为校验编码与哈希再读一次。同一文件在单次全量索引中被读两次，磁盘密集型项目中占比显著。
- 全量恢复时先重扫全量文件列表，再按路径排序并计算整体文件列表哈希，文件数增长时该前置工作线性增长。

### 1.2 批处理并发

- 批循环按批次大小动态决定并发度，并用信号量约束并行任务数。并发度过大时任务与内存句柄激增，过小时解析、自然语言转换、切块串行等待，吞吐对批次与并发参数敏感。
- 每文件处理完成后按文件、模块、阶段多次更新状态跟踪，多次异步等待累积为固定开销，文件数多时不可忽略。

### 1.3 检查点编码与写入

- 解析产物检查点采用结构化序列化加压缩，每文件触发一次编码加一次事务写入。产物中包含源码、实体与原始关系，体积随文件增大而增大。
- 摘要持久化对同一文件产生第二次写入事务，与解析检查点写入叠加。
- 向量与全文两条存储路径各自维护按批次计算的工作单元哈希，伴随排序、查询与插入事务。小批量场景下事务次数先于实际嵌入成为瓶颈。

### 1.4 向量存储微批次

- 每微批次需要计算工作单元哈希并查询与插入工作单元记录，产生两次存储事务。
- 构建存储数据时每批次全量扫描当代表中实体行并解析来源实体标识，批次越多重复扫描次数越多，呈现批次放大效应。
- 摘要生成在批内同步等待，导出拼接按文件分组克隆文本块，大项目下内存占用随批次堆积。

### 1.5 关系终局构建

- 终局构建先清空构建器并加载配置类文件的解析结果，再分别走内存与磁盘两条回放路径。内存路径一次性收集全部解析产物，峰值内存与项目规模成正比。磁盘路径对缓存做两次读取与反序列化，输入输出开销翻倍。内存与磁盘路径的切换存在固定阈值，阈值附近易出现行为跳变。
- 快照规范化需要遍历文件记录、函数索引、关系与依赖并组装规范形态，同时计算实体与关系的派生键与指纹，复杂度与实体加关系总数成正比。
- 治理边注入存在三重循环，导入数量多时组合膨胀。
- 查询优化索引与传递依赖索引在快照构造时同步构建，两份二级索引均为全量量级。
- 导出文档阶段逐文件反序列化文本块并递归扫描输出目录清理过期文档，文件数多时收尾阶段耗时明显。

## 2. 热更新

### 2.1 变化检测

- 每次检测全量走目录扫描，重建相对路径到文件条目的映射并克隆上一轮条目，目录越大单次轮询开销越大。
- 已存哈希的加载、计数与删除判定各自扫描本代与祖先代数据，内存中再做集合合并，多次全代扫描叠加。
- 旧的逐文件查询哈希路径在文件多时退化为多次单行查询，应以批量读取替代。

### 2.2 事件循环与模式切换

- 事件通道有界，防抖、待处理集合与通知机制在文件风暴下频繁触发模式切换。风暴阈值配置直接决定是逐文件处理还是退化为周期扫描，抖动区间需要度量。

### 2.3 关系增量更新

- 更新处理器先做传递依赖的广度优先展开，再按并发上限重解析受影响文件，随后构建稀疏候选并计算增量、发布与更新基缓存。传递闭包过大时存在整包拒绝重做的保护分支，该分支触发条件需要基准覆盖。
- 增量计算在未传入受影响文件集合时退化为双边全量对比，涉及实体差分、边差分与导入导出差分的多表扫描与集合物化。热更新必须恒定传入单文件加传递闭包的作用域，否则单文件修改也会付出全项目差分代价。

### 2.4 层叠快照读放大

- 层叠视图的多数查询先把基快照全量合并到临时映射再叠加增量，单次查询即全量量级。增量链越长线性扫描层数越多，压实前查询呈现项目规模乘链长的放大。
- 按受影响文件过滤拷贝仍需全表迭代判定交集，过滤节省的是拷贝量而非扫描量。
- 分离克隆对实体库、关系库、符号注册表、文件库与两份依赖图做深拷贝，全量物化只应在压实与冷启动出现，热路径已由基缓存加层叠视图替代，但回退分支仍需度量。
- 基缓存命中时为零拷贝包装，未命中或断链时全量重载，缓存窗口与链长阈值决定重载频率。

## 3. 代码解析

### 3.1 解析流水线总体特征

- 单文件解析为串行多阶段：语言判定、语法解析、实体抽取、控制流抽取、行为抽取、宏体抽取、文档注释处理、关系抽取、结构抽取、后处理。同一语法树被多次查询扫描，中间匹配结果全部物化为集合，无流式处理。

### 3.2 语法解析与节点转换

- 解析本身与文件字节数相关，节点转换阶段对每个节点做文本截取与字符串复制，大文件全树转换存在文本翻倍现象，冗余字段进一步放大内存。

### 3.3 查询执行

- 查询执行是最大热点之一。每次捕获涉及捕获名复制与节点文本复制，大段正文捕获尤其昂贵。查询编译结果有缓存，命中后便宜，未命中时编译开销大。部分执行路径在全量匹配后再做二次过滤，未下推谓词。
- 单文件样式内嵌查询存在每次新建查询而无缓存的分支，应优先补基准并修复。

### 3.4 实体抽取与后处理

- 实体抽取遍历全部匹配并处理特殊形态，例如元组解包折叠、循环分支扇出、属性缓冲。多遍区间关系解析与去重截断带来二次量级的后处理开销。
- 语言专属分支差异明显，属性过滤、装饰器保留、接收者解析、标准库分类等按语言分叉，复杂语言的后处理链更长。

### 3.5 内嵌模板二次解析

- 单文件组件类语言先做主语言解析，再对脚本与样式块逐块二次解析并调整跨度偏移，等价于同一文件解析多次。大单文件组件与样式内联是尾延迟主要来源。

### 3.6 分组

- 分组流水线存在多次全量复制、排序与集合过滤，空文件回退与断言检查也在主路径上。调用合并、测试套件处理、类方法处理、函数成员处理、碎片合并等子处理器各自排序与建表，分组数与实体数增长时开销叠加。

### 3.7 自然语言转换双路径

- 全文检索文本与嵌入文本两条路径对同一实体组各跑一遍，模板拼接、关键词抽取、文本清洗各自全文本扫描多次，至少两到三遍字符串中转。
- 嵌入路径含长文档阈值判定、嵌套组递归、截断与噪声过滤，标识符规范化对每实体名至少触发一次，含大小写转换与分词连接。

### 3.8 切块

- 切块按边界层级递归下钻，无边界时逐级降级到行与硬切，超限片段在容差外递归细分，逐段复制文本。合并小片段时贪心重算代价，两条路径按各自上限各跑一遍。
- 词元边界查找逐字符扫描并回退寻找句子、空白、换行与围栏边界，大组场景下切分本身的扫描开销显著。

### 3.9 摘要与文档链

- 默认规则摘要在生成时重建预处理流水线，与主流程分组重复，存在重复分组开销。可复用结果的入口未被默认使用。
- 混合分词对中文段走词典切分，非中文段做标识符切分与大小写复制，每文本块触发一次，索引期每块一次，检索期查询与标题各一次。
- 文档解析链与代码链同构，按格式分支解析、分组、切分与摘要，共享词元估算开销。

### 3.10 语言差异

- 单文件组件类查询体积最大，模板指令与控制块多，编译慢且捕获多。脚本样式混排语言用内嵌二次解析补偿缺失的查询类型，省一次扫描但加倍偿还。
- 大类与大实现体的成员多，模板拼接长，嵌入递归与截断段数多。中文注释多的文件更易触发切分与中文分词。
- 宏体抽取仅部分语言触发，注解语义与修饰符处理按语言分支，查询缺失类型导致各语言扫描次数不同。

## 4. 中断恢复

- 恢复文件索引器需要获取最近检查点、重扫全量文件、校验文件数、批次、根目录、整体哈希与边界文件，任一失配即从头开始。
- 已完成批次的哈希校验逐批读取并解码，首个哈希漂移、缺失或版本不兼容即回退起点，后续全部重做。
- 关系回放逐批读取并解码后追加符号，总量与已完成规模成正比。导出预热逐批解码后重新切块，相当于恢复期重做一次切块。
- 磁盘内容变化与配置指纹变化各自强制重解析或重做对应模块，指纹缺失的陈旧检查点走保守全量重做。
- 候选代不可采用时清除模块进度，已提交的嵌入与全文微批次全部重做。文件列表哈希与批次边界任一失配即全量重做，该悬崖行为需要基准量化。
- 恢复期每文件经历压缩解码加结构化反序列化，文件数多时恢复耗时与重解析相当。

## 5. 本地检索

### 5.1 本地全文检索

- 主读路径按项目、代际、测试与分类多层布尔过滤，取回数量为限制加偏移，随后跳过偏移并逐文档取存储字段。大偏移分页代价高。
- 查询构造按位置分组做整词加切分膨胀，每词元乘以多个字段加权重生成子句，长查询子句扇出大。每个整词做多次词典频率查询，长查询词典访问次数多。
- 每个命中触发高亮流程，重复执行查询分词与标题分词，高亮关闭时仍有匹配词抽取开销。高亮内部对标题全量分词，每次新建多模式匹配自动机并逐字符检查词边界，命中数放大后同步放大。
- 批量写入逐文档删除加添加后一次性提交，大批量提交仍有逐词典删除开销。快照与代际统计类接口做全量扫描加逐文档反序列化，只适合代际拷贝与回收判定，不适合热查询。
- 全文客户端互斥锁跨越整个搜索过程，高并发下本地全文读相互串行。

### 5.2 本地元数据查询

- 文本块按编号集合查询，混合召回膨胀后集合变大，大集合成员查询退化为多次定位。
- 继承视图两阶段查询在本代未命中时再查父代，失败路径查询次数翻倍，排除文件集合在内存中过滤。
- 源文件行读取按命中逐次全文件读取并按行计数与截取，同文件多命中重复读整文件，无文件级缓存与行缓存。每请求解析结果中的实体标识与名称各一次，并重复查询项目根路径。
- 代际最大实体标识查询全代际扫描并逐行解析标识集合，热更新种子用途下开销偏大。部分查询携带相关子查询求最大代际，每次读多一次聚合。个别查询缺代际过滤或联合字段索引不匹配，存在全项目连接与排序风险。
- 活跃查询过滤器每请求重算且明确无进程缓存，关键词与搜索器各触发一次。

### 5.3 关系图查询

- 调用链遍历为广度优先，每节点查询函数、文件路径与出入边，默认最大节点数较大，深图易触顶。
- 路径查找在队列中存放完整路径，每条边触发一次路径复制，复杂度随深度增长。邻居查询对每个调用者再查被调用集合找边，度数大时呈平方特征。
- 全图导出与连通分量遍历全图函数与关系并做并查集合并与排序，不适合在线热查询。
- 文件过滤存在时绕过查询缓存，全量遍历后再过滤分页，过滤查询的缓存命中为零。被调用查询直透无缓存，调用者查询走缓存，两侧不对称。
- 符号解析存在命名空间回退全表扫描与通配导入展开遍历，重建索引为全量重建。

### 5.4 融合排序与后处理

- 混合融合按对齐键取最佳分并做归一化，对空一路仍走统一加权归一化，归一化与搜索器预归一化叠加为两次缩放，边界语义不一致易产生大量并列。
- 对齐键优先级固定，实体优先于片段，双路独立切块导致块标识天然不对齐，无实体或片段键时永不融合。多实体展开防御性克隆使候选数乘实体数。
- 摘要加权在融合分上逐命中改分，聚合按文件分组排序合并，每次合并重估词元。关键词独立工具链与主链重复分词、读盘与高亮。

### 5.5 候选截断与词元估算

- 候选选择线性扫描分数跌落并截断到最大候选数，默认候选规模较大，构建候选时全量克隆正文与路径大字符串，合并后重排。
- 词元估算对代码密集文本为启发式，截断以比例循环每次重估，大文本最坏呈平方特征，聚合每次合并重估。

### 5.6 缓存

- 查询结果缓存键包含项目、代际、排除集合哈希、查询串、来源、过滤与限制，限制不同即未命中，聚合多子查询组合易抖动。禁用时使用零容量缓存。
- 嵌入缓存仅精确文本命中，向量批量路径直透。关系查询手写最近最少使用缓存的提升操作为线性移队，读缓存需写锁。符号解析缓存有全局锁，部分映射无界无过期，插入与裁剪时清缓存。
- 存储块缓存影响文档取存储字段，间接影响全文命中的物化开销。

## 6. 现有覆盖小结

- 已有热更新扩展性基准覆盖合成链式项目的全构、层叠视图、单文件作用域增量计算与增量应用，断言后三者不随文件数线性增长，结果追踪到表格文件。该基准未覆盖扫描、检查点编解码、终局双遍回放、层叠链长退化、存储微批次事务与并发参数组合。
- 根目录端到端脚本覆盖索引、查询与热更新三类场景，依赖真实服务与 fixtures 填充，当前 fixtures 为空壳，本地裁剪后的轻量路径缺失。
- 随仓全文检索引擎的微基准均为上游通用倒排与分词基准，与本项目混合分词、代际过滤与融合逻辑无关。
- 各模块单元测试集中在正确性，无耗时断言。关系增量单测覆盖作用域与全量等价性，但未覆盖误用全量时的代价告警。工作流文档覆盖恢复正确性，不覆盖恢复耗时曲线。
- 端到端说明中引用的性能基准分析文档当前缺失，根基准说明中的部分链接已失效，需要在本轮补齐。
