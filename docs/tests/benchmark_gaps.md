# 需要补充的性能基准测试

本文给出为找出性能瓶颈需要补充的基准清单。每个基准说明目的、输入、度量与通过标准。实现时以简洁自然语言描述为准，不内嵌完整代码。

## 通用原则

- 微基准定位单环节耗时，端到端基准验证组合与回归，两类缺一不可。
- 所有基准默认不依赖外部网络，嵌入与重排用确定性模拟或本地规则生成器，全文走本地路径。
- 每个基准固定随机种子与输入规模，输出表格化结果并追加到趋势文件，至少记录文件数、实体数、命中数、耗时均值与分位值、内存峰值。
- 优先度分为高、中两档，高的对应主链路瓶颈或悬崖行为，建议先落地。

## 1. 索引构建基准

### 1.1 扫描与哈希吞吐

- 目的：量化目录扫描、全量哈希、增量复用命中率与二次读取代价。
- 输入：小中大三档文件集，混合源码、文档、大文件与二进制文件，含无变化、少量变化、全量变化三种状态。
- 度量：扫描耗时、哈希耗时、增量复用率、二次读取占比。
- 通过标准：无变化轮询耗时远小于全量扫描，全量重哈希间隔可解释。
- 存放建议：扫描归属 crate 微基准加端到端脚本场景。
- 优先度：高。

### 1.2 批并发与批次参数组合

- 目的：找出批次大小、解析并发、存储并发、嵌入批量与延迟的最优区间。
- 输入：中等规模真实项目切片，固定输入变换并发与批量组合。
- 度量：端到端吞吐、任务峰值、内存峰值、存储事务数。
- 通过标准：给出推荐默认区间，偏离区间时有日志或指标提示。
- 优先度：高。

### 1.3 检查点编解码

- 目的：量化解析产物序列化压缩与反序列化的单文件吞吐。
- 输入：小文件、大文件、单文件组件、含大段注释文件四类样本。
- 度量：编码耗时、压缩比、解码耗时、事务耗时占比。
- 通过标准：大文件编码不主导单文件总耗时，恢复期解码曲线可用。
- 优先度：高。

### 1.4 存储微批次事务

- 目的：量化工作单元哈希、查询插入事务与来源实体加载的批次放大。
- 输入：固定文本块总数，变换嵌入批量大小。
- 度量：每批次事务数、来源加载扫描行数、总耗时随批量变化曲线。
- 通过标准：大批量下来源加载不成为主导项，或给出批量上限建议。
- 优先度：高。

### 1.5 关系终局双遍回放

- 目的：对比内存收集与磁盘两次回放的内存与耗时，验证阈值合理性。
- 输入：中小大三档项目，含配置类文件与导入边。
- 度量：两遍读取耗时、峰值内存、规范化耗时、二级索引构建耗时、治理边耗时。
- 通过标准：阈值附近无剧烈跳变，大项目收尾占比可解释。
- 优先度：高。

## 2. 热更新基准

### 2.1 单文件修改端到端

- 目的：验证单文件修改的增量代价不随项目规模线性增长。
- 输入：合成链式项目从百到数千文件，单文件改名模拟编辑，已有基准可直接扩展。
- 度量：视图包装、作用域增量计算、增量应用三段耗时。
- 通过标准：后三段耗时基本持平，全构耗时线性增长作为对照。
- 优先度：高。

### 2.2 变化检测轮询

- 目的：量化全量扫描、已存哈希加载、删除判定在不同变化率下的开销。
- 输入：固定项目规模，变换单次变更文件数与删除新增比例。
- 度量：轮询耗时、内存克隆量、数据库查询次数。
- 通过标准：空操作路径快速返回并可断言不产生新代际。
- 优先度：高。

### 2.3 层叠链长退化

- 目的：量化增量链长度对查询的放大，确定压实阈值。
- 输入：固定项目，链长从一到二十递增。
- 度量：常用合并查询耗时、指纹计算耗时、物化耗时。
- 通过标准：给出链长上限与压实触发建议，超限有计数告警。
- 优先度：高。

### 2.4 过滤拷贝与分离克隆对照

- 目的：对比按受影响文件过滤拷贝与全量分离克隆的扫描与拷贝代价。
- 输入：大项目加单文件与多文件两种作用域。
- 度量：全表扫描行数、实际拷贝量、耗时。
- 通过标准：单文件作用域拷贝量远小于全量，扫描占比可解释。
- 优先度：中。

### 2.5 误用全量差分告警

- 目的：验证未传入作用域时的全量差分代价，并形成可观测信号。
- 输入：中等项目，分别传入单文件作用域与空作用域。
- 度量：差分耗时、集合物化量、越界计数。
- 通过标准：空作用域触发明确计数或日志，不静默退化。
- 优先度：中。

## 3. 代码解析基准

### 3.1 单文件解析吞吐

- 目的：量化各语言单文件解析、抽取、后处理的总耗时与分段占比。
- 输入：每语言选取小文件、大文件、深嵌套文件、大注释文件，含单文件组件与样式内联样本。
- 度量：分段耗时、匹配数、实体数、内存峰值。
- 通过标准：定位最慢语言与最慢阶段，尾延迟样本单独记录。
- 存放建议：解析归属 crate 微基准。
- 优先度：高。

### 3.2 查询编译与执行

- 目的：区分冷编译与热命中的代价，定位捕获复制热点。
- 输入：全部支持语言的代表文件，冷热两次运行。
- 度量：编译耗时、缓存命中率、匹配数、执行耗时。
- 通过标准：热路径无重复编译，无缓存分支需要单独建基准并修复。
- 优先度：高。

### 3.3 内嵌二次解析

- 目的：量化单文件组件与样式内联的多次解析放大。
- 输入：真实单文件组件、超大样式内联、脚本样式混排样本。
- 度量：主解析耗时、块解析次数与耗时、跨度调整耗时。
- 通过标准：块数与耗时的关系明确，大文件有专项优化目标。
- 优先度：高。

### 3.4 分组与自然语言转换

- 目的：量化分组多遍复制排序与双路径文本生成的开销。
- 输入：大类、大实现体、多成员文件、测试套件文件。
- 度量：分组耗时、双路径生成耗时、清洗遍数、输出文本量。
- 通过标准：双路径耗时占比明确，大组样本不主导批次。
- 优先度：高。

### 3.5 切块与摘要

- 目的：量化递归切分、代价重估、跨组合并与规则摘要的重复分组。
- 输入：长组、超限组、嵌套组、文档型文件。
- 度量：切分耗时、重估次数、合并耗时、摘要耗时。
- 通过标准：默认摘要路径的重复分组可度量，复用入口有对照基准。
- 优先度：中。

### 3.6 混合分词

- 目的：量化中文分词与标识符切分在索引与检索两处的耗时。
- 输入：中文注释密集样本、中英混合样本、标识符密集样本、长标题样本。
- 度量：分词耗时、输出词元数、词典加载耗时。
- 通过标准：长文本分词不主导命中高亮与索引切块。
- 优先度：高。

## 4. 中断恢复基准

### 4.1 崩溃点恢复曲线

- 目的：量化不同崩溃点的恢复耗时与重做量，现有功能矩阵需补充耗时维度。
- 输入：固定项目，分别在解析后、候选克隆中、部分模块完成、发布后等中间态中断。
- 度量：恢复耗时、重解析数、重嵌入数、重生成摘要数。
- 通过标准：部分完成场景只补未完成模块，已完成模块计数不变。
- 优先度：高。

### 4.2 已完成规模放大

- 目的：验证恢复耗时随已完成批次数的变化，找出线性段与悬崖点。
- 输入：固定总规模，变换中断发生时的已完成批次比例。
- 度量：校验耗时、回放耗时、导出预热耗时。
- 通过标准：给出可接受的中断窗口建议，悬崖行为有明确阈值。
- 优先度：高。

### 4.3 校验失配回退

- 目的：量化文件列表哈希、批次边界、磁盘内容、配置指纹失配时的重做代价。
- 输入：恢复前分别修改磁盘文件、变更切块配置、篡改版本字段、构造陈旧检查点。
- 度量：回退起点、重做文件数、重做模块数。
- 通过标准：失配类型与重做范围对应关系明确，无过度重做。
- 优先度：中。

## 5. 本地检索基准

### 5.1 全文查询构造与执行

- 目的：量化查询膨胀、词典访问、分页跳过与逐命中物化的开销。
- 输入：短查询、长查询、短语查询、多词元查询，变换限制数与偏移量。
- 度量：子句数、词典访问数、取回耗时、跳过耗时、物化耗时。
- 通过标准：大偏移与长查询的代价明确，限制数放大效应可解释。
- 优先度：高。

### 5.2 高亮

- 目的：量化逐命中高亮的分词与自动机构建开销。
- 输入：固定查询变换命中数，开关高亮对照。
- 度量：高亮总耗时、单命中耗时、分词次数。
- 通过标准：关闭高亮时无多余分词，命中数放大后有上限建议。
- 优先度：高。

### 5.3 本地元数据与源文件读取

- 目的：量化大集合成员查询、双代际查询、逐命中读整文件的放大。
- 输入：固定命中数，变换同文件命中聚集度与代际命中分布。
- 度量：查询次数、扫描行数、文件读取次数与字节数、反序列化次数。
- 通过标准：同文件多命中复用文件读取，失败路径查询次数明确。
- 优先度：高。

### 5.4 关系图查询

- 目的：量化调用链展开、路径查找、邻居展开与全图操作的边界。
- 输入：链式图、扇出图、深继承图，变换深度与节点上限。
- 度量：访问节点数、路径复制量、耗时、触顶率。
- 通过标准：默认深度与节点上限有依据，过滤后分页语义明确。
- 优先度：高。

### 5.5 融合排序与候选截断

- 目的：量化双路归一化、多实体展开、摘要加权与候选构建的开销。
- 输入：双路重叠高、低、无三种对齐度，变换候选上限。
- 度量：融合耗时、展开倍数、归一化次数、候选构建耗时。
- 通过标准：默认候选上限有依据，空一路不做多余归一化。
- 优先度：中。

### 5.6 词元估算与聚合

- 目的：量化启发式估算、截断循环与聚合重估的开销。
- 输入：代码密集文本、大文本截断样本、多命中聚合样本。
- 度量：估算耗时、重估次数、聚合耗时。
- 通过标准：大文本截断无平方退化，聚合重估次数可解释。
- 优先度：中。

### 5.7 缓存命中

- 目的：量化查询缓存、嵌入缓存、关系缓存与符号缓存的命中率与锁争用。
- 输入：重复查询、分页游走、聚合多子查询、并发读四类负载。
- 度量：命中率、锁等待耗时、逐出率。
- 通过标准：重复查询命中稳定，分页与聚合组合的抖动可解释。
- 优先度：中。

### 5.8 并发读

- 目的：量化全文互斥锁与数据库连接在并发下的串行程度。
- 输入：固定查询集，变换并发数。
- 度量：吞吐、分位延迟、锁等待占比。
- 通过标准：给出并发上限建议，串行瓶颈有明确归属。
- 优先度：高。

## 6. 落地顺序建议

1. 先补扫描哈希、批并发、检查点编解码、单文件解析、全文查询与高亮、单文件热更新六项，覆盖主链路最大头。
2. 再补终局回放、层叠链长、恢复曲线、元数据读取、关系图边界五项，确定阈值与悬崖点。
3. 最后补过滤拷贝对照、全量差分告警、切块摘要、分词专项、融合候选、缓存与并发读七项，形成完整回归网。
4. 每个基准落地时同步记录基线表格，未达通过标准的项转入优化任务，不在测试文档中堆积优化方案。
