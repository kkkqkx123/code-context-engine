# `ripgrep` 词项未分组下滑与 `flask` 对照

日期：2026-11-04
范围：`ripgrep` 为主，`flask` 为对照；其他项目数据为旧快照，不作为依据
证据：`crates/app/cce-e2e-tests/outputs/benchmark/ripgrep` 与 `outputs/benchmark/flask` 的聚合与逐查询报告（`variant=all/impl_only`，`top5/10/30/50`），`outputs/scenarios/rust/chunks/ripgrep` 与 `outputs/scenarios/python/chunks/flask` 的双路分块，以及 `fixtures/rust/review/ripgrep` 与 `fixtures/python/review/flask` 原始代码
口径：三基线含义与组级/片段级评测语义沿用既有分析文档，不重复展开

## 1. 问题清单

### 1.1 `ripgrep` 聚合

`impl_only` 下词项未分组 `full` 稳定低于 `direct`，且多数切口下也低于 `raw`；词项分组差距小一个量级；向量两路 `full` 全面领先。

* 未分组词项 `R_s`：`top10 direct 0.6111 / full 0.5444 / raw 0.5667`，`top30 0.7444 / 0.6556 / 0.7556`，`top50 0.8444 / 0.7667 / 0.8111`。
* 分组词项 `R_s`：`top10 0.6333 / 0.6444 / 0.6778`，`top30 0.8556 / 0.8111 / 0.8444`，差距约零点零几。
* 向量未分组 `R_s`：`top10 0.4667 / 0.5111 / 0.5222`，`top30 0.6556 / 0.8000 / 0.7556`，自然语言对向量为正增益。
* 向量分组 `full` 在各切口均为最高。

按查询类型看，未分组词项的下滑集中在语义类；精确符号与扰动类在分组视图下已与 `direct` 持平，大切口下未分组也能追回。语义类即使分组仍有约零点一的差距。

### 1.2 `ripgrep` 逐查询（`impl_only`，未分组词项，`top10`）

`full` 严格低于 `direct` 或 `raw` 的共 5 个，其余查询均持平或领先：

* `G1Q9 build method on Pcre2Matcher`：`direct 1.0 / full 0.0 / raw 0.0`，真相为 `pcre2/src/matcher.rs` 内 3 行小方法，被装入约 280 行大实现块的概览分片，标题泛化为实现块名。
* `FZ-G1Q9-abbrev_expand build method on pcre2 matcher`：同上目标的扰动问法，模式相同。
* `G2Q3 check if file path matches glob pattern`：`direct 1.0 / full 0.0 / raw 0.0`，真相为 `globset/src/lib.rs` 内 3 行 `is_match` 加相邻候选方法，同处一个成员分片，内容完整但排序跌出前列。
* `G2Q20 search stdin stream without file path`：`direct 1.0 / full 0.0 / raw 0.0`，真相为 `searcher/src/searcher/mod.rs` 内约 40 行 `search_reader`，被按预算切成前后两片，单片无法单独覆盖标注区间。
* `G1Q1 find_at in RegexMatcher`：`direct 0.0 / full 0.0 / raw 1.0`，真相为 `regex/src/matcher.rs` 内约 13 行 `find_at`，落在约 100 行大特性实现块内；同一切分下原文成功而自然语言失败，属于纯文本稀释，与切分无关。

上述 5 个中前 4 个满足 `full` 与 `raw` 同败而 `direct` 独胜，判定为切分与竞争主因；`G1Q1` 满足同切分下原文独胜，判定为文本主因。5 个在分组词项下除 `G1Q1` 外全部恢复为 `1.0`，`G1Q1` 在分组下依然为 `0.0` 而 `raw` 分组为 `1.0`。

### 1.3 `flask` 对照

`impl_only` 下 `full` 相对 `direct` 与 `raw` 无下滑：未分组词项 `top10 0.8889 / 0.8889 / 0.8667`，分组词项 `0.9778 / 1.0 / 1.0`，向量两路 `full` 均为最高。`all` 下唯一 `full` 略低的是分组词项 `top10 0.9778 / 0.9556 / 0.9556`，差一个查询（`G2Q6`），三基线未分组词项全为零，属于高频词竞争而非切分退化。`all` 下真正大跌的是 `raw` 向量（`emb 0.9556 / 0.7556`，`emb_group 1.0 / 0.8667`），原因是测试与示例源码在含噪语料下挤占原文，自然语言反而抗噪。结论是 `flask` 无需为词项未分组做结构性修复，回归门槛以不跌破当前聚合为准。

## 2. 原因分析

### 2.1 切分与竞争是前 4 个的主因

`full` 与 `raw` 共享完全相同的分块边界，两者同败而 `direct` 独胜，只能解释为边界与排序问题。自然语言比源码长，同样的代码在词项路更容易超限：大实现块被按预算切成多片加概览，小方法被合并进大块后标题泛化。`full` 词项块数约两千二，`direct` 约一千五，多出的数百块全部参与同一词项排序。查询词在自然语言模板中反复出现（签名复述、调用列表、成员罗列），逆文档频率被摊薄，长度归一惩罚真块，目标在未分组下被挤出前列。分组把同段各片合并为组跨度后全部恢复，证明内容存在且可定位，失败在召回单位与排序。

逐目标映射：`G1Q9` 的 3 行方法藏在 280 行概览分片里；`G2Q20` 的真相横跨前后两片；`G2Q3` 的分片内容完整但同文件数十个相似分片竞争同一组查询词。原始代码分别见 `pcre2/src/matcher.rs` 开头、`searcher/src/searcher/mod.rs` 的读器方法、`globset/src/lib.rs` 的集合匹配方法；转换结果分别见对应 `bm25` 分块文件的实现块分片、读器前后分片、集合匹配分片。

### 2.2 文本稀释是 `G1Q1` 的主因

`G1Q1` 三基线同切分下只有 `raw` 成功，标题与关键词仍是自然语言（`raw` 基线只替换正文），说明正文的词汇密度是区分项。约 13 行的 `find_at` 被装入约 100 行 6 方法大块，自然语言正文含签名复述、控制流、调用与类型列表，查询的两个关键符号在长文本中权重不足；原文同区间保留精确定义与相邻实现声明，混合分词下命中更集中。`ripgrep` 真相多为 3 到 15 行小函数，固定模板开销主导长度，信号被装饰淹没；`flask` 真相多为 20 到 140 行大方法，模板占比小，标题精确到方法名，故无同类下滑。语言与目标尺度差异是跨项目不一致的直接解释。

### 2.3 概览卡在词项路弊大于利

既有概览机制为被切散成员追加 union 卡，文本取首片头部截断，区间取各片并集。该卡对向量语义是单命中覆盖所必需，对词项却是新增的近重复文档：标题与关键词与源分片高度重合，头部截断未必含有查询词，union 区间不参与词项排序interview，只增加同主题竞争者。当前 `ripgrep` 词项场景转储中概览分片约一百七十片，约占词项块数的百分之八；`flask` 词项约三十余片。未分组词项的竞争本已因自然语言膨胀而偏高，概览卡进一步推高。分组词项已可通过段合并恢复，无需依赖概览卡。因此词项路的概览增卡属于负收益，限制到向量路是最小风险的纠正。

### 2.4 非目标

`G2Q6` 类高频词竞争与词汇缺口、`G1Q1` 类小实体语义稀释属于检索层或模板治理范畴，不在本轮分块改动内硬解。明确不调预算数值、不放宽评测覆盖语义、不为评测查询加词。
