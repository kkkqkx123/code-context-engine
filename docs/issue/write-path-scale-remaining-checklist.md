# 写路径规模化剩余问题与待补验证清单

本清单承接 `docs/plan/write-path-scale-next-phase.md` 的执行结果，
只记录尚未关闭的事项。已关闭的提交边界聚合、阶段指标契约、工作单元查询收敛、
流式 spool 回放和四类故障注入不再重复登记。

状态含义：`待治理` 表示需要改动或方案决策；`待验证` 表示机制已实现但缺少明确验收数据；
`独立事项` 表示不属于写路径范围，按单独 SLA 跟踪。

## 写路径性能

- **待治理：批间等待占 50,000 文件向量阶段 151.7 s**，占向量阶段约 60%，是当前最大单项。
  新增 `vector_delay_ms` 已把成本隔离出来；下一步需在 provider 限流预算与批间等待策略之间做方案选择，
  不通过调大 batch size 或关闭等待掩盖提交频率问题。
  验收口径：同机器、同档位、同 mock 配置下延迟可解释；生产默认值变更有独立决策记录；WAL flush 与工作单元语义不变。

- **待验证：工作单元查询收敛的规模收益**。50,000 文件档已从约 2,000 次降到 500 次，
  但 `vector_work_unit_query_ms` 仅 21 ms，未验证在更大项目或远端 PostgreSQL 下的收益。
  验收口径：远端元数据后端下以同口径重测查询次数与耗时，确认不存在 N+1 回归。

- **待验证：关系镜像等价性**。流式回放替换了原来的全量收集路径，e2e 查询通过，
  但尚未用同一批 spool 输入对比流式路径与切片路径的规范化快照 fingerprint。
  验收口径：两种构建方式产出的 canonical snapshot fingerprint 逐字节一致，关系数量与查询顺序一致。

## 关系索引内存（下一阶段重点）

- **待治理：50,000 文件峰值 RSS 约 9.6 GiB，未下降**。全量 `ParsedFile` 驻留已移除，
  容量指标指向 1,349,968 个关系节点，按实测约 6 KiB/节点估算约 8.3 GiB，与
  批次结束 1.4 GiB、关系结束 9.3 GiB 的增量吻合。
  分析与方案见 `docs/plan/relation-index-memory-analysis.md`。
  验收口径：50,000 文件档峰值 RSS 相对本轮下降至少 50%，或经实测 SLA 证明查询期内存有上界；
  不截断关系、不改变召回与快照 fingerprint。

- **已实现，待规模复测：canonical snapshot 二次物化**。构建期索引直接流式导出磁盘工件，
  指纹由有界外部排序计算，SQLite 与 PostgreSQL 都按批次消费工件；
  设计与验证口径见 `docs/plan/relation-index-streaming-write-design.md`。

## 实体与块存储同类内存风险核对

- **已实现，待规模复测：`source_entity_ids` 改为按批次解析**。批次写入实体后，
  只读取当前批次 chunk 引用的 `(file_path, source_id)`，通过新增的
  `entities_with_files_in_paths` 存储端口精确查询 durable 行并替换本批映射；
  阶段指标记录批次峰值而不是全项目累计量。跨文件引用仍按持久化键解析，映射缺失仍按错误上报。

- **待治理（低优先级）：`UpdateStateTracker.states` 全文件映射**。每个文件一条含嵌套模块状态的记录，
  随文件数线性增长；恢复时也会整表载入。量级估计为数十 MB，远小于关系索引，但需要给出上限或分片恢复方案。
  验收口径：状态查询与恢复语义不变，且内存随文件数增长有上界。

- **待验证（低优先级）：符号表全项目驻留**。50,000 文件档为 725,024 条目，按 128 B/项估算约 93 MB；
  跨文件解析需要完整符号表，暂不作为优先治理对象，但应纳入容量报表。
  验收口径：随项目规模给出条目数与估算字节数，确认增长曲线。

- **已确认无同类问题**：批次结果只保留当前批次的解析文件与 chunk；
  向量暂存窗口上限为 512 点（实测派生记录峰值 7,788 行），BM25 暂存上限为 2,100 文档；
  关系与导出 spool 都是磁盘支撑，仅保留路径列表。本地向量引擎按设计常驻全部点，
  属于查询期索引而非构建期泄漏。

## 工程与测试

- **待验证：提交边界故障注入的检查点索引断言**。现有四个用例断言了数据落盘、工作单元状态、
  派生映射与恢复重放，但没有逐个断言批次检查点索引是否停在失败窗口之前。
  验收口径：四个失败时点分别读取批次检查点游标，确认恢复从失败窗口重入且不跳过文件。

- **待治理：根 `Cargo.lock` 已完成取消忽略，但未纳入提交**。本轮以 `--locked` 在本地和 devs 通过编译与测试；
  后续需把锁文件正式纳入版本基线，避免不同机器首次解析得到不同依赖集。
  验收口径：两端同一锁文件，`cargo check --locked` 与 `cargo test --locked` 通过。

- **待验证：服务脚本资源前置检查的负向用例**。脚本已检查文件句柄下限 65,536 与 20 GiB 磁盘余量，
  本轮以 `ulimit -n 65536` 正向通过，但没有验证低句柄时明确失败。
  验收口径：低句柄环境执行 `run` 返回非零并给出可操作原因；服务未启动、无残留数据。

- **待验证：TSV 新列的趋势连续性**。服务矩阵与完整流水线阶段 TSV 已重建表头并对齐字段数，
  但趋势文件在切换后没有历史对照。
  验收口径：至少再跑一轮同档位，确认列数、字段名与行宽稳定，无把旧结构数据混入。

## 独立 SLA 与覆盖缺口

- **独立事项：Elasticsearch 冷查询 SLA**。需提高冷查询采样数，记录首字节延迟、JVM 堆与进程 RSS；
  不与本地 Tantivy 混为同一指标。
- **独立事项：Qdrant 冷查询长尾**。medium 档曾出现单次约 136 ms 长尾，样本数不足，需扩大采样后给 SLA。
- **独立事项：生产 provider 限流预算**。chat、embedding、rerank 共享令牌桶，需给出预算与交互查询等待的 SLA。
- **独立事项：恢复失配输入夹具**。补齐文件列表哈希、磁盘内容、版本字段三类不一致的自动化用例。
- **独立事项：50,000 文件远端四档矩阵**。本轮只完成 medium 四档；大档位需按容量条件执行，未执行时记录明确跳过原因。
