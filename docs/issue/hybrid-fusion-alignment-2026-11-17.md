# Hybrid 查询聚合对齐与融合问题清单与修改方案

日期：2026-11-17
范围：查询侧混合召回（向量 + BM25 对齐与融合）、单查后处理去重、多子查询聚合；索引侧双路分块仅作为对齐前提引用
证据：`crates/core/cce-types/src/types/alignment.rs`、`crates/core/cce-types/src/types/ast_to_nl/chunked.rs`、`crates/app/cce-orchestrator/src/query/retrieval/primitives/fusion/`（`aligner.rs`、`merger.rs`、`normalizer.rs`）、`crates/app/cce-orchestrator/src/query/searcher/searcher_core.rs`、`crates/app/cce-orchestrator/src/query/searcher/post_processing.rs`、`crates/app/cce-orchestrator/src/query/coordinator.rs`、`crates/app/cce-orchestrator/src/index/storage_coordinator/mapping.rs`、`crates/app/cce-orchestrator/src/index/storage_coordinator/vector.rs`、`crates/app/cce-orchestrator/src/index/storage_coordinator/bm25.rs`、`crates/core/cce-config/src/modules/search.rs`，以及 `crates/app/cce-orchestrator/tests/alignment_integration.rs` 与融合模块内单测
口径：本文只讨论对齐键推导、分数合成、去重与合并语义；向量相似度算法与 BM25 词项权重本身不在范围内

## 1. 现状概述

索引侧同一逻辑组产出两套文本（语义摘要走向量、混合增强文本走 BM25），两路独立切分、数量与边界无对应关系，仅共享 `content_entity_ids` 与 `segment_id`。向量载荷与 BM25 文档字段均持久化这两项，SQLite 另存全量分块记录供查询侧回填内容。

查询侧对齐键优先级为实体优先、其次分段、最后块标识。融合前先把多实体块展开为单实体条目，再按对齐键取每路最佳原始分，归一化或排名后按权重合成。单查流水线为召回（并行双路，任一路失败即整查失败）→ 融合 → 一次 SQLite 回填 → 去重 → 重排 → 排序 → 阈值 → 标注。多子查询聚合则为子查询阈值清零并放大拉回、加权后按统一去重键取最大分、再施加唯一全局阈值与截断。

总体方向正确：实体级而非块级对齐是双路独立切分下的必然选择，分段兜底覆盖了无实体文档，展开步骤避免了多实体块丢召回，回填后置节约了 SQLite 开销。

## 2. 问题清单

### 2.1 融合得分、展示取单块，另一路证据被丢弃

双路同键融合时，最终只保留加权贡献大的一方分块作为代表（标识、内容、行号均属胜出方），另一路命中的分片仅贡献分数。同一实体下两路文本本就不同（语义摘要与关键词增强文本），长函数多分片时用户看到的可能是向量分片，而 BM25 实际命中在另一子分片，可解释性弱，且后处理与重排都只能看到胜出方文本。

### 2.2 孤路快捷路径与双路并存时的单路键计分不一致

一路为空时走快捷路径，幸存路归一化分直接作为融合分；双路并存时单路键得分还要再乘以本路权重占比。同样一个键，僅因另一路是否返回了无关结果，得分可相差一个权重因子（等权下差一倍）。快捷路径注释称与双路语义完全一致，实际并不一致，阈值会因此漂移。

### 2.3 单键与全等分输入退化为满分

归一化在无极差时把全部输入映射为满分。孤路单键经快捷路径恒得满分，而它在双路并存下作为单路键至多得权重占比分（见 2.2）。单命中查询的满分与多命中查询的满分含义不同，阈值无法统一理解。

### 2.4 归一化分布敏感，阈值跨算法不可移植

加权最小最大归一逐查询独立计算极差，离群值会压缩主体分数；名次型算法把分数重心推向高端（高排名在常用参数下贴近满分）。三种算法名义上都输出到同一区间、共用同一阈值语义，实际相同阈值在不同算法下的选择率差异很大，切换算法需重调阈值，但现状未给出各算法的推荐阈值。

### 2.5 实体展开与按块去重互斥，次优实体丢失

融合前把一物理块展开为多实体条目以实现实体级对齐，融合后按物理块标识去重又只留最高分条目。含多实体的块在去重后只剩优胜实体，其余实体的命中信息丢失。召回是实体粒度，展示与去重是块粒度，两者未解耦。

### 2.6 融合在回填之前，可对齐键可能错过

融合只用索引携带字段推导对齐键，而 SQLite 回填会补全缺失的实体关联。后处理注释承认去重是在回填后复检，恰说明融合期存在键缺失。本可对齐的双路命中在融合阶段错过，只能得到单路加权分，后置去重无法补回失去的融合加成。

### 2.7 块标识兜底恒不对齐，异常块混合增益为零

块标识含双路路径后缀，跨路永不相等，这是刻意为之。但插件或异常分块（空分段回退到块标识）因此永远走单路并集，混合对它们无增益。现状有覆盖率统计可观测，但缺少对无键比例的显式上报与策略文档，下游难以区分是正常现象还是索引缺陷。

### 2.8 多子查询聚合取最大分，多命中不累加

聚合对同键多子查询命中取加权后最大分，而非证据累加。多个子查询共同命中同一实体的信号被浪费，大权重子查询天然垄断排序，多样性受损。同样，单路键计分问题在聚合层以加权缩放形式再次出现。

### 2.9 单路保留开关隐式不对称

向量独有键恒保留，开关仅门控 BM25 独有键，快捷路径亦然。向量主路的定位本身合理，但不对称藏在实现与单测中断言里，未在配置层面显式表达，后续调整阈值或交集策略时容易误判。

## 3. 修改方案

约束：只改原模块，不新增替代模块；按职责拆分而非按优劣另起模块；允许打破既有分数语义，不保留兼容垫片。

### 3.1 第一批：计分一致性与对齐键补全

目标是同一键得分不再取决于无关路况，且融合看到的键尽量完整。

* 统一孤路与双路单路键的计分：二选一并全文贯彻，要么快捷路径同样乘以本路权重占比，要么双路单路键不再乘权重占比。同步更新融合单测与端到端对齐单测的期望，并补一条一致性单测断言同一单路键在另一路为空与非空时得分相等。涉及融合合并器与融合配置校验说明。
* 融合前补全实体关联：将 SQLite 回填拆为轻量键补全（仅实体标识与分段标识，限候选集合）前移到融合前，全量内容回填仍保留在融合后。键补全未命中或失败时降级为现状行为并计数。涉及检索器搜索流水线与实体映射原语，候选规模需设上限以控制回填成本。
* 显式化单路保留语义：把隐式不对称写进融合配置说明，或拆分为向量与 BM25 各自独立的保留开关（默认保持向量保留、BM25 受控）。涉及融合配置结构与联合键集合逻辑。

### 3.2 第二批：双证据保留与展示解耦

目标是融合增益可解释，多实体块不再丢信息。

* 融合结果携带双路代表引用：除胜出方分块外，记录另一路代表分块的标识、分数与行号区间，供回填、重排与接口层选用。展示默认不变，重排仍只消费主文本，避免排序语义抖动。涉及融合输出结构、回填逻辑与结果类型。
* 按块去重改为按块分组展示：同物理块多实体条目合并为一条，保留实体列表与各自分项，而非丢弃次优实体。重排预算按合并后条目计算。涉及融合完成阶段与后处理去重函数，二者共用同一键空间，保持行为一致。

### 3.3 第三批：归一化、阈值文档与聚合累加

目标是阈值可移植，聚合体现多命中累加。

* 退化映射与离群收缩：单键与全等分输入不再映射满分，改为按路径权重占比计分并标记低置信；最小最大归一化增加按分位收缩或截断，减弱离群值对主体区间的压缩。按算法给出推荐阈值区间并写入配置文档。涉及归一化模块与检索配置说明。
* 聚合层同键累加：多子查询同键从取最大分改为加权求和（或名次式累加），保留单调性说明并更新聚合单测。涉及查询协调器聚合分支。
* 无键比例可观测：上报对齐覆盖率时同时记录无键条目占比，超过阈值告警，帮助区分正常并集与索引缺字段。涉及对齐统计结构与搜索指标记录。

## 4. 验证建议

* 单测：增补孤路与双路单路键一致性断言、键补全前后对齐覆盖率对比、聚合累加单调性、分组展示下多实体不丢失。
* 集成：沿用现有端到端对齐集成测试，追加文档分片多子分片对齐、插件异常块兜底、严格交集开关三条用例。
* 基准：跑融合缓存基准确认快捷路径改动无回归；在现有词项与向量基准上对比切换名次型算法前后的阈值选择率，验证推荐阈值区间的有效性。
* 上线观察：首周关注对齐覆盖率（匹配键占比）、无键占比、单路键占比三项指标，确认 3.1 落地后匹配键占比上升且无键占比下降。
