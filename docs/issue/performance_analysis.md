# 性能基准实测分析

## 1. 方法与范围

依据 `docs/tests/benchmark_gaps.md` 落地顺序建议的第一步，优先覆盖主链路最大头：
扫描哈希、检查点编解码、单文件解析、全文查询与高亮，另附单文件热更新对照、
关系链长、元数据读取与分词专项共 7 组微基准。全部使用小数据量、固定输入、
多次取平均，dev（debug）模式编译，结论以组内对比倍数为主，不以绝对耗时为准。

实测环境为本地单机，内存数据库或本地临时目录，不依赖外部网络与真实模型服务。

各基准输入规模：扫描 100 与 300 文件；解析样本为双函数小文件、150 函数大文件、
60 函数 Python 文件、单文件组件；全文索引 200 篇本地文档；元数据为内存库
50 文件加 500 文本块；关系为 500 文件合成链式项目；检查点为真实解析产物。

## 2. 实测结论与问题

### 2.1 全文检索高亮逐命中成本线性放大（ISSUE-01，高）

200 篇文档上的查询耗时（毫秒）：

| 场景 | 耗时 | 命中数 |
| ---- | ---- | ------ |
| 短查询 | 1.02 | 10 |
| 长查询 | 2.19 | 10 |
| 短语查询 | 1.53 | 10 |
| 短查询放宽限制到 50 | 2.93 | 50 |
| 短查询大偏移 | 1.14 | 10 |
| 短查询开启高亮 | 4.94 | 10 |

高亮开关对比显示，开启高亮后总耗时约为关闭时的 4.8 倍。
高亮单独计时随命中数严格线性增长，10 命中 3.55 毫秒，50 命中 17.62 毫秒，
折合每命中约 0.35 毫秒。结合实现分析，每次高亮对查询串与标题重复分词，
并为每次调用新建多模式匹配自动机，命中数放大后同步放大。

优化方向：关闭高亮时跳过匹配词抽取等多余分词；高亮改为按需懒生成，
只对最终展示的少量命中生成；限制单次高亮命中数并给出上限建议；
自动机与分词结果在同查询内复用。

### 2.2 索引期同一文件被读取两次（ISSUE-02，高）

100 与 300 文件项目上的扫描与哈希耗时（毫秒）：

| 文件数 | 全量扫描 | 无变化重扫 | 全量重哈希 | 解析前二次触碰 |
| ------ | -------- | ---------- | ---------- | -------------- |
| 100 | 14.59 | 14.19 | 12.60 | 7.07 |
| 300 | 27.89 | 27.45 | 21.15 | 20.73 |

无变化重扫与全量扫描耗时基本持平，说明在目录遍历层没有增量收益，
增量复用完全依赖上层清单比对。一次全量重哈希的耗时约为全量扫描的
八成，意味着当前流水线对同一文件至少触碰两次，磁盘密集型项目中
文件输入输出接近翻倍。

优化方向：扫描阶段一次读取同时产出内容哈希与语言判定所需前缀，
解析前校验复用扫描期结果而非重新读盘；大文件流式哈希分支的阈值
与命中情况需要单独度量。

### 2.3 自然语言双路径耗时直接相加（ISSUE-03，高）

单文件流水线分段时间（毫秒）：

| 样本 | 解析 | 冷解析 | 分组 | 全文路径 | 嵌入路径 | 双路径 | 切块 |
| ---- | ---- | ------ | ---- | -------- | -------- | ------ | ---- |
| 双函数小文件 | 0.73 | 0.74 | 0.06 | 0.13 | 0.10 | 0.19 | 0.10 |
| 150 函数大文件 | 102.70 | 102.41 | 8.98 | 7.77 | 9.28 | 16.83 | 14.80 |
| 60 函数 Python | 26.23 | 26.45 | 2.70 | 3.00 | 2.97 | 6.37 | 6.70 |
| 单文件组件 | 1.62 | 1.96 | 0.21 | 0.12 | 0.14 | 0.25 | 0.90 |

双路径耗时基本等于两条单路径之和，说明两条路径对同一实体组各跑一遍，
模板拼接、关键词抽取、文本清洗没有共享中间结果。150 函数大文件上
双路径转换加切块合计约 31 毫秒，约为解析耗时的三成，不可忽略。

优化方向：抽取两条路径公共的实体遍历与文本预处理，只在末端按路径
分叉渲染；关键词抽取结果复用而非逐路径重算。

### 2.4 未传作用域时增量差分退化为全量对比（ISSUE-04，高）

500 文件合成项目上的关系增量耗时（毫秒）：

| 场景 | 耗时 |
| ---- | ---- |
| 传入单文件作用域的差分计算 | 6.40 |
| 未传作用域的全量差分 | 21.35 |
| 层叠视图包装 | 7.96 |
| 全量分离克隆 | 20.57 |
| 单文件增量应用 | 低于计时分辨率 |
| 规范化快照随链长 1 到 20 | 68.04 到 74.79 |

未传作用域的全量差分耗时约为传入单文件作用域的 3.3 倍，
且该退化是静默的。热更新调用方一旦漏传作用域，单文件修改也会付出
全项目差分代价。层叠视图包装约为全量分离克隆的四成，
说明热路径以基缓存加层叠视图替代全量物化是有效的，但回退分支仍需度量。

优化方向：为空作用域增加显式计数或日志告警，不静默退化；
调用侧以类型或断言保证热更新恒定传入单文件加传递闭包的作用域。

### 2.5 文本块批量查询与逐行查询的倍数差（ISSUE-05，高）

500 文本块内存库上的元数据查询耗时（毫秒）：

| 场景 | 耗时 |
| ---- | ---- |
| 单行主键查询 | 0.05 |
| 批量查询 10 行 | 0.09 |
| 批量查询 50 行 | 0.29 |
| 批量查询 200 行 | 1.11 |
| 循环单行查询 50 次 | 2.48 |
| 按文件查询 | 0.10 |
| 按路径查文件 | 0.02 |
| 分页偏移 0 | 0.16 |
| 分页偏移 400 | 0.39 |
| 整代最大实体标识扫描 | 0.63 |

50 行批量查询耗时 0.29 毫秒，而循环单行查询 50 次耗时 2.48 毫秒，
相差约 8.5 倍。混合召回膨胀后编号集合变大时，若走逐行定位路径，
代价会随集合线性放大。分页大偏移耗时约为小偏移的 2.4 倍，
大偏移分页存在跳过代价。整代最大实体标识查询需全代扫描并逐行解析
标识集合，当前规模下绝对值小，但随代规模线性增长。

优化方向：混合召回的文本块物化统一走批量编号查询；
同文件多命中复用单次文件读取与行缓存；分页优先游标语义，
大偏移给出上限建议。

### 2.6 大文件单文件解析耗时占比过高（ISSUE-06，中）

150 函数大文件在 debug 模式下单文件解析约 102 毫秒，
占解析加分组加转换加切块全链路的七成。小文件解析不足 1 毫秒，
耗时随文件规模超线性增长的趋势明显。冷热两次运行耗时基本持平，
说明在小样本上查询编译缓存命中与否不是主导因素，
真正的开销在每次执行的捕获复制与多阶段重复扫描。

优化方向：定位最慢阶段并补充分段计时；捕获文本按需懒取，
大段正文捕获避免全量复制；单文件样式内嵌查询的新建无缓存分支优先修复。

### 2.7 层叠快照规范化耗时随基规模增长（ISSUE-07，中）

500 文件项目规范化快照约 68 毫秒，链长从 1 增长到 20 仅增加约 10%，
说明当前开销主要来自基规模而非链长。调用链前向查询在深度 2 到 20
之间均低于计时分辨率，默认深度与节点上限在链式图上是安全的。
扇出图与深继承图的边界尚未度量。

优化方向：给出链长上限与压实触发建议并配套计数告警；
补扇出图的邻居展开与路径复制基准，验证默认节点上限依据。

### 2.8 检查点编解码在大文件上不可忽略（ISSUE-08，中）

真实解析产物的编解码耗时：

| 样本 | 编码 | 解码 | 压缩后字节 | 压缩比 |
| ---- | ---- | ---- | ---------- | ------ |
| 双函数小文件 | 0.16 | 0.05 | 659 | 约五成 |
| 150 函数大文件 | 4.58 | 3.16 | 6994 | 约一成 |
| 删除标记 | 0.01 | 可忽略 | 极小 | 不适用 |

大文件单次编码加解码合计约 7.7 毫秒，约为其解析耗时的近一成。
恢复期每文件经历压缩解码加结构化反序列化，文件数多时恢复耗时
与重解析相当。删除标记几乎零成本， tombstone 设计合理。

优化方向：摘要走独立小载荷写入，避免重写源码大载荷；
恢复期解码与重解析的取舍给出中断窗口建议。

### 2.9 中文分词单位字符成本高于标识符切分（ISSUE-09，低）

分词耗时（毫秒）与输出词元数：

| 样本 | 分词 | 带偏移分词 | 清洗 | 词元数 |
| ---- | ---- | ---------- | ---- | ------ |
| 中文密集 | 0.81 | 0.85 | 0.15 | 740 |
| 标识符密集 | 4.00 | 3.90 | 1.44 | 3000 |
| 中英混合 | 3.82 | 3.85 | 0.75 | 1600 |
| 长标题 | 0.27 | 0.29 | 0.09 | 140 |

按字符折算，中文密集文本单位字符成本约为标识符密集文本的 2.6 倍，
差异来自词典切分路径。带偏移版本相对普通分词仅增加约百分之五，
高亮等需要位置信息的消费方可直接使用带偏移接口，无需二次分词。

优化方向：检索期查询与标题分词结果复用，避免索引与检索两处重复触发；
长文本分词增加上限保护。

## 3. 未复现项

以下在开销清单中提及的风险在本轮小规模基准中未复现或未充分验证，
不代表不存在，需要更大规模或专项输入进一步确认：

- 查询编译冷热差异：冷热解析耗时持平，编译开销未成为主导，
  但单文件样式内嵌查询的无缓存分支尚未单独建基准。
- 大偏移分页悬崖：偏移 80 相对偏移 0 仅增加约一成，
  文档量与限制数放大后的效应需要更大索引验证。
- 内嵌二次解析放大：单文件组件样本整体耗时小，
  主解析与分块二次解析的各自占比需要块数递增的专项基准。
- 传递依赖整包拒绝重做分支：触发条件需要基准覆盖。
- 文件列表哈希与批次边界失配的悬崖回退：需要恢复曲线的中断注入基准。

## 4. 尚未覆盖的基准缺口

对照 `docs/tests/benchmark_gaps.md`，本轮未落地的高优先级项还有：

- 批并发与批次参数组合，含推荐默认区间的度量。
- 存储微批次事务的批次放大曲线。
- 关系终局双遍回放的内存与耗时对比及阈值验证。
- 变化检测轮询在不同变化率下的开销。
- 崩溃点恢复曲线与已完成规模放大的耗时维度。
- 并发读下全文互斥锁与数据库连接的串行程度。

建议按 gaps 文档落地顺序建议继续补齐，顺序为先批并发，
再终局回放、层叠链长细化、恢复曲线与元数据读取细化，
最后补过滤拷贝对照、全量差分告警、切块摘要、分词专项、
融合候选、缓存与并发读。
